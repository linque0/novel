# 关联知识修复与恍然梦 Agent 优化方向

日期：2026-10-23。基于当前项目代码与独立验证目录中的注册验证书。未调用真实模型，未修改作者作品，未自动提交或升级应用/数据库版本。

## 本轮修复

界面关联原先分散在不同存储结构中，并非全部进入 AI 读模型。此次补齐了以下链路：

| 关联来源 | 修复后的处理 |
| --- | --- |
| 设定↔设定、设定↔人物的 `lorelinks` | 进入源清单、冻结快照、可检索文档、关系图和本地资料卡；保留方向、反向名称、说明及两端版本依赖 |
| 人物关系 `relations` | 保留现有正式关系投影；人物工具同时返回条目关联，来源可跳回人物/设定 |
| 大纲普通连线、分支、连接点、线到线 | 递归读取 `_out`、`fromJunction`、`toJunction`；保留真正的连接端点与箭头，不把连接点误解释为所属节点之间的因果 |
| 大纲连线的知识性质 | 每条连线是独立的 `outlineconnection` 计划文档，来源绑定所属原生节点；不会混入已写内容摘要。继承所属章节范围，计划不可读时连线文档、图边和连接实体同时隐藏 |
| AI 灵感中作者选择保存的 `aiLinks` | 建立带来源的灵感关联边、目标名称与依赖；仍是未采纳创意，不升级为剧情事实 |
| 富文本与纯文本双链 | 支持已写大纲引用；设定截断标题、灵感首行和“总纲/卷纲/章纲”名称与 UI 共用标题服务；同名歧义继续报告，避免错误归并 |

`PROJECTION_VERSION` 从 2 调整为 3，仅使派生读模型重建。已有正文、设定及关系数据不迁移；旧投影不会被当作当前完整索引使用。新增关系和修改/删除关系均触发变更通知与投影失效，旧提案不能覆盖较新的数据库资料。

作者登记的条目关联仍是设定。未标明历史生效范围时，历史任务不读取关系正文；正文创作可将其作为明确标注的作者约束。隐私模式不返回关联说明、反向名称等原文。失效端点的关联不形成可用文档或图边，并列入问题清单。

这意味着资料能通过统一检索与工具读取，并按相关性和预算进入上下文；不意味着每轮都把全书资料全部发送给模型。正文事实提取仍需原文证据与作者确认，附件仍需已有可解析文本。

## 恍然梦 Agent 的优化方向

当前已经具备五模块、15 类任务、只读工具、上下文预算、待确认提案、来源核验、事务应用与撤销。应围绕这些能力形成更好用的写作流程。以下为建议，除上面的知识链修复外，尚未实施。

### 优先级 1：让作者看得见每轮使用的资料

现有上下文报告能说明范围与预算，但“资料已索引”“本轮检索命中”“实际发送给模型”“已确认剧情记忆”仍容易混淆。

建议在现有报告上增加资料清单：来源名称、设定/事实/计划/灵感性质、关联路径、选入原因、是否因预算省略。允许作者固定本轮必用资料或临时排除资料，过期后明确提示，避免悄悄丢失约束。

验收：作者能在生成前确认“用了哪一章、哪个人物、哪条关联”；超出预算有明确处理；关闭一个可选预设槽不能移除必要的创作约束。优先扩展现有报告与预设流程。

### 优先级 2：关系增加生效阶段与知情范围

目前人物关系已有部分生效章节字段，条目关联主要是当前作者设定。现在采取保守隔离，能避免把当前关系投射到过去，但无法充分表达“第十章之前是同伴，之后敌对”。

建议逐步支持长期约束、生效章节、结束章节、关系变更证据，以及人物的知情范围。历史状态从正文证据回放，作者预定的关系变化保留为计划。不能根据一条连线自动推断对方也知道秘密。

验收：同一人物在不同章节、不同视角得到不同的有效关系与知识状态；关系变化可追溯到正文，而不是覆盖旧记录。

### 优先级 3：把续写变成可控制的场景工作流

现有续写、改写和扩写任务边界明确，但作者仍主要依靠一段自由要求表达目标。

建议给正文任务增加可选的场景卡：视角人物、当前目标、主要阻力、本场转折、结尾变化、需要触及的伏笔，以及本章不应提前兑现的计划。流程可串联“场景卡→草稿→对照修改→作者采纳→记忆待确认”，每步保留单独确认。

验收：生成结果能与场景目标逐项对照；改写不扩大选段；采纳正文不会自动确认模型提取的记忆；重试可保留已经满意的场景卡。

2026-10-24 方案细化：作者要求续写先生成 4–6 个不同剧情方向，并可在选项卡片内直接手动编辑，再按选定编辑稿生成正文。该能力已纳入[正文工作流细化方案](正文续写与改写工作流细化方案-20261024.md)第一阶段；仍为方案，尚未实施。

### 优先级 4：以关联图支持修改影响检查

建议把本轮补齐的关系图用于“修改设定前查看影响”：列出直接关联的人物、设定、正文引用、纲点和候选灵感，并标明关系依据。进一步区分确定的结构冲突与模型提出的疑似语义冲突。

验收：点击冲突可打开来源和原文；修改只应用作者选中的项；找不到证据时显示未知。已有资料不应为迁就新草稿而自动改写。

### 优先级 5：长书按任务增量组织材料

已有分块、版本依赖和失效保护。下一步应按场景、章节和人物选择有限的相关邻接资料，并显示记忆缺口；批量提取记录已读进度及失败范围，允许重试。

当前全作品来源变化就拒绝旧提案属于保守保护。只有在来源依赖记录完整、跨窗口一致性验证充分后，才考虑缩小拒绝范围，避免为了流畅牺牲可靠性。

验收：长书不把全书直接塞进每轮；材料省略可见；修改某章只重算必要派生数据；中断恢复不会把未读完的范围称为已完成。

### 优先级 6：建立真实模型的写作质量样例集

机制测试已经能验证权限、证据和写回，不能验证文风、自然衔接与人物表现。建议用独立样书固定一组续写、改写、历史关系、伏笔、设定冲突与长篇检索样例，在同一模型和配置下比较版本。

分别记录来源正确率、未来信息泄露、遗漏约束、重复表达、作者修改量与最终保留情况。对文风与情绪节奏由作者评审；不把模型自己的 review 字段当作质量保证。

建议实施顺序：资料透明与关系阶段 → 场景工作流与影响检查 → 长书增量和真实样例评测。每一步都沿用现有皮肤、模型设置和作者确认流程。
