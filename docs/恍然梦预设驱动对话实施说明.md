# 恍然梦预设驱动对话实施说明

> 本文记录 2026-10-12 的初版实现。后续编排角色、重新生成触发、参数、正则、候选及测试环境已更新，当前行为与使用方式以 [预设体验优化实施说明](./恍然梦预设体验优化实施说明.md) 为准。

日期：2026-10-12。对应作者最后确认的“酒馆式预设编排＋小说工坊上下文＋对话草稿＋确认应用”方案。此前 v2 增强方案与本地酒馆调研文档是设计历史，不再作为专项任务、文风档案或工作流入口的运行规格。

## 使用方式

1. 在设置中配置模型、兼容 Chat Completion 的 API 地址和密钥。
2. 在恍然梦对话面板选择预设，点击“预设编辑”打开独立窗口。可复制默认预设或导入酒馆 JSON，编辑提示块、排序、启停、消息角色、深度、触发类型及生成参数。
3. 在“小说工坊上下文适配”选择动态槽的材料来源、包装与预算。发送预览只编译实际材料，不调用模型，也不提交宏变量修改。
4. 关联当前章，有编辑器选段时优先附带选段。自然语言描述需求后发送；人物、设定和大纲中的“发送给恍然梦”只附带对象并预填输入。
5. 展开草稿卡片，确认追加、替换选段或保存为新章节。普通回复可选中其中的正文，点击“所选文本／回复作为正文草稿”，直接建立候选，无额外模型调用。
6. “继续”创建后续候选；“重新生成”保留旧候选。长度中断、取消、后续请求失败时保留已收到的文字或未完整草稿，完整结束前禁止应用。

## 已实现的边界

### 预设编排与酒馆兼容

- 编译 `prompts` 与 `prompt_order`，默认使用酒馆全局分支 `100001`；保留原始字段及其他分支。支持相对位置、历史消息深度、同深度优先级和角色分组。
- 支持正常、继续及重新生成；重新生成沿用 normal 触发兼容。预设中的其他触发枚举保留，当前对话界面不增加模拟作者或后台静默生成入口。
- 支持作者／助手、作品／章节／选段、消息状态、局部及全局变量、日期时间、随机与确定性 pick、roll、注释、换行等常用核心宏。局部变量按作品隔离；预览使用副本；生成编译一次，工具轮次复用结果。
- 对照本地 SillyTavern 1.15.0 核心检查了变量宏展开顺序、确定性 pick/hash、消息深度、重复 identifier 的首次定义行为及材料包装。
- 支持完整 Chat Completion 与 Prompt Manager 两种 JSON。导入先展示槽位映射与兼容报告，作者决定是否调整。文本不静默改写，原字段和小说工坊适配配置分别保存并可往返导出。
- 实际发送 temperature、top_p、frequency_penalty、presence_penalty、上下文及输出预留。其他参数、未知宏、扩展附件和插件依赖明确报告；第三方脚本、实验宏引擎、完整角色卡生态不执行。
- 材料槽的原始角色与字段仍保存在资产中；出站作品材料统一标为只读 user 材料，避免将正文或设定当成系统指令。

### 作品材料与统一对话

- `send(text, { contextRefs, presetId?, generationType? })` 为统一入口，专业任务分派、旧审稿／改稿运行器、文风档案和工作流界面及角色模型配置已退出运行。
- 动态槽包含作品概况、当前对象、有效前情摘要、人物作者档案、设定、有效事实、标明为计划的大纲、正文参照与作品内对话历史。无材料时显示缺失报告；没有知识库时仍可通过现有只读检索读取材料。
- 发送前冻结作品、关联章、选段、章节顺序、所属卷、源内容版本和预设版本。默认事实范围截至当前章；明确提出全书讨论时扩大范围，并报告实际摘要、事实和正文参照覆盖。
- 历史讨论、未应用草稿、已应用结果分别标注；大纲计划与草稿不进入事实提取。知识库保持独立的固定事实提取提示，创作预设不控制其提取结果。
- 只读工具集中提供材料，原生工具可提交正文草稿及通用人物／设定／大纲提案。最多六轮，最后一轮形成回答；重复检索缓存；整组工具调用与结果一起裁剪。服务商拒绝工具时降级普通对话。
- 完整预算计入提示、材料、历史、工具定义、工具结果和输出预留。工具定义无法容纳时先关闭工具，保留普通对话。预算为字符估算，缺失 provider usage 时明确记录估算用量。
- 隐私模式不创建新原文摘要，不发送正文参照、选段、旧对话、已存宏值、证据摘引和标记为原文／范文的提示块。已有有效摘要及去除摘引的结构化资料可发送。作者本轮输入仍是主动提交的内容；粘贴范文需在条目中标为原文／范文，发送前可检查预览。
- 作品切换中止旧调用并隔离消息；迟到回调不覆盖新作品。对话候选保存在当前应用会话中，预设资产、作品选择和宏状态持久化。

### 草稿应用与数据

- 所有写入经过作品 store。追加与替换通过编辑器事务执行，保存快照与应用审计，提供撤销。新章节支持标题、所属卷与插入位置，撤销同时处理新建章节的大纲记录。
- 应用及撤销检查目标存在、来源版本、章节布局、数据库内容与多窗口锁；通过数据库租约防止同时应用。重复应用和未完整候选均阻断。
- 替换片段必须能唯一定位；跨越双链或批注时禁用一键替换，保留草稿供复制整理。未修改区域的格式保留；修复了在粗体边界替换时错误继承前一个字格式的问题。
- 通用大纲提案应用到生成锚点；空 edge 不建立连线。人物关系不会隐式新建未匹配人物，新增实体作为独立提案确认。
- Dexie v10 增加 `aipresets` 与 `aipresetstate`。备份明确包含预设、宏状态、摘要、知识库及检查点；旧备份可导入。旧专项数据仅保留备份兼容，不参与运行。
- 预设资产修改及设置／知识库变更通过应用事件同步；预设编辑窗口全局唯一，编辑保存检查修订号冲突。
