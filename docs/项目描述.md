# 小说工坊（Novel Studio）项目描述

小说工坊是一款**本地优先**的小说创作桌面软件（Windows x64），代码托管于 GitHub（linque0/novel，单分支 main 即开发主体），当前版本 v1.0.23。它把「正文 / 大纲 / 人物 / 设定 / 灵感」五个创作要素收进同一个工作台，核心主张是**输入即存、永不丢稿**：所有数据存于本机 IndexedDB，无任何网络请求，不登录、不上传。v1.0.0（2026-09-07）为首个正式版里程碑，交付形态为 NSIS 安装程序与免安装本体（electron-builder，随版本重建），功能覆盖开发计划 M0–M6 核心项。

它针对长篇小说创作中最常见的三个断裂：一是正文与大小纲分离、写着写着失去结构；二是人物关系记在纸上、设定散在多个文档；三是心血丢失、版本混乱。对应解法是：大纲做成可拆窗并排的自由模块画布；人物用关系图、设定用无限嵌套的幕布树，并通过双链与正文互相引用；自动保存（输入防抖 1 秒落盘、30 秒兜底、失焦/切章/关窗前强制保存）加章节版本快照（自动保留最近 30 份、可回滚）。

## 功能构成

**正文**：卷—章两级树（拖拽与按钮排序）+ TipTap 富文本编辑器，Word 风格工具栏与右键快捷操作栏；章节书签三入口；批注功能（选中右键加批注，右侧批注栏逐条对应，被批注文字带可按用途改色的实线下划线，与双链点状下划线错位共存）；本章大纲 / 出场人物 / 插图 / 信息随章节实时联动；字数统计与章节状态管理。

**大纲**：流程图式自由白板。事件（矩形/菱形/平行四边形/椭圆）、便签、引用卡、文本框、容器、章节锚点自由摆位；四向锚点拖线表达因果 / 伏笔 / 冲突 / 关联四类语义，支持箭头、标签、线型与单条样式。两项工程硬保证：连线**严格锁定建立时的两端接口**（节点挪位绝不漂移），途经模块按**全局最短路径自动绕行**（Hanan 稀疏网格 A*）。另支持「线连到线」的连接点体系与连线拖拽塑形；文本（幕布）视图与画布共享数据。

**人物**：人物卡（定位 / 别名 / 标签 / 自定义字段 / 头像 / 小传）+ 人物关系图（头像节点、拖线建关系、点边改标签、一度关系网高亮、圆形 / 网格排布、孤岛提示），图与列表双向同步，可一键转为大纲引用卡。

**设定**：整库一棵统一节点树，节点平权、无限嵌套、自由拖拽，支持内联格式与快照式撤销重做，MD / TXT 导入自动转层级，旧数据无损迁移。

**灵感**：随手记，一键转为章节 / 设定。

**全局工具**：跨五模块全局搜索（命中高亮、点击跳转）；写作统计（每日新增柱状图、180 天热力图、写作天数卡片，ECharts）；双链系统（`[[标题]]` 令牌与富文本链接，悬停预览窗带进出场动画且标题栏可拖动）；导入支持 TXT / Markdown / DOCX / PDF / EPUB / 图片（TXT 自动识别 GBK 并按「第 X 章」分章，导入前预览）；导出按卷分组勾选，TXT / Markdown / Word 三格式（docx 由 JSZip 手组 OOXML），大批量可合并单文件或按章打包 zip；回收站与整库 JSON 备份恢复。

**多窗口**：五个模块可拆出为完整功能界面的独立窗口（边看大纲边写正文），内置实体锁——面板占用的条目在主窗口转只读并给出「前往窗口」跳转，锁随面板选中迁移，防止双写。

**视觉**：宣纸 / 羊皮纸 / 暗夜书房三套皮肤与沉浸模式；正文字体中 / 西文分离切换（思源宋体、霞鹜文楷等 6 中文档 + Playfair Display 等 3 西文档，全部为随包本地 OFL 字体、零网络请求）；书架为「色带书封（G）」陈列——平涂单色封面 + 衬线书名 + 作者名圆印，6 款配色冷暖对位，封面张扬、界面中性；主题 / 字体 / 数据 / 书签 / 统计 / 帮助统一收编于顶栏设置面板。

## 技术架构

Electron 33 + Vue 3 + Pinia + Naive UI。编辑器三轨并行：正文用 TipTap，设定与大纲文本用自研幕布编辑器，大纲画布与人物关系图共用自研画布引擎（端口与路由逻辑抽在共享层）。存储为 Dexie / IndexedDB，经 Repository 层隔离，后续可平滑迁移 SQLite；图表 ECharts；打包 electron-builder。工程命令 dev / build / start / web / dist / stop 齐备，支持 `--profile` 多数据目录隔离与网页调试版。源码规模约 51 个文件、1.54 万行。

## 工程实践与质量保障

项目有成文的开发纪律：单分支直推 main、一个版本一个特性粒度、版本号在 package.json / README / CHANGELOG / 提交信息四处同步、源码改动必须升版。质量保障以 CDP（Chrome DevTools Protocol）真实事件驱动的端到端验收脚本为核心，17 套脚本、179 项断言随版本入库，覆盖画布、双链、多窗口、连接点、关系图、打包冒烟等；`npm run dev` 自动种入 15 本验证书（正式版绝不写入测试数据）。历史上验收驱动修复过多批缺陷——如退役组件遗留 CSS 压过 SVG 连线样式、恢复备份时脏数据回写覆盖、贪心绕障改全局最优等；不理想的实验（如插件化架构）走 backup 存档回退，版本号只进不退。

## 美术设计

界面美术历经多版方向探索（设计稿存档于 docs/前端美化/，v2–v7）：早期古风方案因元素堆砌被判「粗糙」而放弃，最终选定参考 Fitzcarraldo Editions 双色制的「色带书封（G）」，配套完成字体选型（中英分离、全部 OFL 本地化）与封面配色对位研究；书架与设置面板已按此风格落地，其余界面沿用既有皮肤，后续封面排版设计稿（v8–v10）待实施。
