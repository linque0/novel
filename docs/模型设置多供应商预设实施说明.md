# 模型设置：多供应商预设改造实施说明（ZCode 式管理）

检索/实施日期：2026-10-13。范围：`src/stores/ai.js`、`src/services/ai/provider.js`、
`src/components/ai/AiSettings.vue`、`src/db/repo.js`、`tools/mock-ai.mjs` 与相关验收脚本。

## 一、目标与结论

把「模型设置」从**单套连接配置**（一个 baseURL + 一把密钥 + 一个全局模型列表）改造为
ZCode 式**多供应商预设管理**：

- 每个预设 = 一套连接（名称 / Base URL / API 格式 / API Key）+ 模型列表（含启停）+ 生成参数；
- 可添加（模板）、复制、删除预设；供应商级「总开关」启动 / 停止；模型级开关启停使用；
- **API 格式**可选（实发两种协议）：`Chat Completions (/chat/completions)` 与 `Anthropic Messages (/v1/messages)`；
- 生成与记忆参数（温度 / 隐私模式 / 自动记忆 / 语义检索 / 向量模型）**随预设各带一份**，切换预设整套切换；
- 全部**即时保存**（无「保存设置」按钮）：文本失焦、开关/下拉变更、模型增删启停均即点即存。

## 二、数据结构（Dexie `appconfig`）

| 键 | 内容 |
|---|---|
| `ai.providers` | 预设数组（不含密钥，可安全进备份） |
| `ai.activeProviderId` | 当前使用中的预设 id（点列表项切换） |
| `ai.cred.<providerId>` | 每预设一把 safeStorage（Windows DPAPI）密文密钥 |

```js
Provider = {
  id: 'p_xxxxxxxxxxxx', name: 'DeepSeek',
  apiFormat: 'openai' | 'anthropic',
  baseURL: 'https://api.deepseek.com/v1',
  enabled: true,                                   // 供应商总开关
  models: [{ name: 'deepseek-chat', enabled: true }],
  activeModel: 'deepseek-chat',                    // 该预设内「使用中」模型
  modelCfg: { 'deepseek-chat': { enabled, contextWindow, maxTokens, temperature, note } },
  params: { temperature: 0.7, maxContext: 10000, privacy: false,
            kb: { auto: false }, embeddings: { enabled: false, model: '' } }
}
```

**启停语义**：停用供应商 → 列表状态点变灰，若是当前预设则自动切到第一个启用预设
（没有其他启用预设时保留但 `ready=false`）；停用模型 → 不再可选，若是使用中模型则自动切到同预设下一个启用模型。

**兼容投影**：`baseURL / model / models / modelCfg / temperature / privacy / options / hasCredential / ready`
等旧字段名全部改为 getter 投影（指向当前预设），全站组件（助手栏、工具条、右键菜单、预设评测等）**零改动**。

## 三、旧配置迁移（幂等）

`loadSettings` 检测：`ai.providers` 为空且旧键（`ai.baseURL / ai.model / ai.models / ai.modelcfg /
ai.temperature / ai.maxContext / ai.privacy / ai.options / ai.credential`）任一有值时，
合成一个预设（名称按 baseURL 匹配内置模板：DeepSeek / 智谱 GLM / OpenAI / Ollama，否则「默认供应商」；
apiFormat='openai'），模型、专属参数（modelCfg）、生成参数原样搬入，`ai.credential` 密文**原样搬运**到
`ai.cred.<新id>`（DPAPI 密文绑定本机，无需重加密），写入新键后删除旧键。
导入旧备份后重载会再次触发同一迁移；预设已存在而旧键残留时会清理旧键，保持单一数据源。

**兼容入口**：`saveSettings(patch)` 保留（旧组件与多数验收脚本依赖），把单配置补丁映射到当前预设；
无预设时先创建「默认供应商」。`apiKey` 明文经 `credentialEncrypt` 落 `ai.cred.<id>`，空串清除。

## 四、双 API 格式（`services/ai/provider.js`）

`chatStream(opts)` 增加 `opts.apiFormat`（默认 `'openai'`，原路径逐字未动）：

- **URL**：anthropic 容错拼 `{baseURL}/v1/messages`（已含该路径原样；以 `/v1` 结尾则 +`/messages`）；
- **请求头**：`x-api-key` + `anthropic-version: 2023-06-01`；
- **请求体转换**（OpenAI 形态 → Anthropic）：system 消息合并上提至顶层 `system`；
  `{role:'tool', tool_call_id}` → `user` 消息内的 `tool_result` 块（连续工具结果合并同一 user turn）；
  assistant `tool_calls` → `tool_use` 块；`max_tokens` 必填（缺省 4096）；tools 转 `input_schema`；
  toolChoice `auto/none/指定函数` 映射；
- **SSE 解析**：`message_start / content_block_start(tool_use) / content_block_delta(text_delta | input_json_delta) /
  message_delta(stop_reason) / message_stop / ping / error`，**归一输出与 OpenAI 分支完全一致**
  （`{ text, toolCalls, usage, finishReason }`，`end_turn→stop`、`max_tokens→length`、`tool_use→tool_calls`），
  对话工具循环（dialogue.js，最多 6/24 轮）与用量统计无需感知格式差异；非流式 JSON 响应兜底；
- **能力边界**：anthropic 格式下 `listModels`（拉取模型）与 `embed`（向量）抛出明确错误，
  设置界面同步禁用「拉取模型」与「语义检索 / 向量模型」并给出说明；
- 错误分类、空闲超时、流式 400 回退等既有机制对两种格式共用。

## 六、写入时序保护（本次修复的真实缺陷）

`app:broadcast` 会回发给发送窗口自身，接收端以 `loadSettings` 重读 `appconfig`；
多步写入（如 `saveSettings`：先写预设再写密钥）若在中间态广播，接收端会读到「写了一半」的库并以
过期快照**覆盖内存**（实测：密钥保存后立即读为空）。修复（`stores/ai.js`）：

1. `withWrite` 写事务计数：事务内所有 `emitSettings` 合并为结束时的一次广播（嵌套安全）；
2. `loadSettings` 先 `waitForLocalWrites`（等本地写完成），并在读取期间有写事务结束时
   以**写事务世代号**判定快照过期、直接丢弃（交由写入方广播重载）。

## 七、备份与密钥（`db/repo.js`）

导出 / 导入的密钥排除由 `key !== 'ai.credential'` 改为 `!key.startsWith('ai.cred')`
——同时覆盖旧键与新键 `ai.cred.<id>`，密钥（明文与密文）绝不进备份 JSON；
`ai.providers`（不含密钥）正常进备份，恢复后重新填密钥即可用。

## 十、风险提示

- 降级到旧版本会因 `ai.baseURL` 等键已被迁移删除而显示「未配置」，需重新填写（数据仍在 `ai.providers`）；
- Anthropic 分支的 `/v1/messages` 拼接对常见中转（`https://host/v1`、`https://host`）容错，
  经代理接入时以代理路径为准；
- 每个预设各带一份生成参数，切换预设即切换温度 / 隐私模式等（按设计）。
