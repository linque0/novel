## Important

### 1. 点卷后再点当前章，管理目标仍可能留在卷上

- 定位：`src/components/ChapterTree.vue:43` 的目标同步 watcher、`:47` 的 `onSelect`（尤其 `:48–49`）、`:150–165` 的管理动作；受控选中值定义在 `:35–38`。
- 触发：已打开章节 A → 点击卷 B（或者新建卷 B）→ 用鼠标回点仍处于选中状态的章节 A → 打开目录管理并选择重命名 / 删除。
- 实际结果：目录视觉选中值仍为 `c:A`，但 `selNode` 保持卷 B。重命名会打开卷 B；确认删除会调用 `deleteVolume(B)`，该既有 store 动作会连同卷内章节一起移入回收站。删除确认虽然提示“本卷及其中章节”，但没有显示具体卷名，并未消除错误目标。
- 原因：`selectedKeys` 始终只返回当前章节。点击卷只改 `selVolumeId` / `selNode`，并不改变该受控值。Naive UI 默认 `cancelable: true`（本地依赖 `node_modules/naive-ui/es/tree/src/Tree.mjs:102–105`），再次点击已经选中的章节时发送 `[]`（`:693–697`）。`onSelect` 直接返回，`selChapterId` 没有变化，所以新增 watcher 也不会重新设定管理目标。
- 验证：在 Node 中直接提取当前组件的 script setup，使用真实 Vue `reactive` / `watch` / `nextTick` 和记录型 store，依次调用 `onSelect(['v:volume-b'])`、`onSelect([])`、`manage('delete')`、`confirmDelete()`；输出的可视选中值为 `["c:chapter-a"]`，删除目标为卷 B，最终调用为 `[["deleteVolume","volume-b"]]`。没有修改数据库。
- 来源说明：chapter-only `selectedKeys` 与空数组直接返回属于沿用逻辑；本轮新增的场景管理菜单及 watcher 继续暴露此缺陷，不能宣称它已被新增 watcher 完整处理。
- 修复建议：让鼠标点击当前章也能明确更新管理目标，并保证卷目标与视觉选中状态一致；可以利用 NTree 回调的节点元信息处理空数组，或明确在节点点击路径同步目标。仅设置 `cancelable=false` 时，已选中节点可能不再发 update，仍需验证不会保留旧卷目标。
- 必要回归：点击卷 / 新建卷后回点当前章，检查菜单重命名所示对象、删除确认目标、排序可用状态均对应当前章；同时保留直接管理卷的能力。

### 2. 阅读目录抽屉复用 ChapterTree，却漏接新快捷事件

- 定位：新增按钮在 `src/components/ChapterTree.vue:292–293`；漏接处为 `src/components/EditorPane.vue:515` 的 `<ChapterTree />`。对照已经接线的主目录 `src/components/Workbench.vue:265` 和独立窗目录 `src/components/PanelHost.vue:199`。
- 触发：引力或琉光皮肤 → 进入阅读模式 → 点击左缘目录按钮打开抽屉。主窗口与章节独立窗口均会出现。
- 实际结果：抽屉里的“阅读”和“独立窗口”呈可用状态；点击只向直接父组件 emit，父组件没有监听，因而没有任何动作。Vue 自定义事件不会继续冒泡至 Workbench。独立窗口中的抽屉也没收到 `in-panel`，因此错误显示可用的“独立窗口”，而不是禁用的“当前窗口”。
- 原因：新增 footer 会随着所有 scene `ChapterTree` 实例一起呈现，但本轮只给主侧栏和 PanelHost 侧栏接线，遗漏了已有的阅读抽屉实例。
- 验证：核对全部 `ChapterTree` 使用点，抽屉是唯一既没有 `@read` / `@window` 也没有上下文控制的实例。现有 Esc 退出路径仍在，因此不是无法退出阅读的死锁，但这两个入口确实没有功能。
- 修复建议：阅读抽屉只保留目录，显式关闭写作快捷 footer；如果决定保留快捷入口，则应明确实现阅读状态语义、接入拆窗处理并传入独立窗上下文。
- 必要回归：两皮肤分别在主窗口与章节独立窗口打开阅读抽屉，确认没有未接线的可用按钮，并确认切章 / Esc 两级退出正常。
