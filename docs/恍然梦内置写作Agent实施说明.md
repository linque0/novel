# 恍然梦内置写作 Agent：实施记录

日期：2026-10-13。依据已确认的《恍然梦 Agent：小说工坊全书写作助手详细实施方案》及酒馆 1.19 研究方案实施。

## 1. 当前交付范围

五个模块提供自己的「恍然梦 · 本模块助手」入口，共用现有模型设置、创作预设、检索服务与 AI 面板。模型先生成草稿或结构化提案；作者确认后由应用服务保存。通用聊天只提供只读工具，不能自行提交跨模块写回提案。

| 模块 | 专用任务 | 确认后的承载位置 |
|---|---|---|
| 正文 | 续写、选段改写、场景扩写、章节记忆提取 | 指定章正文；另行确认的摘要、事件、人物状态与伏笔 |
| 大纲 | 未来规划、正文反推章纲/卷纲 | 原生大纲节点；明确区分 `plan` 与 `written` |
| 设定 | 新设定设计、正文提取、指定条目修订 | 原生幕布设定树 |
| 人物 | 人物设计、正文捕捉、指定人物更新、关系提取、阶段状态提取 | 人物卡、关系表、带章节证据的状态记忆 |
| 灵感 | 创意扩展 | 灵感条目；作者可选择保存关联建议 |

共 15 类明确任务。人物阶段状态任务只产出状态记忆，不能修改人物卡或关系图。人物设计不能把尚未发生的阶段状态登记为事实。

## 2. 作者使用流程

1. 在对应模块点击助手入口，选择本模块任务和目标。正文改写需先选中正文；反向总结和正文提取需明确选择章节范围。
2. 填写本次要求，生成待确认结果。生成期间可以取消；错误、超时、工具不受支持、预算不足或未返回完整提案都不能当作完成。
3. 在 AI 面板查看结果、出处摘引、冲突/缺口与核查说明。设定和人物修订可以查看现有资料；正文改写可对照原选段和新稿。
4. 确认保存，或拒绝/重新生成。应用失败保留提案；应用成功提供撤销。后续编辑已改变应用内容时，撤销停止，避免覆盖作者后续修改。
5. 专用正文草稿保存后启动章节记忆提取。记忆仍是独立待确认提案；提取失败时正文保存保留，作者可重试记忆提取。

来源摘引可跳转对应模块，正文证据可以打开章节并定位选段。各项提案展示自身证据，不只展示一份总来源列表。

## 3. 模块隔离与上下文

- `task-profiles.js` 明确任务类型、模块、目标、范围、输出工具和允许的应用操作。
- `dialogue.js` 为每次任务仅注册一个对应模块的提交工具；运行时再次核对授权工具名。模型的自由聊天指令不能扩大权限。
- 正文续写仅追加到绑定章节；选段改写与有选段的扩写仅替换原选段。专用任务不能借通用「保存为新章节」入口扩大目标。
- 原文提取任务屏蔽未来规划工具、旧事实检索和旧摘要输入，限制检索章节范围，并跟踪逐页读取进度。未顺序读完选定章节不能提交完整提案；超长范围超过轮次/预算时明确失败，不把局部读取称为全书总结。
- 正文创作可以读取作者人物卡作为创作约束，标记为 `author-profile`；人物阶段状态另从已确认正文记忆回放。作者档案不等同当前或过去已经发生的事实。带生效章节的关系不会注入生效之前的任务。
- 大纲规划只表示未来计划。正文反推大纲保存为已写内容纲，附正文版本依赖，检索时按摘要性质处理；原文变化后旧内容纲不继续作为有效记忆注入。
- 正式资料、未来计划、已发生摘要、候选灵感与待确认输出保留不同性质。专用任务历史按类型/目标筛选，并明确待确认生成内容不能作为书内事实。

设定/人物承担酒馆世界书的知识注入用途，未来大纲和已发生摘要承担不同的规划与记忆职责；全书理解依靠检索与外部记忆，不进行模型训练。

## 4. 提案应用与恢复

`task-proposals.js` 校验结构、书籍/目标、实体身份、来源版本与摘引位置。人物同名、别名冲突、悬空关系、自关系、重复修改同一实体和重复关系会被拒绝。

`task-application.js` 在保存前刷新自动保存，获取作品应用锁，并同时比较当前工作区与数据库的作品来源版本。结构化提案、批量人物/关系/状态与应用记录在一个数据库事务内提交；任何一项写入失败都整批回滚。界面内存只在提交成功后同步。

人物联合提案以临时键连接新人物与关系，应用时生成真实 ID，并将关系端点映射到这些 ID。关系图继续读取正式 `relations` 表，因此只展示作者已确认的关系；候选关系留在提案预览中。

应用记录保存每条变更的前后快照，用于检查后续修改并整批撤销。专用任务记录保存请求、结果和来源，重新打开作品可恢复待确认/已应用/已撤销结果；拒绝状态也持久化。记录不保存 API 密钥或隐藏推理。

当前采取保守的全作品来源变化保护：即使作者修改了本次未使用的正式资料，旧提案也可能要求重新生成。后续可在完整依赖记录可靠后缩小检查范围。

## 5. 正式记忆确认规则

- 自动提取的旧知识库事实和章节摘要默认视为待确认；原有缓存不会删除。
- 只有已确认、证据有效、正文版本匹配的摘要与事实参与后续检索。
- 人物阶段状态保存发生章节、人物 ID、维度、变化和原文摘引；不会通过状态任务覆盖长期人物字段。
- 已发生摘要来自实际正文，未来计划和未采纳灵感不能成为正式剧情记忆。
- 作者可以在知识面板确认有效摘要/事实。过期、覆盖不完整或依赖无效的记录必须重新提取。
- 专用记忆提案确认时更新该章摘要并保存带证据事实；撤销会恢复先前摘要并移除本次事实。

## 6. 数据与兼容

沿用现有 `olnodes`、`mubu`、`characters`、`relations`、`snippets`、`aisum`、`aikb`、`airuns`，新增字段不要求迁移作者正文。只读投影版本升级到 2；旧投影不被误用，使用当前源数据重建/回退投影。

新增/补充字段主要有大纲性质与正文依赖、来源证据、状态确认、灵感事实/创意及可选关联、任务/应用记录。既有作者资料没有这些字段时仍按作者记录处理；旧大纲仍作为计划。

酒馆是能力参照。此交付不宣称完成酒馆 1.19 的完整世界书格式导入、全部关键词激活语义、扩展脚本执行、世界自动推演或百万字性能验收。

## 8. 真实模型验收入口

待工坊恢复有效模型配置后，在独立验证窗口运行：

```powershell
$env:CDP_PORT = '9333'         # 独立 booksource-verify 窗口
$env:MODEL_SOURCE_PORT = '9222' # 已配置真实模型的工坊窗口
node tools/agent-task-verify.mjs --real
```

脚本检查指定模型与已知 mock 端点，使用工坊原生凭据解密/加密接口，临时把真实配置复制到隔离验证目录，结束时恢复该目录原配置；原工坊配置不改写。使用可解密的配置备份时可显式设置 `MODEL_CONFIG_BACKUP`，但不可用失效密文或测试密钥替代。普通运行只执行确定性机制检查。

真实输出必须继续人工/样书核查：续写是否遵循前文、人物状态与章纲；反向总结是否混入未来事件；人物与关系是否有明确证据；冲突设定是否被提示；灵感是否区分事实与创意。模型自述的 `review` 仅是核查说明，不能保证语义正确，也不代替作者确认。
