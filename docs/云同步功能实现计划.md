# 小说工坊云同步功能实现计划（v1.1.0）

> 版本定位：v1.1.0（大特性）｜ 参考实现：Obsidian 坚果云插件 nutstore-sync v1.5.0（`E:\小小的说\obsidian笔记\linque\.obsidian\plugins\nutstore-sync`，已从其打包源码提取全部设计参数）
> 关联文档：`docs/开发流程.md`（工程纪律权威）、`docs/工作报告书.md`（第八节规则总纲）、`../小说创作软件开发计划.md` 9.3 节（「多端云同步（可选）」由本文升格为正式排期，本文即其落地设计）

## 〇、一句话方案

**不做数据库同步，做「快照同步」**：以「作品」为同步单元，把每部作品序列化为一个 JSON 快照文件，经坚果云 WebDAV 上传/下载，以同步记录（etag）做三向比对（本地 / 同步记录 / 云端），决定上传、下载、冲突或跳过。

## 一、参考插件的设计要点（已提取）

| 维度 | nutstore-sync 的做法 |
|---|---|
| 协议 | WebDAV：`dav.jianguoyun.com/dav`（个人版）/ `/nsdav`（企业版）；PROPFIND 列目录、MKCOL 建目录、GET/PUT 传文件，etag 作版本戳 |
| 认证 | 双模式：手动（账号 + 应用密码，存本地配置）与 SSO（OAuth）；`data.json` 中对应 `loginMode` / `credential` / `oauthResponseText` |
| 同步策略 | 双向 / 仅发送 / 仅发送覆盖 / 仅接收 / 仅接收还原（`syncPolicy`） |
| 冲突策略 | 无冲突合并（双方保留，生成副本）/ diff3 三方合并（留冲突标记）/ 本地优先 / 云端优先（`conflictStrategy`） |
| 比对模式 | 宽松（loose：无同步记录时同路径同类型同大小即视为相同）/ 严格（strict：逐一比对） |
| 调度 | 实时监视 + 启动延迟 + 定时（默认 300s）+ 同步前确认 + 自动同步删文件前确认 |
| 保护 | glob 过滤规则（排除 .git / node_modules 等）、大文件跳过（30MB）、移动端分块（16MiB） |

插件是**文件对等同步**模型（Obsidian 库 = 一堆 md 文件，天然可逐文件比对）。小说工坊的数据在 IndexedDB 里，必须把「文件同步」翻译为「快照同步」。

## 二、总体方案

### 2.1 两条红线

1. **绝不在坚果云目录里放数据目录**。IndexedDB 底层是 LevelDB，运行中持续写 `.log`/`.ldb` 并定期压缩合并，同步工具在写入中途复制或替换这些文件会损坏数据库（Syncthing / Nextcloud 官方文档均明确警告此模式）。
2. **应用云端快照 = 一次「按作品恢复」**，必须复用 v1.0.22 修复恢复备份时确立的安全路径：先 `autosave.flushAll()` → `discardPending()` → 事务写库，且受影响章节先写版本快照。跳过任何一步都会重蹈「防抖队列把恢复前旧状态写回、覆盖新数据」的覆辙。

### 2.2 同步单元与远程结构

远端目录（默认 `/novel-studio/`，MKCOL 自动逐级创建）：

```
manifest.json            # 库级：作品清单（id/标题/封面款/updatedAt/etag/软删标记），几十 KB
works/<workId>.json      # 每作品一个全量快照：卷/章/人物/关系/设定/幕布/大纲/灵感/批注/wordlog
                         # + assets（图片 base64，v1 内嵌；v2 拆独立文件）
```

选「作品」而非「单章/单实体」为同步单元的理由：导出可按作品整体构造（`exportBackupJson` 的 16 张表清单按 workId 过滤即可，改动量最小）；作品是作者心智中的「一本书」，冲突语义天然（「这本书两边都改了」）；主键为 UUID，新作品在各设备间合并无 ID 冲突。单实体级同步留作 v2（届时冲突可细化到章节，并支持 diff3 文本合并）。

### 2.3 版本戳与同步记录

- 服务端版本戳用 PROPFIND 返回的 **etag**；若实测坚果云 etag 不稳定，退化为内容 hash 比对（即插件的 strict 严格模式，v1 直接按严格实现，不做 loose 猜测）。
- 本地新增 `syncstate` 表（Dexie v7 迁移，新表旧表保留原则）：每作品 `{ workId, etag, syncedAt }` + 全局 `{ deviceId, lastSyncAt, lastResult }`。
- **三向比对**（插件「同步记录」的等价物）：本地内容 vs 同步记录 vs 云端 etag → 仅本地变→上传；仅云端变→下载；均未变→跳过；双边都变→冲突策略。

## 三、功能设计

### 3.1 认证与凭证

- v1 只做**手动模式**：账号 + 坚果云「应用密码」（网页端生成、可随时吊销、仅授权 WebDAV），Basic Auth over HTTPS。插件的 SSO 模式需要把开放平台 client secret 打进安装包，安全上更重，列 v2。
- 凭证**必须**经 Electron `safeStorage`（Windows DPAPI）加密后 base64 存入 appconfig（键 `sync.credential`），绝不明文落库；「退出登录」清凭证并停止全部同步。
- 远端目录可配置：基础地址（个人 / 企业 / 自填）+ 路径前缀（默认 `/novel-studio/`）。

### 3.2 同步策略（对齐插件 syncPolicy，v1 收敛为三种）

| 策略 | 行为 | 场景 |
|---|---|---|
| 双向同步 | 本地新→传；云端新→下；双边改→冲突策略 | 主力模式 |
| 仅上传 | 只传不下载，云端删除不影响本地 | 纯备份 |
| 仅下载 | 只下载不上传 | 换机恢复 |

插件的「仅发送覆盖 / 仅接收还原」会删除另一端的数据，写作软件删稿是红线，v1 不做。

### 3.3 冲突策略（作品粒度）

| 策略 | 行为 |
|---|---|
| 保留双方（默认） | 本地不动；云端版本下载为带时间戳的备份文件（恢复入口可见）并 toast 告知——对应插件 no-conflict-merge |
| 本地优先 | 用本地快照覆盖云端 |
| 云端优先 | 下载覆盖本地；**应用前强制给受影响作品全部章节写版本快照**（可回滚） |

diff3 文本级自动合并不适用于整作品快照，随 v2 单实体同步再做。

### 3.4 触发与调度

- **手动**：设置面板「云同步」区「立即同步」。
- **定时**：默认 300s（可关可调）——对应插件 autoSyncIntervalSeconds。
- **启动延迟**：默认 30s 后自动同步一次——对应 startupSyncDelaySeconds。
- **近实时**：autosave `flushAll` 完成后置 dirty 标记，距上次同步超 60s 则触发一次——插件 realtimeSync 在本项目的对应物，v1 做到分钟级，秒级即时同步列 v2。
- **同步前确认**：默认开，弹窗列出计划（上传 N / 下载 N / 冲突 N），确认后执行——对应 confirmBeforeSync。
- **删除保护**：云端 manifest 少了某部已同步作品时**默认不删本地**，仅提示用户手动处理——对应 confirmBeforeDeleteInAutoSync，直接定在默认安全侧。

### 3.5 同步期间的数据安全

- 同步开始先 `await autosave.flushAll()`（否则上传的是内存旧状态）；
- 应用云端快照前 `autosave.discardPending()`（v1.0.22 备份恢复 bug 的同款防护，缺一不可）；
- 同步状态置 `syncing` 期间，autosave 新产生的脏数据在同步完成后统一 flush，不与同步写库竞争；
- 每作品快照带 `schemaVersion`，低版本 app 读高版本快照时明确拒绝并提示升级，不静默猜测。

## 四、与现有架构的集成点

| 集成点 | 做法 |
|---|---|
| autosave | 见 3.5；syncstate 写入复用 appconfig 同款 put 通道 |
| 版本快照 | 云端优先覆盖前对受影响作品全部章节 forceSnapshot（工程纪律第 4 条：影响用户正文的操作必须先写快照且可撤销） |
| 多窗口 | 同步只在主窗口执行；应用完成后经 `panels.js` 既有 `broadcast` 广播 `sync:applied { workIds }`，主窗口重载受影响作品 store，面板窗口提示「数据已更新，点击刷新」。跨窗口实时刷新（计划书 W3）本身是待办，v1 用「广播 + 手动刷新」兜底，不阻塞云同步交付 |
| 单实例 | 云端写库可能与面板实体锁冲突：目标作品正被面板占用时**跳过该作品**并在同步结果中列出（v1 保守策略） |
| 网页版 | 不支持：浏览器 IndexedDB 与桌面数据独立，且 WebDAV 走浏览器有 CORS 限制；UI 明示 |
| appconfig（主题/字体/侧栏宽等） | 设备本地设置，**不同步**（manifest 与作品快照均不含 appconfig） |

## 五、分阶段实施拆解

> 遵循项目编辑纪律：纯逻辑模块（.js，可脚本自测）+ 组件壳（.vue）；单次文件写入 ≤300 行；每步 `npx vite build` 语法门禁。

**P0 地基（S1–S3）**
- **S1**：`syncstate` 表（Dexie v7 迁移）+ deviceId 生成 + `src/services/syncauth.js`（safeStorage 凭证加密/解密/清除，纯逻辑可脚本自测）。
- **S2**：`src/services/webdav.js`：PROPFIND（DOMParser 解析 etag / lastmodified）/ GET / PUT / MKCOL / DELETE + Basic Auth + 错误分类（401 凭证错 / 403 / 404 / 409 / 网络不通 / 5xx）。全部走 fetch，**零新 npm 依赖**（对齐「零新依赖优先」原则）。
- **S3**：`tools/mock-dav.mjs`：node http 最小 WebDAV 服务（PROPFIND / GET / PUT / MKCOL / DELETE，临时目录存储）——验收基建，**验收绝不连真实坚果云**。

**P1 快照序列化（S4–S5）**
- **S4**：`repo.js` 增 `buildWorkSnapshot(workId)` / `applyWorkSnapshot(workId, json)`：导出 = 按 workId 过滤现有备份表清单；应用 = 事务内先删该作品旧行再写快照行（软删行随快照传播）+ 受影响章节 forceSnapshot。
- **S5**：manifest 生成 / 解析 / 合并（新作品并入、软删传播、etag 更新）。

**P2 同步引擎（S6–S8）**
- **S6**：`src/services/sync.js`：三向比对 → 同步计划（upload / download / conflict / skip 清单）→ 顺序执行 → 更新 syncstate；参数为 mode + conflict 策略。
- **S7**：调度器：手动 / 定时 / 启动延迟 / flushAll 后 dirty 触发；`sync` store（idle / syncing / error + lastSyncAt + 上次结果摘要）。
- **S8**：冲突与确认 UI：同步前确认弹窗（计划清单）、保留双方落地为备份文件、云端优先前的快照提示。

**P3 界面与接线（S9–S11）**
- **S9**：设置面板「云同步」区（G 风格）：账号 / 应用密码 / 远端目录 / 策略 / 调度开关 / 立即同步 / 上次同步状态 / 退出登录；首次开启二次确认（明示「未发表作品将上传至你的坚果云账号」）。
- **S10**：`sync:applied` 广播 + 主窗口 / 面板刷新接线。
- **S11**：`tools/sync-verify.mjs`（CDP + mock DAV，断言清单见第六节）。

**P4 打磨与发布（S12–S13）**
- **S12**：健壮性：大作品（>20MB）警告与跳过（对齐插件 skipLargeFiles）、断网 / 超时重试与错误文案、配额超限（507）提示、上传进度。
- **S13**：文档四同步（README / 产品介绍 / 使用手册 / CHANGELOG）+ 版本号升 v1.1.0 + `npm run dist` 打包 + pack-smoke。

## 六、验收计划

`tools/sync-verify.mjs`（CDP 真实事件驱动，本地 mock DAV）：

1. 首同步：本地 2 部作品 → 上传 manifest + 2 快照，syncstate 落 etag；
2. 无变化二次同步：0 上传 0 下载（etag 命中跳过）；
3. 新设备（新 profile）首同步：下载并完整还原 2 部作品（逐表行数、章节字数断言）；
4. 双边修改同一作品 → 三种冲突策略各自行为（保留双方落备份文件 / 本地优先覆盖 / 云端优先覆盖且快照存在）；
5. 仅上传 / 仅下载模式方向正确；
6. 凭证错误（401）→ 明确错误文案，不静默失败，本地数据无损；
7. 同步期间 autosave 不覆写（同步前制造脏数据，断言 flushAll 先于上传、apply 后 discardPending 生效）；
8. 默认关闭状态下零网络请求（硬断言）。

另按大特性合并规格执行：四套全量回归（canvas-model / chargraph / olcanvas / relfollow）+ `npm run build` + 双主题截图 + pack-smoke。真机连接用户坚果云的最终验证由用户完成。

## 七、风险与对策

| 风险 | 对策 |
|---|---|
| 同步损坏数据库 | 只同步快照 JSON，红线写进文档与代码注释；验收第 7 项专门守 |
| 云端快照覆盖较新本地稿 | flushAll + discardPending + 强制快照三件套；云端优先前额外确认 |
| 两设备同时改同一作品 | v1 以作品为冲突粒度，默认保留双方；UI 明示限制 |
| 未发表作品外传 | 默认关闭、首次开启显式授权、随时退出登录、凭证 safeStorage 加密、仅连用户配置的 dav 域名且强制 HTTPS、证书错误明确失败 |
| 坚果云流量 / 配额 | 快照体积在设置内可见；>20MB 警告；v2 assets 拆文件 + gzip 传输 |
| 多窗口写竞争 | 目标作品被面板占用时跳过该作品并在结果列出 |
| 安全宣称 | Mimosa 完整审计未过，发布说明只列改动与验收数据，不做安全性断言 |

## 九、v1 明确不做（留接口，列 v2+）

SSO / OAuth 登录；单实体（章 / 人物级）同步与 diff3 自动合并；秒级即时同步；跨窗口实时刷新联动（依赖 W3）；网页版同步；assets 独立文件与增量传输；与自动更新器联动。
