## 一、项目概况

**小说工坊**是一款本地优先的小说创作软件（Electron + Vue 3 + Dexie/IndexedDB），面向个人作者，核心主张：正文/大纲/人物/设定/灵感一站式管理，**输入即存、永不丢稿**，所有数据留在本机。

| 项 | 状态 |
|---|---|
| 技术栈 | Electron 33 + Vue 3 + Pinia + Naive UI + TipTap（正文富文本）+ 自研幕布编辑器 + Dexie + ECharts + 自研画布引擎（graphview.js）+ 多窗口面板（panels.js） |
| 版本演进 | v0.1.0 初版 → v0.2.x 富文本+导入 → v0.3.0 幕布设定库 → v0.3.2 书签 → v0.3.3–0.3.5 双链 → v0.4.0 大纲导图重构 → v0.4.1 自由模块画布+人物关系图 → v0.4.2 画布交互打磨 → v0.4.3–0.4.5 画布修复批次 → v0.4.6 功能面板多窗口 → v0.4.7 侧栏调宽 → v0.4.8 面板完整界面化 → v0.4.9 画布右键建模块+Delete 删除 → v0.4.10 关系图拖线改关系 → v0.4.11 关系图体验增强 → v0.4.12–16 连线端口锁定与避障路由系列（**当前 v0.4.16**） |

## 二、已完成功能清单

### 1. 核心写作（v0.1–v0.2）
- **自动保存**：输入防抖 1s 落盘 + 30s 兜底 + 失焦/切章/关窗前强制保存；顶栏常驻保存指示；章节版本快照（滚动保留 30 份）可回滚；崩溃恢复经强杀进程验证。
- **正文编辑**：卷-章两级树（拖拽/按钮排序）；TipTap 富文本 + Word 风格工具栏；正文右键快捷菜单（20 项，含二级飞出菜单）。
- **五模块**：正文、大纲、人物、设定（见 2）、灵感；**导入导出**：TXT（GBK 识别+智能分章）/ MD / DOCX / PDF / EPUB / 图片；整库 JSON 备份恢复。
- **其他**：全局搜索、回收站、统计看板（ECharts）、三套主题、沉浸模式。

### 3. 书签系统（v0.3.2）

### 7. 画布交互打磨（v0.4.2）
- **前批**：连线对齐接口（fromSide 存储随边 + 换侧自动回退）、实线/虚线/点线三线型、连线粗细设置、标签中段上方显示、模块边缘调整大小（放大显示全文）、容器与普通模块同级化、**文本框独立模块**（虚线框/透明度滑杆/双链卫星/拖入归组）、容器八向调整与右键七色调色板、**侧栏层级树**（容器从属缩进+折叠，与画布同步）、**文本视图容器内容**（子模块内容卡片+所属容器面包屑）；
- **本轮（2026-09-02 晚）更新**：
  1. **模块可拖拽出容器**——落点判定与容器派生盒计算排除被拖子树（否则盒子随节点扩张永远"拖不出"），拖出即回根级、拖入即归组；
  2. **双击行内编辑修复**——编辑态给节点显式高度（修复 absolute 编辑器撑不开节点）+ `.oc-node.editing` 解除 clip-path 并恢复边框底色，五类形状（矩形/菱形/平行四边形/便签/文本框）编辑区完整可见；
  3. **菱形/平行四边形改 SVG 描边**——弃用 clip-path 方案（裁掉边框、锚点悬空），节点内嵌 SVG polygon（viewBox 拉伸铺满），形状顶点恰在连线锚点上，hover/选中描边高亮，锚点与缩放手柄恢复贴边；
  4. **事件高度拖拽 + 四角同时调宽高**——根因是非容器节点 `height:'auto'` 不渲染落库高度；改为显式高度渲染（与连线锚点几何一致），resize 只落库被拖轴（横拖不再钉死高度），四角手柄补方向光标。

### 8. 功能面板多窗口（v0.4.6 / v0.4.8，计划书 9.2-W5 首批）
- **五类模块拆出为完整功能界面的独立面板窗口**：顶栏「⧉ 拆窗 ▾」（正文/大纲/人物/设定/灵感），面板 = 侧栏 + 正文区（正文含右栏资源面板）+ 调宽手柄，与主窗口同一套组件零改动复用，**可在面板内自由切换章节/人物/条目**；正文面板挂载双链悬浮预览与版本历史；
- **架构**：面板窗口加载同一应用（`?panel=<type>:<workId>:<entityId>` 启动参数），PanelHost 精简布局（迷你工具条=作品·条目名+保存状态+保存并关闭）；面板持有自己的 work store 与 Dexie 连接，写经锁互斥、保存复用 autosave 链路；
- **实体锁随面板选中迁移（v0.4.8）**：`panel:set-entity` 原子迁移锁（旧锁释放/新锁登记/moved 广播）——面板切到章节二时主窗口章节二转只读、章节一恢复可写，占位实时跟随；主进程锁表保证同作品同实体全应用仅一个可写窗口，重复拆出自动聚焦已开面板；
- **主窗口只读占位**：章节/人物/灵感为条目级跟随锁（当前被面板占用的条目只读 +「前往窗口」，其余条目照常可写）；大纲/设定为模块级锁（对应页签整体占位）；
- **生命周期**：面板按类型记忆几何（userData/panel-geometry.json，夹取可见屏），关闭前 `__flushNow` 优雅保存，主窗口关闭级联关闭全部面板。

### 9. 画布右键建模块 + Delete 删除（v0.4.9）

### 12. 连线端口锁定与避障路由（v0.4.12–v0.4.16，2026-09-05，明细见 CHANGELOG）

- **v0.4.14–15 严格端口 + 避障初版**：建立连线时记录两端接口（fromSide/toSide）存库，渲染严格锁定、节点挪位不漂移；存量连线首次渲染一次性补记；两端节点本体纳入障碍集；
- **v0.4.16 避障路由重写（当前方案）**：最简首形（Z/L）无碰撞直用；被挡或端口背对时在 Hanan 稀疏网格（障碍膨胀边界 ±margin + 桩端点张成）上跑 A*（曼哈顿段长 + 转向惩罚）全局最短路，再直连/L 形拉直收敛；绕行段保 2px 可视间隙；旧贪心逐段绕行仅作重叠节点病态布局兜底。v0.4.14/15 的贪心与包络环绕方案会绕出巨型路线/重复段，已由全局最优取代。

## 五、重要决策与回退记录

1. **v0.4.0 插件化尝试 → 已回退**：插件架构不满意，回退至 v0.3.1，存档 `backup/v0.4.0-plugins`。踩坑记录：`git reset` 不回退被 ignore 的 `dist\`，**回退后必须重新 build 再打包**（实际发生过）。
2. **v0.3.7 大纲文本优化实验 → 回退**：存档 `backup/v0.3.7-outline-text`。
3. **OutlineMap 退役（v0.4.1）**：画布与导图两套并行实现统一到 OutlineCanvas，保留侧栏与 olTypes。
4. **clip-path → SVG 描边**：clip-path 天然裁掉边框/锚点/手柄，形状渲染改节点内 SVG polygon，描边随形状走。
5. **面板锁粒度分两级**：章节用实体级锁（主窗口该章只读、其余章节照常可写）；大纲/设定幕布为跨节点树编辑，用模块级锁（对应页签整体占位）——粒度跟随编辑面，避免"锁了半个模块"的假安全。
6. **取消安装程序/便携版**：仅保留免安装本体；node_modules 裁剪 504MB→279MB（v0.4.1 实测 231MB）。

## 八、工作规律与规则总纲（协作沉淀，2026-09-05 随 v0.4.16 校准）

> 本节是给后续接手人员的操作手册：每次代码更新照此执行，可避开本项目踩过的全部坑。功能史见第二节与 CHANGELOG；本节只讲"怎么干活"。多数条目背后都有一次真实的翻车教训（括号注明年份版本），不要凭感觉绕过。

### 1. 版本更新规则（硬性纪律，缺一不可）

1. **一个版本 = 一个特性粒度**：一批相关修复或一个功能 → patch +1（v0.4.14→15→16 皆如此）；不攒批、不拆碎；版本号只进不退（不满意的实验走 `backup/` 存档回退，见第五节）。
2. **每次代码更新四处同步版本号，且在同一批提交内完成**：
   - `package.json` 的 `version` 字段；
   - `README.md` 第 3 行括号内版本号 + 末尾"最近一次验收"计数行；
   - `CHANGELOG.md` 顶部新增该版本段（日期 + 一句话定性 + 修复点/算法要点 + 验收数据）；
   - git 提交信息以 `vX.Y.Z：` 开头，正文为 CHANGELOG 要点浓缩（含验收计数）。
3. **单分支直推 main**（2026-09-03 起）：所有开发与发布都在 `main`，不新建/不删除版本分支，里程碑发布点打 tag 存档；构建产物不入库。
4. **仅文档/工具脚本改动**可不升版本号，提交信息注明"仅文档"（前缀沿用当前版本号）；源码（src/、electron/）改动一律升版。
5. **每版随发布重建交付物**：`npm run dist`（= vite build + electron-builder --win，输出 `release/`）。若旧 `release/win-unpacked` 的 app.asar 被占用（进程列表查不到占用者也会发生），**不要纠结解锁，直接换新输出目录** `-c.directories.output=release-<版本>`（本仓库既有做法）；打包完成后以测试 profile 启动打包 exe 跑 `pack-smoke`，用户以最新构建重启 app 后本轮才算交付闭环。

### 2. 标准更新流程（五步法）

1. **定位**：先读 CHANGELOG 同类版本段与本节第 6 条（画布问题的头号嫌疑是遗留 CSS 与两画布不对称）；
2. **修复**：源码一律用 Write/Edit 工具改（见第 5 条环境约束）；
3. **验证**：纯逻辑改动跑对应 node 直测脚本；UI 改动跑 CDP 端到端脚本 + 相关全套回归（清单见第三节）；
4. **四处版本同步**（第 1 条）；
5. **提交推送 + dist 重建**（第 1 条第 5 款）。

### 3. 验证规律（最容易翻车的环节）

1. **DOM 属性 ≠ 渲染结果**：CSS 规则优先级压过 SVG 表现属性——v0.4.13 真因即退役组件遗留的 `.om-edges path { stroke: var(--border) }` 让两画布连线永远灰、粗细锁死，而箭头/标签不受影响，呈现出"只有中段变色"的假象。判断"颜色/粗细为什么不变"必须查 getComputedStyle 或做像素采样，不能只看元素属性；
2. **像素级验证法**：CDP `Page.captureScreenshot` → 页面内 Image+canvas `getImageData` → 采样目标点与期望色比色距（阈值 ~60）；"位置不对/没绕开"类问题沿折线多点采样断言不入模块矩形（relfollow check13 用 80 点采样）；
3. **真实鼠标事件**：CDP `Input.dispatchMouseEvent`（带命中测试）优于合成 `dispatchEvent`；Chromium 对 SVG `pointer-events:stroke` 路径的 contextmenu 命中与 mousedown 可能不一致，右键目标需 `elementFromPoint` 反查真实落点（v0.4.13）；
4. **验收脚本用全新 profile**：脏数据跨轮残留会造假失败（relfollow 曾因旧 profile 数据 3 项假失败，换新 profile 即全绿）；
5. **CDP 连接按窗口 title 精确匹配**：打开面板窗口后 `connect('app://')` 会命中第一个 target（可能是面板页而非主窗口）；
6. **锁屏会冻结一切渲染**：LockApp 状态下 rAF 不触发、Vue 过渡冻结、含 `location.reload` 的检查挂起——脚本卡住先怀疑环境（v0.4.12 轮 olcanvas/cdp-test 因此受阻，代码无问题）；
7. **探针不可绕过组件直写数据库**：组件的 flushSave 定时器会覆写外部直写（人物图验证曾复现），造数据要走真实交互路径（dragNodeTo 等）；生产构建无 `__vueParentComponent`，组件实例调试改用 store 行为对比/埋点；
8. **画布处于 pan-zoom 变换层**：DOM 测量用 CSS px（offsetWidth/offsetHeight），勿用 getBoundingClientRect（被变换缩放）。

### 4. 调试与测试纪律

1. 调试/验收结束必须 `npm run stop` 完全退出（优雅关闭确保落盘）；**用户正在运行的实例绝不动**；
2. 自动化只跑一轮，失败即止不重试；修复后复验同样只跑一轮；
3. **验证书数据归属开发调试版（2026-09-06 二次修订，取代同日「默认数据直跑」版）**：`npm run dev` 已挂 `--profile=dev`（数据目录 `%APPDATA%\小说工坊-dev`，9 本验证书所在地）；CDP 验收连 `npm run dev` 实例或 `electron . --profile=dev --remote-debugging-port=9222`，脚本按书名幂等复用；`npm start` 正式启动版只含真实书目（浮世/星尘旅人），不得写入测试数据；历史测试 profile 已于 2026-09-06 合并清理（91 本并入后去重至 9 本）；
4. **常规更新不做全量回归，按用户指令执行（2026-09-07 起）**：日常版本更新只做**针对性验证**——改动所及功能的主路径实测（如改导出只验导出各分支、改路由只验路由场景）+ 构建（`npm run build`）通过即可；canvas-model-test / chargraph / olcanvas / relfollow 四套全量回归**仅在用户明确要求时执行**（适用场景：大版本合并、里程碑打包、涉及共享底层（canvas-model/仓库/store）的改动、久未回归后的集中确认）；打包交付前是否全量回归同样听用户指令；
5. 打包冒烟仍用独立 profile 启动打包 exe（只验启动不落数据），测完即杀进程并删 profile。

### 5. 环境与工具约束

1. **源码一律用 Write/Edit 工具写入**：Mimosa hook 会拦截 Bash 直写源码/安全配置文件；`tools/` 下验证脚本等临时文件不受限；
2. **不得在任何交付物中宣称"项目安全"**：commit/push 时 Mimosa hook 提示"未得到完整扫描结论（library_source_limit_exceeded）"，措辞上只列改动与验收数据，不做安全性断言；完整深度审计仍是待办（第六节）；
3. 中文路径走 spawn 数组传参（execSync 经 cmd 会 GBK 乱码）；网页版固定端口 18688；
4. 打包流程：改源码 → `npm run dist` →（文件锁则换输出目录）→ pack-smoke。

### 6. 画布连线技术规律（v0.4.12–v0.4.16 五连修沉淀）

1. **两画布对称实现**：大纲（OutlineCanvas.vue + olnodes.rels）与人物图（CharacterGraph.vue + relations 表）功能对等。任何连线能力改动必须两侧同步实现 + 双回归，漏一侧用户必反馈另一处；
2. **严格端口语义**：建立连线时记录 fromSide/toSide 存库，渲染只用记录值；存量数据首次渲染一次性补记（migratedSides Set 防重复触发）。推导默认端口用 `sideBetween`（面向对端一侧），**不要用"落点最近接口"**——节点中心处上下口恒比左右口近，语义会漂移（v0.4.15 教训）；
3. **路由算法现状（v0.4.16，canvas-model.js 共享）**：先试最简首形（Z/L，无碰撞直用）；被挡或端口背对时在 Hanan 稀疏网格（障碍膨胀边界 ±margin 与桩端点张成）上跑 A*（曼哈顿段长 + 转向惩罚）全局择优，再直连/L 形拉直收敛；旧贪心逐段绕行仅作节点重叠病态布局兜底。**演进教训：v0.4.14 贪心逐段、v0.4.15 包络外环绕 + 长桩延伸，都会绕出巨型路线/来回重复段——局部贪心不等于全局最短，绕障类需求直接上全局最优**；
4. **两端节点本体必须纳入障碍集**，桩出端保证在矩形外；`segHitsRect` 用严格重叠（>、<）防贴边误判；
5. **改渲染前先全仓搜历史 CSS**：退役组件（OutlineMap，v0.4.0 退役）的规则曾存活到 v0.4.13 才被发现。遗留 CSS 是画布样式问题的头号嫌疑；
6. **用户对同一问题反馈第二次起 = 前次修复未打中真因**：此时不能再沿"改掉明显可疑点"的思路，要么搭可复现环境做像素级自证，要么向用户要现象细节（v0.4.13 真因正是靠用户一句"变色的只有中段块和箭头"锁定的）。
