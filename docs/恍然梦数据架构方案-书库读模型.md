# 恍然梦书内知识与创作闭环数据架构方案（优化版）

> 性质：目标架构与分阶段验收方案。2026-10-13 已实施数据基础与上下文接入，实际范围见 [书库读模型实施说明](恍然梦书库读模型实施说明.md)；本文的完整创作闭环仍是后续目标。
> 起草：2026-10-12；优化：2026-10-13。
> 目标：让恍然梦完整访问一本书的正文、设定、大纲、人物、人物关系、灵感与批注，建立可追溯的作品记忆，并支撑正文辅助写作、按纲生成、正文反推大纲、人物捕捉与原创、关系图自动构建及设定一致性检查。
> 基线：以当前工作区代码为准；相关文档包括《AI助手接入方案》《AI助手优化方案-恍然梦v2》《AI助手优化方案-恍然梦v3-酒馆式注入引擎》《恍然梦Agent增强实施说明》《恍然梦预设驱动对话实施说明》《云同步功能实现计划》。历史文档中的限制是待协调的设计约束，不能替代本次产品目标。

## 一、优化结论与产品目标

原方案的“投影层 + 知识底座”应保留，但它只能解决资料可读取，不能单独解决剧情、人物与设定一致性。本次升级为：

**全书可读 → 全量建库 → 实体与证据关联 → 按任务组织上下文 → 规划与生成 → 一致性校验 → 提案应用 → 更新作品记忆。**

这里的“AI 学习本书”指持久化作品知识、作者裁决和文风资料，并在每次任务中检索、回放、装配；不指自动训练模型权重，也不能假定模型跨会话永久记得整本书。

### 1.1 用户目标对应的交付能力

| 目标 | 必需能力 | 完成标准 |
|---|---|---|
| 完整读取书内数据 | 全源投影、目录清单、分页全文读取、全量建库与覆盖报告 | 每个有效可读单元都能读取；漏读、过期、失败明确可见 |
| 将各内容联系起来 | 实体对齐、人物出场索引、关系边、事件与时间线、纲文对应、证据链 | 能从人物追到出场正文、所属势力、相关设定与大纲，并回跳原位置 |
| 正文辅助写作与自动生成 | 当前场景状态、章纲目标、约束包、分场景生成、生成后检查 | 草稿携带依据、目标完成情况、冲突和新增实体，不只返回一段文字 |
| 正文符合大纲／正文总结成大纲 | 计划与已发生事实分开；章纲—场景—正文映射；反向归纳流程 | 生成能核对必达节拍；反推大纲能追溯正文且不擅自覆盖原规划 |
| 自行创建人物并捕捉人物卡 | 原创人物流程、正文人物抽取、同名消歧、字段级证据 | 区分“已有正文捕捉”和“原创角色”；可完成建卡与关联关系的整组提案 |
| 自行绘制人物关系图 | 有方向、类型、阶段和来源的关系边；复用现有人物图布局 | 建卡与关系应用后图自动更新；不靠模型生成图片作为关系数据 |
| 人物与世界观不偏离 | 固定属性与动态状态分离；规则约束、时间截断、冲突判定 | 硬冲突不能作为已通过草稿直接应用；不确定项明确提示 |

### 1.2 “完整”的三个层级

1. **数据完整**：所有有效正文、设定、各级大纲、人物字段与小传、关系、灵感、批注都有投影；附件有元信息，图片／PDF 等未转写内容标记为 `unparsed`，不能计为已读。回收站默认排除。
2. **建库完整**：全量阅读任务按清单遍历每个文档与核心分块，分别记录处理状态；完成不能以“生成了一张书卡”代替。逐章全文处理包括长章中间部分。
3. **任务上下文充分**：每次调用在预算内加载当前任务的必要事实与规则；缺项通过工具补读。**全库可访问不等于一次请求塞入全书，也不等于每次任务重读全书。**

本方案不给“模型绝不犯错”的保证；通过明确规则、证据、验证和作者裁决降低偏离，并以固定样本评测衡量实际效果。

## 三、总体架构与数据职责

```text
作品事实源：Dexie 中的正文、人物、设定、大纲、关系、灵感、批注等
  │ 保存／删除／导入／恢复 → 变更信号 + 清单校验
  ▼
A. 可读投影：aidoc / aichunk / aiindex
  │ 全量扫描与增量处理；原文与结构引用
  ▼
B. 作品记忆：aikb / aikbmeta / aisum / aientity / aiedge
  │ 实体对齐、事件状态、规则、计划、灵感、人物关系、纲文映射
  │ 作者裁决 aidecisions；可选 aikbvec；文风 aistyle
  ▼
C. 任务读取：booksource + contextPack + constraintPack + stateAt
  │ 固定作品范围、叙事时间、必要上下文、工具补读
  ▼
D. 创作闭环：读取 → 场景规划 → 生成 → 检查 → 局部修订 → 提案组
  │ 作者应用，或未来明确授权范围内批量应用
  ▼
E. application → work store／保存 → 重新投影与记忆失效
```

### 3.1 事实源与派生资产

- 原始作品表是作者维护内容的事实源；AI 提取结果不能反向成为“作者已经写过”的事实。
- 投影、检索索引、提取缓存、实体与关系索引可重建；保留原有源表字段与存储介质。
- 作者确认的实体归并、规则锁定、纲文映射、纠错和允许偏离记录是持久化裁决，进入 `aidecisions` 并备份；不能在清空知识库时删除。
- AI 草稿只属于本次候选分支；保存／应用后的正文才能进入正式作品记忆。
- 不需要外部 agent 框架、MCP、独立图数据库或向量数据库；内部关系索引用 Dexie 实现。向量是召回增强，不是完整阅读的前提。

### 3.2 自动行为与应用边界

“自行完成”应覆盖自动分析、规划、生成、捕捉人物、生成关系与布局方案、检查和修订，不应在人物草案与关系草案之间反复要求作者手工拼接。默认产出**一个可整体预览和应用的提案组**。

本次方案保留当前提案应用行为。若后续提供连续自动写入，需单独设计一次性任务授权范围：允许章节、允许新建实体类型、是否覆盖、字数／费用／调用上限及中止条件。不能把“自动生成”直接解释为无限制自动覆盖现有正文。本次文档优化不要求额外确认。

## 四、完整可读投影与一致性

### 4.1 源覆盖矩阵

| 来源 | 投影单元与内容 | 默认语义 |
|---|---|---|
| works / volumes / chapters | 作品资料、卷目录、章节全文；保留状态、章节顺序和所属卷 | 作品资料／正文记录 |
| mubu | 每节点文本／富文本、祖先路径及子节点清单 | 作者设定，规则强度待确认 |
| olnodes | 每节点 title + text/html、祖先、refId/refType、rels 有向连线 | 未来规划，不能当已发生剧情 |
| characters | 姓名、别名、role、tags、fields、小传、头像引用 | 作者人物档案 |
| relations | 独立边投影，保留 fromId/toId/label；人物文档附关系摘要 | 作者登记关系 |
| snippets | 标题（如有）、全文、标签、引用关系 | 灵感候选，默认不成为正史 |
| annotations | 摘引、备注、类型、目标章、锚点有效性 | 作者批注；评论不等于剧情事实 |
| legacy outlines/lore/lorecats | 迁移完成时采用新结构；未迁移时提供兼容投影 | 防漏读与重复计数 |
| assets / links | 元信息、实体附件关系；已有转写文本另成文档 | 未解析附件显式列出 |
| revisions / wordlog / 配置 | 版本历史按需读取，统计／配置不作为剧情语料 | 维护数据，不进默认知识包 |

旧、新结构采用迁移状态与映射 ID 选择一份有效来源，不按文本相似简单删掉不同资料。孤儿关系、失效 ref、树循环作为数据质量问题报告，不无限递归。

### 4.2 表与字段

```js
// 下一空闲 Dexie schema 版本：当前 v10，预计 v11。
aidoc:   'rowKey, id, workId, [workId+generation], [workId+generation+sourceType], [workId+generation+orderKey], sourceId'
aichunk: 'rowKey, id, workId, [workId+generation], docId, [generation+docId+idx], hash'
aiindex: 'workId, status, updatedAt'
aikbblock: 'id, workId, docId, cacheKey'
aientity: 'id, workId, [workId+kind], [workId+refType+refId]'
aiedge:  'id, workId, [workId+kind], [workId+fromId], [workId+toId]'
```

这些是索引声明示意，实际字段、复合索引与迁移脚本需按查询验证；当前源表结构不需新增字段。

`id` 是跨批次稳定的逻辑引用，`rowKey = generation + ':' + id` 是物理主键，避免 staging 新批次覆盖正在读取的旧批次；所有查询必须携带已发布 generation。小增量可在当前 generation 内原子更新并递增 workRevision，分页游标和运行时读取缓存都绑定该 revision；版本改变返回 `source-changed`，重新冻结任务，不拼接两版全文。全量新 generation 发布后，旧批次按在途读者／保留策略清理。

**aidoc**：

| 字段 | 含义 |
|---|---|
| id / workId / sourceType / sourceId | 稳定文档身份；例如 `doc:<workId>:chapter:<sourceId>` |
| title / headingPath / parentDocId | 可读标题、层级路径和结构归属；路径是显示信息，不作为主键 |
| orderKey / meta | 按源类型分别排序；章采用 collectExportChapters 口径，树按确定性 DFS；meta 保留引用及标签 |
| plainText / markdown | plainText 为规范化正文与证据坐标系；Markdown 为展示／导出，不混用偏移 |
| paragraphs | `{paragraphId,start,end,sourceAnchor}`；HTML／编辑器映射不可靠时只回跳原章并高亮待定位 |
| sourceHash / textHash / contextHash | 本行版本、规范文本版本、关系／祖先／引用等依赖版本；不能混为一个 hash |
| deps / semanticClass | 依赖源版本；fact/setting/plan/inspiration/comment/metadata |
| projectionVersion / generation | 规范化版本与已发布投影批次 |
| tokenEstimate / updatedAt | 估算文本规模和时间；不宣称估算值等于模型真实 token |

**aichunk**：`id, docId, idx, coreStart, coreEnd, contextStart, paragraphIds, text, hash, chunkerVersion, tokenEstimate`。`text` 包含重叠区，引用只落在核心区或明确指向上一块。

**aiindex**：当前投影批次、源清单哈希、章节布局哈希、各源统计、dirty/missing/failed/unparsed 清单、建库覆盖、待运行任务和最近成功时间。通过“源清单 ⇄ 投影清单”核对增删，不能仅依赖事件。

### 4.3 规范化与分块

1. 提取富文本内容，统一换行并保留段落、标题和列表；章内双链记录结构化目标引用，批注标记保留正文并记录锚点。规范化不能把正文里的 `<` 随意认成 HTML。
2. 新树节点须保留标题与富文本正文，不能只取 `text` 而漏掉 olnodes 的 `title`。人物 fields 用确定性键序序列化。
3. `normalize.js` 文本规则与 DOM 适配分离：现有 `importers.htmlToMd` 使用 DOMParser，不能直接称为 Node 环境无依赖纯函数。
4. 默认目标块约 640 估算 token、重叠最多约 96；预算包含重叠，先预留重叠后聚合核心段。长段按句界、必要时按 Unicode 边界切分，所有字符均被核心区覆盖。
5. 主体保存以下恒等式：`doc.plainText.slice(coreStart, coreEnd) === chunk.text.slice(coreStart - contextStart)`；核心区连续覆盖全文，不丢空白，不靠重新拼句改变原文。
6. 本地 tokenizer 可用时按目标模型计数；否则使用现有估算并留余量，最后由完整请求预算检查兜底。模型／上下文窗口变化时可二次切分读取视图，无需破坏原存储分块。

**稳定身份**：段落经前后版本序列对齐分配 UUID，重复文本用邻接上下文与顺序消歧；块由段落身份集合与分块版本标识。插入一段会使局部重新聚合，不承诺后续块全部不变；未变块可复用，偏移必须刷新。引用同时携带 `docId + textHash + paragraphId + range + quote`；旧版本引用不能直接沿用旧偏移。

段落身份映射随 sourceHash 保留并可在重建时复用；彻底清理投影后，作者裁决先按稳定源 ID、字段、原句及邻接上下文重新定位，再恢复段落绑定。重复句无法唯一匹配时列入待重新绑定，不丢弃裁决，也不把随机重建的 paragraphId 当成原身份。

### 4.4 增量、快照与恢复

- 主窗口为构建协调者，作品级租约和提交校验防跨窗口竞争；面板窗口只发送变更。保存事件在源写成功后广播；直接删除、批量导入、恢复、作品资料修改同样登记变化。
- 3 秒防抖、10 秒最长等待仅为初始配置；dirty 清单持久化，重启可继续。打开作品和 AI 任务前核对源清单，弥补漏事件。
- 正文编辑重建对应文档／局部块；人物关系变化同时刷新独立边和两端人物关系摘要；祖先重命名更新后代路径；ref 目标改名更新引用显示；卷／章重排刷新全局章序与时间派生依赖。
- 不把“结构修改不会重排全书”作为承诺：全局顺序确实受影响时，更新元数据即可，未变正文不必重做模型提取。
- `loadWorkBundle` 当前的并行读取不是跨表一致快照。新增 repository 快照读取，在短只读事务中固定源清单；耗时转换和模型调用在事务外执行，提交前复核输入版本，变化则重排。
- 小增量单事务发布文档及块；全量构建采用分批 staging + generation 指针发布，读者只读取一个完整批次。恢复增加 restoreEpoch，取消在途任务并拒绝迟到提交，不先清空可用投影再慢慢重建。
- 任务开始冻结作品、目标章／选段、来源版本、章节布局与隐私策略。本窗口先等待保存并复核结果；其他窗口未保存编辑不属于已保存快照，显示“基于已保存版本”。保存失败不能被 flushAll 返回成功掩盖。
- 投影缺失可即时规范化**任务必需单元**并标记 provisional，同时排队重建；大量资料缺失、硬规则未知或预算不足时暂停正式生成，返回资料缺口或受限草稿，不能以“任何情况下都继续”牺牲一致性。

## 五、作品知识模型：让内容真正关联

### 5.1 每条知识必须说明“性质、来源、时间”

扩展现有 `aikb`，避免另造一套与知识卡竞争的事实系统。现有 kind 保持兼容，新增 rule/relation/mention/planBeat/alignment 等结构化类型；消费方使用版本适配，不把新 kind 默认塞进旧卡片 UI。

```js
{
  id, workId, kind, schemaVersion,
  semanticClass: 'fact|setting|plan|inspiration|inference|draft',
  assertionStatus: 'extracted|authorConfirmed|rejected|superseded',
  subjectId, predicate, objectId, value,
  sourceRefs: [{ docId, sourceId, sourceHash, textHash, paragraphId,
                 start, end, quote, evidenceStatus }],
  temporal: { chapterId, sceneId, narrativeOrder, storyTime,
              validFrom, validTo, scope: 'global|chapter|scene', temporalStatus },
  perspective: { observerId, visibility: 'author|narrator|character', reliability },
  dependencies, extractorVersion, model, promptHash, updatedAt
}
```

字段可按 kind 选填；`evidenceStatus:'matched'` 只表示原句定位成功，不证明推断一定正确。模型置信度仅作排序提示，不能据此直接把推断提升为事实。否定、传闻、梦境、假设和不可靠叙述需保留语义，不可抽成肯定正史。

| 资料类型 | 如何参与生成 | 如何成为正式知识 |
|---|---|---|
| 正文已呈现事实 | 连贯性与前情依据，按截至章和叙事视角过滤 | 证据校验后作为正文事实；有争议则标待裁决 |
| 作者世界观／势力／能力规则 | 规则与边界；重要约束必读 | 用户确认强度／适用范围；普通设定不可全部自动升为硬规则 |
| 人物档案 | 人物身份、性格、背景的登记依据 | 固定属性与阶段性设定分别解释 |
| 大纲计划 | 生成目标、节拍与未来铺垫 | 明确标记 plan；不能计为已发生事件 |
| 灵感、批注 | 可选素材、作者意见或修改方向 | 采用后绑定目标；不因检索命中就自动成真 |
| AI 推断／原创／未应用草稿 | 本次分支候选和建议 | 单独确认或应用；随后再从保存正文提取 |

**冲突处理不用一个简单权威排序掩盖差异**：作者裁决决定是否追认、修订或特许；已发生事实约束后续连贯性，硬规则约束世界边界，大纲约束创作目标。若正文已违反设定，保留两方证据并形成冲突单，不能静默覆盖任一来源。

### 5.2 实体目录与对齐

`aientity` 是可重建索引：人物、势力、地点、物品、能力／术语以及匿名／未登记实体，统一使用作品内实体 ID。已登记实体引用源 ID；未登记者先用候选 ID，不向 characters/mubu 偷写数据。

对齐顺序：明确双链／refId → 作者确认映射 → 唯一姓名／别名精确匹配 → 带场景、身份、势力的候选消歧。模糊匹配只能给候选。同名人物、称谓“师父”、代词、匿名人物均可能多解，不能用名称 hash 当唯一身份。

- 新人物提取先建候选目录，再提取事件与状态，解决当前事件出现未登记人物即整块失败的问题；事件可引用候选 ID，后续提案中完成归并／建卡。
- 人物捕捉按字段记录证据，未明确的年龄、外貌等留空；与作者人物卡冲突则给 diff，不能为凑齐模板编造字段。
- 势力同样形成实体，记录成员、阵营、资源、地点、制度与规则关联，而不只把势力名字列成关键词。
- 新人物原创需包含叙事职责、动机、背景、性格、能力边界、所属势力与预期关系；创作允许范围由任务参数确定，并检查与已有角色重复。
- 作者合并候选与已有角色后，裁决保存在 `aidecisions`；重建索引重放该映射。不存在证据的原创字段始终显示为原创来源。

### 5.3 关系索引与证据链

`aiedge` 保存规范有向边：`fromId/toId/kind/label/semanticClass/sourceRefs/temporal/status/dependencies`；边类型包括人物关系、出场、势力归属、地点关联、事件参与、因果、伏笔、纲文对应与引用。

- 树父子关系、olnodes.rels、ref、双链和 relations 直接投影；模型抽取的边保留提取状态与证据。
- “甲是乙的师父”用方向和类型表达；“同伴”可对称；“同章出现”只生成共现边，不能自动推成朋友／恋人。
- 关系可随章节改变，保留建立、破裂、伪装和恢复记录。作者登记关系与正文抽取关系分别有来源，冲突可见。
- 关系索引支持邻接查询；默认围绕任务实体扩展一至两跳，限制节点数、token 与边类型。路径遍历不是证明因果，问答仍须读取原证据。
- 正文提取关系确认后写入现有 relations；人物图以现有 characters + relations 自动绘制。历史关系图使用 `stateAt` 派生视图，不把过去关系覆盖当前登记图。

### 5.4 人物状态、时间线与视角知识

人物不能只存“最新一张卡”。分成：

1. **固定／长期约束**：身份背景、能力上限、性格底线、动机等；仍可由明确剧情和作者修改改变。
2. **动态状态**：位置、伤势、资源、能力阶段、持有物、阵营、情绪、目标及关系变化，按事件记录。
3. **知情状态**：谁在什么时候知道哪些信息；作者知道的秘密不能直接变成人物已知。

`stateAt(entityId, cutoff)` 按叙事章／场景顺序回放有效变化，附证据；故事内日期另作时间线，不用章序假定倒叙发生在更晚日期。回忆、预言与梦境保持标记。状态改变需有依据或在当前生成计划中安排过渡事件。

没有时间范围的现有人物小传、设定和关系只标为“当前作者档案／时间待定”。历史任务不得将其中未来信息当历史状态；关键属性无法确定时列为 unresolved。若要严格历史重建，需作者标注适用章节或利用有版本证据的历史资料，单一当前行无法凭空还原所有过去版本。

同样，书卡、卷摘要、主线聚合、人物弧线与伏笔必须带完整依赖和截止范围；第 5 章任务不能使用含第 20 章结局的全书书卡。

### 5.5 规则库与纲文双向对应

**规则模型**从设定提取候选 `{subject, rule, modality, strength, scope, exceptions, sourceRefs}`，涵盖世界观、势力制度、地理交通、能力条件／代价、物品限制、社会关系。明确必需／禁止与一般描述不同；锁定规则通过作者裁决保存。规则语义未结构化时，原文仍须作为相关约束进入上下文。

未确认强度不等于可以忽略：设定原文中的明确禁令／必需条件默认作为必须阅读的约束材料；模型对其范围、例外或冲突解释不确定时按关键 unresolved 处理。全书初建可批量呈现规则候选，不要求作者为每次写作逐条重新确认。

**大纲节拍**从总纲／卷纲／章纲／故事线拆出 `{beatId, purpose, participants, location, prerequisites, mustReach, forbidden, revealPolicy, targetChapter, sourceRefs}`；字段未写明则为未知，不自动编成作者要求。

**纲文映射**按 `beatId ↔ chapterId/sceneId/paragraphId/eventId` 保存 `planned/partial/fulfilled/diverged/deferred`。模型自动对应为候选，作者确认映射优先；正文变化使映射过期。人物弧线、伏笔、势力冲突可沿此映射连接未来规划与已发生事件。

反推大纲仅概括正文已呈现的事件、目的、转折与未解线索，保留来源；缺乏因果依据时标未知。先生成独立“已写内容大纲”提案树，再展示与原计划的差异，用户可选择并列保存、合并或替换。

## 六、全量建库、摘要与增量失效

### 6.1 可恢复全书阅读作业

使用现有 `airuns` 租约、进度与用量管理，增加 `workRevision/readManifest/stage/cursor/checkpoints`。清单固定源版本，逐文档／逐核心块处理；新资料到达不偷偷混入本次清单，完成后再处理增量。

```text
准备：核对源清单与投影 → 建目录／登记实体／结构边（本地）
阅读：依阅读序读取所有源块 → 候选实体／事件／规则／状态／关系提取
对齐：消歧与证据校验 → 合并块重叠记录 → 建实体出场与关系索引
归纳：块摘要 → 章摘要 → 卷／故事线摘要 → 截止范围书卡
审计：检测未读、未解析、失效引用、冲突、孤儿边 → 发布覆盖报告
```

空章、零事件章节也记录“已完整处理，无提取事实”；一次 LLM 输出有条数上限不等于全文事实全覆盖。触及输出上限时拆小／继续枚举或标记 `extractionIncomplete`；摘要完成和事实提取完成分别计数。

`aikbmeta` 扩展到按源文档记录版本、块总数／完成数、摘要／提取状态、失败原因与依赖，不只记录 chapter 成功。UI 示例：正文读完 118/120 章，设定 64/64 节点，人物 23/23，灵感 9/9；过期 2 章，附件未解析 3 项，冲突待裁决 4 项。

全库处理不受普通对话六轮限制：它是按文档有检查点的后台作业；交互问答保留有上限工具循环。不要依赖一次聊天让模型自行遍历数千章。

### 6.2 块缓存与依赖传播

`aikbblock.cacheKey` 至少包括 `coreHash + overlapHash + normalizer/chunker/extractor版本 + promptHash + provider/model标识 + entityRegistryHash + 相关规则版本 + 上游状态/伏笔Hash + 作者裁决版本`。不同供应商的同名模型不能默认共享缓存。

- 文本未变但人物归并、前章伏笔或规则发生变化，依赖提取也要失效；只比对块 hash + model 不足以保证正确。
- 每块返回事实按语义键与证据区间去重；与当前块正文证据核验，禁止“在整章找得到就算当前块提取成功”。重叠事实归属证据起点所在核心区。
- 纯局部事实可复用；状态回放、伏笔及后续聚合沿依赖链重新计算。改前章可能影响后面很多章，不能承诺永远只重提改动块。
- 来源删除后清理其贡献和引用边；同一事实若还有其他有效来源，可保留并更新证据集合。陈旧资产可留作审计，生成默认排除。
- 作者裁决按稳定实体／字段／证据定位标识，不依赖模型措辞或整章正文 hash，否则重提后无法复用纠错。

### 6.3 摘要与书卡

接通 `summarize.js` 的生成能力，同时替换截首尾逻辑：全文块摘要保留事件 ID 和来源，归并为章摘要，再递归聚合卷／故事线／全书。章摘要 150–250 字是展示摘要，不足以替代结构化事件／状态账本。

摘要存储保留 `schemaVersion/sourceRefs/dependencies/cutoff/coverage/generation`；`aisum.entityType` 扩展 chunk/chapter/volume/work。正文变更逐级失效，源 hash 不一致的迟到摘要不得落为有效资产。书卡应有结构化 payload；兼容期若复用 summary 存 JSON，必须显式 contentFormat，普通摘要调用不得直接注入整段 JSON。

书卡含梗概、主线、卷进度、重要人物状态、活跃伏笔、设定冲突和覆盖情况；按任务 cutoff 生成或复用范围匹配缓存。资料不齐时标部分书卡，不用空泛概括掩盖未读内容。

**调用策略**：本地投影／检索可自动运行；付费摘要、提取和向量首次由“建立作品记忆”启动，增量自动更新沿现有开关与每日上限。仅打开作品不得默认静默付费全量处理；自动与手动都须遵守本次作业预算、取消和实际用量结算。

## 七、统一读取、检索与上下文装配

### 7.1 统一 API 与只读工具

```js
readBookManifest(workId, access) // 目录、源覆盖、版本、未解析与失败清单
readDocument({ docId, cursor, limitTokens }, access) // 顺序全文页与 nextCursor
queryBook({ query, sourceTypes, semanticClasses, entityIds, limitTokens }, access)
relatedEntities({ entityId, edgeKinds, depth, limitTokens }, access)
stateAt({ entityIds, cutoff, perspective }, access)
constraintPack({ task, target, budget }, access)
contextPack({ task, target, budget }, access) // markdown/json + sources + coverage
```

`access` 由任务编排器注入：`workId/allowedSourceIds/factCutoff/planScope/perspective/privacy/sourceRevision/restoreEpoch`。工具参数只能缩小范围，不能换作品、放宽 cutoff、关闭隐私或借读取关联实体绕过限制。

新增 `search_book/read_document/get_book_coverage/get_entity_state/get_related_entities/get_outline_alignment` 等只读工具；同时更新 `dialogue.js` 的工具参数 schema、执行校验、UI 来源报告与取消点。大纲计划读取权限与正文事实权限分别控制。

现有工具保持含义：`search_chapters` 仅查正文；`read_chapter` 返回连续章节页；`list_recent_chapters` 使用目录／摘要。不能把它们全部改成跨源 queryBook，以免返回结构和“读完整章”的契约被破坏。

### 7.2 检索策略

先做作品隔离、来源有效性、语义类型、截止范围与隐私过滤，再排序；过滤必须同样作用于向量、摘要、关系扩展、回跳和缓存。

1. 本地中文 2-gram + 英文／数字词、标题、别名、标签与路径的关键词检索；本地倒排索引与分片载入，避免每次全库读取文本。
2. 任务实体、明确 ref、双链与一至两跳关联扩展；前后块补读帮助理解因果。
3. 可选 chunk/card 向量检索与 RRF 融合，按 model/provider/dim/textHash 校验；批量 upsert，修复现有整表反复 replace 的写放大。
4. 去重单位为知识语义键或 `docId + 证据核心区间`，不是 sourceId；同章不同场景必须可同时保留。
5. 未命中先改写关键词或扩展同义／实体，再补读邻域；仍不足返回“缺少依据”。可提供标明 `lowConfidence` 的候选线索，不能把任意 top-k 当答案证据。

向量失败回退本地路线；未配置 embedding 也能完整阅读、建库与执行核心创作流程。

倒排索引属于可重建运行资产：P0 可按作品载入压缩 postings，并设置内存上限；大书采用分片加载和淘汰。重启从 aichunk 重建，不另引入搜索服务；是否需要持久化 postings 由规模验收决定，届时单独增加索引表与版本。

### 7.3 任务上下文与硬约束预算

`contextPack` 至少输出：作品概况与范围、当前正文／选段及衔接段、前情、章纲目标、人物卡与动态／知情状态、世界与势力规则、相关证据、允许采用的灵感、当前草稿分支，以及 `sources/omitted/unresolved/conflicts/coverage/tokenReport`。

总预算先扣系统与作者指令、预设注入、工具 schema、历史、输出预留和误差余量；剩余才是资料预算。`tokens()` 为估算，最终完整请求再检查，不把 640 分块预算当请求必然可容纳的依据。

| 优先级 | 内容 | 超预算行为 |
|---|---|---|
| 必需 | 任务目标、锚点、相关硬规则、关键人物状态、必达／禁止节拍、应用来源版本 | 压缩可读表达但保留规则 ID 与必要原文；仍放不下则拆场景／缩任务或停止 |
| 高 | 前情、因果证据、目标人物卡、相关势力与地点、伏笔 | 按关联度与证据保留，不盲目只取最近章 |
| 可选 | 灵感、文风样例、次要角色、无关目录、远端资料 | 先裁剪并报告遗漏 |

不能固定“相关段落最先丢”，因为关键因果可能正来自相关段落。硬规则是否已包含是门禁；预算不足不能静默截成不完整 JSON 或只保留世界观标题。

当前 `novel-context.js` 保留槽位签名，增加内部结构化包：chapterAnchor/writingReference/workBrief/characterFacts/worldInfoBefore/outlinePlan/previousChapters 对应读取结果；新状态与规则作为受保护块注入 `prepare-dialogue` 和最终 fitBlocks。槽位兼容不意味着旧预设裁剪可以删除必需块。

隐私策略统一在**出站读取视图与最终请求**执行：本地可建规范投影；隐私模式只用已有有效摘要与允许字段，禁止正文、选段、小传、设定／灵感原文、摘引、范文及旧聊天原文出站，也不临时生成原文摘要。导出镜像属单独本地设置。每次检索结果、工具页与缓存都绑定该策略；不得先裁剪 text 后把原文藏进 meta 或 markdown 再发送。

正文、设定、批注、灵感和检索结果始终作为资料块处理；其中“忽略规则”“修改系统指令”等文字不构成执行指令。作品事实／规则与模型行为控制分层，作者本次任务和受信任预设才决定工作流程；资料内容不能开启写入权限或放宽读取范围。

### 7.4 防止事实未来泄漏与剧情提前兑现

- 正文事实、摘要、人物状态及关系按 `factCutoff` 过滤；聚合的每个来源都须合规。
- 规划可按 `planScope` 读取后续大纲来安排铺垫，但带 `revealPolicy`，不可写成已发生事件或让人物提前知道。
- 严格历史任务排除时间不明且可能包含未来状态的资料，显示信息缺口；作者修改的当前全局规则是否适用于过去由裁决确定。
- AI 草稿只在本次 run/branch 内形成临时状态增量；候选 A 的新人、死亡或关系变化不能污染候选 B 和正式知识库。

## 八、面向目标的五条创作流程

### 8.1 正文辅助写作／按大纲自动生成

```text
冻结来源与目标
  → 读取章纲、必要规则、人物状态、场景前情与证据
  → 查缺补读（仍缺关键条件则列明）
  → 生成场景计划：目标／人物／地点时间／冲突／必达节拍／禁区
  → 按场景生成正文，维持本分支临时状态
  → 从生成正文独立抽取实际事件和变化
  → 校验规则、人物状态、知情范围、因果与纲文对应
  → 有限局部修订并重新检查
  → 输出正文草稿 + 检查报告 + 新人物／关系／纲文映射提案
```

- 辅助写作可输出续写、改写、扩写或情节选项；共用资料门面和校验器，不因入口不同绕过规则。
- 整章生成按场景串行，章尾整体检查衔接和节拍；长篇／多章按章保存检查点并支持继续。每步有调用、token、费用、重试与耗时上限，修订默认最多两轮，触顶保留部分结果并说明原因。
- 场景草稿暂存 airuns 中的运行资产或专用 run 数据，不写正式 chapters；下一场景读取该分支草稿与状态增量。
- 严格按纲模式要求所有标记 mustReach 的节拍达到，禁止节拍不得发生；开放模式可提出偏离及配套纲改提案，但不悄悄改变作者大纲。
- 新人物需要时自动产出完整人物卡与关系草案；开放范围外则先提出角色需求，不为绕过约束临时换名字。
- 请求输出超限、取消或格式不完整时 `complete:false`，不允许当完整章节应用。流式 UI 可先展示，校验状态未完成前禁用正式应用。

### 8.2 已有正文总结成大纲

全量读取选定章节 → 抽取事件、人物目标、转折与证据 → 形成场景纲 → 章纲 → 卷纲／主线／人物线，保持来源传递与依赖。中间零事件场景仍记录覆盖，不把缺失事实编成情节。

产出有版本的大纲树及连线候选，与既有计划做 planned/fulfilled/diverged/deferred 对照。“事实大纲”和“未来计划”在界面及语义层区分，可并列、合并或替换。保留原计划快照，防止用总结结果覆盖尚未写到的后续节点。

### 8.3 正文人物捕捉与人物卡更新

遍历正文提及 → 候选实体聚合 → 姓名／称谓消歧 → 字段逐项证据 → 出场章与时间状态 → 现有档案 diff／新人物卡 → 同步关系提案。

角色卡应包含稳定源引用、姓名与别名、身份／势力、性格与动机、外貌／能力（有依据才填）、小传、出场索引、关系和动态状态摘要。作者可整体应用人物卡，也可逐字段选择；未知项、推断项、冲突项明确分开。

### 8.4 原创新人物

明确叙事缺口 → 查询已有角色是否能承担 → 按任务范围设计人物 → 检查姓名／职责重复、势力与能力边界 → 生成档案与关系 → 在当前草稿引入人物 → 检查人物行为和计划一致 → 形成联合提案。

原创字段与正文捕捉字段不能混写成“原文明确记载”；应用后登记人物 ID，并把本组草稿里的候选 ID、关系和大纲引用替换为正式 ID，禁止通过自由名称自动匹配关系端点。

### 8.5 人物关系图自动构建

读取现有登记关系 + 正文有效关系 → 区分方向／类型／适用阶段 → 消歧与冲突检查 → 关系增改提案 → 应用后复用 CharacterGraph 自动布局与回跳证据。

默认保留已有手工节点位置，为新增人物寻找空位；显式“重新排布”才整体布局。图上支持查看关系证据、切换当前／截至章状态；共现边可作为可选分析图层，不写成人物正式关系。势力关系仍由知识索引管理，人物图暂不强塞所有地点／物品实体。

## 九、一致性校验与提案应用

### 9.1 双层校验及结果状态

第一层为确定性检查：作品与 ID 范围、来源版本、完整预算、关系端点、引用区间、规则所需数据、明示数值／枚举／禁止列表、章纲必达节拍映射、人物去重与提交 schema。能机器判断的条件由代码检查。

第二层为语义检查：独立读取草稿提取实际事件，核对世界规则、能力代价、地点时间与因果、人物性格动机、知情边界、伏笔及大纲目的。语义校验可以使用模型，但必须给冲突依据和草稿位置；生成器自报“已遵守”不能作为通过证据。

| 分类 | 例子 | 行为 |
|---|---|---|
| hardConflict | 明示禁止复活却无例外复活；缺必达节拍；来源变更；关系指向不存在人物 | 阻止作为合格提案应用，修订或作者明确裁决后重检 |
| softConflict | 性格行为可能偏离、动机铺垫不足、语气与文风不一致 | 显示依据、建议修订，作者可保留 |
| unresolved | 不知此前人物是否获知秘密；规则生效范围未知；关系歧义 | 不标“通过”；关键项阻止正式应用，非关键项提示 |
| acceptedDeviation | 作者明确本次允许偏离某规则／大纲 | 保存范围与理由，继续核对其余约束 |

输出 `validation:{status,checkedRules,uncheckedRules,beatCoverage,findings,sourceRevision}`。`passed` 仅表示当前已知约束和检查范围内通过，不表示全部语义正确；`needsReview/blocked/incomplete` 不与 passed 混用。质量目标是降低偏离，不把模型自检当质量保证。

### 9.2 联合提案契约

```js
{
  schemaVersion, proposalId, runId, branchId, workId,
  sourceRevision, sourceVersions, layoutHash, restoreEpoch,
  target: { chapterId, selectionAnchor, sourceHash },
  operations: [
    // createCharacter / patchCharacter / addRelation / patchRelation
    // appendChapter / createChapter / patchOutline / bindAlignment
    // 每项有 opId、前置条件、payload、来源、dependsOn 和临时实体引用
  ],
  draft, evidence, originalEntities, validation,
  complete, status, usage
}
```

呈现为一个提案组：正文 diff、新人物卡、关系变化和大纲影响可展开查看。必需依赖一起应用；用户移除某新人后，引用该人的正文／关系必须同步重检或取消，不能留下悬空引用。新增世界设定仍单列为原创建议，不以新人物档案偷偷改变世界规则。

### 9.3 应用、回滚与知识更新

复用现有 application 的来源校验、锁、快照与审计；新增组应用适配器，不宣称当前独立 store 动作和 autosave 已具备跨表原子性。

1. 刷新并验证所有受影响源与规则版本、作品、布局、目标窗口锁和编辑器锚点；检查已应用 opId，防重复。
2. 准备所有 ID、引用映射与修改补丁，保存撤销基线。现有 store 增加批量准备／提交接口，避免每一步立即落盘。
3. 正文编辑器变化保留 editorBefore；在短事务内再次比对全部受影响源版本并提交涉及表与应用审计，不把网络、模型调用或异步编辑器操作放进 Dexie 事务。失败恢复内存与编辑器，并清理本批 autosave 待存补丁，防稍后误落盘。
4. 提交成功同步各 store，广播完整变更，刷新人物图和纲文对应。跨窗口期间持有应用锁；实际来源仍变更则拒绝提交，不能只靠过期预览 hash。
5. 应用审计记录前后版本、实体映射、操作状态和裁决。崩溃后根据已提交审计恢复 UI；多章任务按提案组分批提交，不宣称全书一次原子。
6. 已保存正文重新进入投影与正式提取；生成器自报的 stateDelta 只作临时计划，不能直接当正式正文事实。
7. 撤销按操作组恢复；若后来内容已改变，检测版本并提示冲突，不能用旧快照覆盖作者新修改。新建角色已被其他内容引用时须做影响核对。

生成草稿中的偏移只用于草稿 UI；应用时由 `textHash + quote + paragraph/sourceAnchor` 核对原位置，投影偏移不能直接当 TipTap 文档位置。沿现有双链／批注保护，映射不唯一则返回手动定位。

## 十、备份、磁盘镜像与性能

### 10.1 备份与清理

- 不备份 aidoc/aichunk/aiindex/aikbblock/aientity/aiedge 等可重建投影索引；备份保留 aikb/aisum/aikbmeta、作者裁决、文风、任务与必要已确认提案审计等现有资产。
- 扩展来源字段、确认映射与规则锁定必须经备份—恢复验证。旧备份缺新表应可恢复，恢复后统一按 sourceHash、layoutHash、版本和 restoreEpoch 校验；未能核对的派生资产不参与生成。
- 清空索引、清空付费知识、删除作者裁决三种操作区分；重建不能抹掉人工修正。源作品删除清理该作品全部派生数据。
- 未解析附件的原始 blob 沿原资产备份路径，知识投影不复制大图。新增 OCR／多模态解析是独立可选工作，完成前不得声称已理解图片内容。

### 10.2 可选磁盘镜像

镜像供其他本地工具阅读；工坊内恍然梦的核心能力不依赖镜像。默认关闭，显式选择目录；仅单向导出，不作为源库，也不等同可恢复的云同步快照。

```text
<root>/<workId>/
  CURRENT.json                  # 已完整发布批次及 manifest hash
  generations/<generation>/
    manifest.json               # schema / workRevision / 文件hash / coverage
    book.md
    chapters/<chapterId>.md
    characters/<characterId>.md
    settings.md  outline.md  outline.json
    snippets.md  annotations.md
    knowledge/entities.json  edges.json  cards.json  summaries.json
```

先在新批次目录写全文件与 manifest 并校验，再原子替换 CURRENT 指针；读者固定 generation 读取，避免跨文件新旧混合。保持旧批次供在途读者，按保留策略清理。路径以稳定 ID 命名，书名／章名在文件内容中展示，避免重命名后残留重复章。

主进程限制根目录与数据目录互不嵌套，拒绝绝对 rel、`..`、NUL 和越界路径，核对实际解析路径并防符号链接／junction 逃逸；IPC 只接受启用配置中的根目录。中断批次不发布、根不可用可恢复重试。网页端提供下载打包降级，不假设 Electron IPC 存在。

云同步若使用本产物，须另补完整源数据／资产／作者裁决、版本冲突和恢复协议；知识镜像缺少这些，不能直接充当云同步备份。

### 10.3 性能与运行预算

- 常态任务按目录／索引选资料并分页读块；避免 `readBook` 一次返回所有正文。首次全量建库采用分片任务、主窗口串行调度与进度提示。
- 本地构建可按时间片让出 UI；纯文本处理与 DOM 适配隔离，worker 使用独立可用解析器。每批转换都支持取消与 restoreEpoch 检查。
- 付费队列默认并发 1；显式提高并发需仍遵守供应商限流和每日／作业预算。计算费用前包括重试、实体对齐、摘要和语义检查，展示预计量与实际量。
- 向量按来源版本、模型和维度分批缓存，局部失败不清空有效索引；降级状态可见。
- IndexedDB 容量按真实投影、重叠、摘要、向量与 staging 测量；不能笼统认为“容量充裕”。配额不足可清理可重建资产并暂停新构建，不影响原稿保存。

## 十三、验收方案与量化评测

### 13.1 固定样书

至少包含两卷、20 章、一个超长章、一个零事件章，正文带双链与批注；人物有同名、别名与匿名人物，势力／能力规则有明确禁区；设有人物受伤／地点移动／关系变化／信息揭露、倒叙、不可靠叙述和伏笔回收；含未采用灵感、未来章纲、已确认裁决与未解析附件。

增加规模样本：10 万字、100 万字、1000 章三档。记录首次投影耗时、查询 P50/P95、单章修改耗时、UI 最大阻塞、磁盘体积、token 与用量；性能门槛由目标设备测量后制定，不预先宣称毫秒级或容量无风险。

### 13.2 确定性验收（必须全部通过）

| 类别 | 用例与断言 |
|---|---|
| 完整性 | 五大内容模块及关系／批注计数匹配源清单；附件未解析单列；零事件有完成状态 |
| 正文分块 | 核心区连续精确覆盖全文；重叠计入预算；长章中间事实被处理；空白、Unicode、超长句保留 |
| 引用 | 同句多次出现不靠首次 indexOf 定位；段落增删后身份／偏移刷新；失效引用拒绝回跳误位置 |
| 结构依赖 | 祖先改名、引用目标改名、关系改动、卷序重排、直接删除、灵感／批注更新均触发正确失效 |
| 多窗口与恢复 | 保存失败、来源中途变化、重启、租约竞争、恢复时迟到响应不得提交旧结果 |
| 缓存 | 模型／提示词／实体映射／前章状态／作者裁决变更均会失效；未变独立块可复用 |
| 历史与隐私 | 工具无法越作品／截止章；全书书卡不漏未来；隐私出站 payload 各字段无原文和摘引 |
| 资料预算 | 系统／预设／工具／历史／输出均计入；必需规则不可被预设裁掉；不足时明确阻止 |
| 提案应用 | 新人物／关系／正文引用 ID 完整；跨表失败回滚；重复应用幂等；撤销不覆盖后续修改 |
| 图与大纲 | 新关系图自动补位；共现不成正式关系；正文反推纲保留证据，不覆盖未写后续 |
| 备份与镜像 | 裁决可恢复、旧备份兼容；镜像中断不发布；整批 hash 一致；路径越界与 junction 拒绝 |

拟新增 `tools/project-verify.mjs`、`book-memory-verify.mjs`、`writing-flow-verify.mjs`，可选 `mirror-verify.mjs`；扩展现有知识、预设、跨窗口和提案应用验收。Mock 验证机制与门禁，不能用 Mock 成功证明真实模型文学质量。

### 13.3 真实模型评测（独立于机制验收）

- 用人工标注问题／事实／关系／章纲节拍建立评测集，保留正确证据及应答“不足”的题目。
- 比较当前实现与新流程的来源命中率、回答证据正确率、人物对齐准确率、关系 precision/recall、章纲节拍完成率、硬规则冲突率、人物状态偏离率、冲突检测误报／漏报及每章费用。
- 以“前章受伤不得无过渡恢复”“角色未获知秘密”“禁止能力不得无例外使用”“灵感未采纳不得成真”“未来大纲不能提前兑现”等样本检验核心约束。
- 初始发布门槛：确定性用例全过；标注明确硬约束的验收草稿无未处理冲突、必达节拍全部覆盖；不能确定的语义项显示待审。开放小说场景的质量以多轮人工评测报告为准，不承诺全域 100%。
- 生成结果由作者评价剧情连贯、人物可信、设定合理和可用程度；不同模型单独记录，不能拿一种模型的表现推断所有供应商。
