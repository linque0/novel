# 前端重置：以设计稿为视觉基准，完整对齐原版功能

本说明作为各皮肤前端重置及后续优化的统一实施与验收要求。**设计稿决定界面表现，现有软件决定功能与数据行为。** 在完整保留原版功能的前提下，整体界面应对齐所选皮肤的设计稿；原版排布、组件默认样式和当前实现不能成为降低视觉还原程度的理由。

## 视觉还原范围

- 以对应皮肤的 HTML、CSS 和截图共同作为视觉基准，还原整体构图、主次关系、内容密度、留白及模块布局。
- 逐项对齐模块卡片的轮廓、尺寸、材质、透明度、边框、阴影与层叠关系，以及按钮、输入框、选择器、标签、菜单、工具栏、弹窗和浮层等 UI 样式。
- 对齐界面字体、字号、字重、行高、字距、标题层级、对齐方式和各区域间距；正文编辑区继续尊重已确认的用户字体、字号及西文字体偏好。
- 设计稿中的选中、悬停、焦点和动效应落实为可用状态，并补齐禁用、加载、空内容、无结果和错误状态。
- 在设计稿基准尺寸下逐屏比较位置、比例、卡片外观及排版；在窄窗口和独立窗口中按同一视觉逻辑适配，不能简单缩小整页导致文字或操作难以使用。

## 功能保留与美术同化

**功能对齐指保留原版的完整能力、操作结果与数据语义，不要求沿用原版的外观和排布。** 可以按设计稿重新组织展示结构和操作位置，但必须保持功能可发现、可理解、可到达，不能因追求截图相似而删减功能或以静态展示替代真实操作。

| 实际软件与设计稿的关系 | 实施要求 |
|---|---|
| 两者均有对应功能 | 保留真实业务逻辑，以设计稿还原布局、卡片、控件与交互状态 |
| 两者表现形式不同 | 先核对功能含义、编辑能力及操作流程，再按设计稿的视觉形式承载原能力；不能直接用原版界面替代设计稿布局 |
| 原版有、设计稿未展示 | 保留该功能，并从同皮肤的字体、尺寸、配色、材质、间距和交互语言中推导其样式，融入相应工具栏、表单、详情区、菜单或弹窗 |
| 设计稿有、实际软件尚无业务实现 | 不使用虚构数据或不可用控件冒充已实现功能；需要时另行明确新增功能范围 |
| 真实内容超出示例长度或数量 | 用换行、合理限宽、内部滚动、折叠或响应式布局承载，保证完整内容和全部操作可到达；不能只适配示例数据 |

设计稿未展示的功能也必须完成美术同化，不能遗留原版样式、默认组件样式或临时拼接区域。新补充区域应与同一页面中的同类控件保持一致，包括标签与关系行、模块菜单、编辑表单、导入导出、历史记录、任务入口、搜索、书签、阅读、恍然梦对话及拆窗等实际存在的能力。主要操作应直接呈现；次要操作可以归入有清晰命名和提示的菜单，不能将高频入口隐藏到难以发现的位置。

## 使用体验要求

界面应在实际使用中成熟、顺滑、符合习惯。设计稿是视觉目标，具体交互需完整处理真实数据、状态变化和窗口约束，避免反直觉、不习惯或不方便的操作。

- 点击、双击、键盘、右键和菜单各自职责清楚；继续沿用已确认的常用行为。例如书籍单击或 Enter 直接打开，作品菜单独立触发，不增加先选中再打开的步骤。
- 按钮、菜单和表单具有明确反馈；编辑、删除及关系操作可发现，重要操作不依赖悬停才能找到；保留键盘焦点、快捷键与工具提示。
- 目录、正文、资料、表单和画布各自正确滚动；导航稳定，不遮挡末项或底部操作；弹出菜单和浮层不被裁切，不出现无意义的双重滚动。
- 主从关系通过位置、层级、标签和内容表达清楚，例如章节信息应明确归属对应作品，关系标签应明确连接对应对象。
- 切换视图、返回详情和换肤应保留适用的当前作品、选中对象、编辑内容、选区与滚动位置，不打断写作现场。
- 动效使用短时淡入、阴影和轻微位移；悬停反馈保留原有构图与透视关系，不持续晃动或让点击目标漂移，并尊重减少动画偏好。

## 验收口径

1. **功能完整：** 依据原版组件及实际入口建立操作清单，检查新增、编辑、删除、搜索、切换、定位、关系、保存读回和跨窗口行为；设计稿没画出的功能同样纳入。
2. **视觉一致：** 在同尺寸下逐屏对照设计稿，检查整体比例、模块卡片、全部 UI、字体大小和界面排版；原版额外功能按同一美术语言检查，不能仅以换色认定重置完成。
3. **体验顺畅：** 检查高频操作步数、键盘与焦点、反馈、滚动、菜单裁切及各类窗口适配；覆盖空数据、单条、多条、长标题、长正文、缺图片和搜索无结果。
4. **差异可解释：** 如真实功能或可用性需要调整设计稿的局部表现，应说明对应功能、调整原因及所采用的同化形式，并提供实际截图；不能笼统以“保留原功能”为由沿用原版设计。

## 第三轮原型的功能对照（历史记录）

以下记录说明本目录独立设计原型第三轮的调整范围，并非限制后续皮肤接入的通用要求。当时仅修改设计稿，书架、灵感、设置已通过，正文沿用；大纲、设定、人物按原软件功能核对，原型使用虚构示例数据。后续真实接入以上述视觉、功能及体验要求为准。

| 模块 | 原版功能基准 | 本轮设计安排 |
|---|---|---|
| 大纲 | OutlineSidebar 的模块树与类型筛选；OutlineCenter 的文本/画布双视图；OutlineCanvas 的自由模块、容器、事件、便签、引用卡、文本框、章节锚点、连线、缩放、整理、吸附与密度 | 恢复左目录 + 主工作区；默认自由画布，非强制三幕流程；文本视图保留标题与富文本；节点双击编辑与右键操作采用轻浮层，删除上一轮的常驻事件属性栏 |
| 设定 | MubuTree 的目录/内容与标签搜索/定位；MubuView 的连续节点编辑、折叠、同级/子级、缩进、富文本与关系入口；LoreDetail 的面包屑、关系行、关系图谱、子条目、返回与幕布定位 | 默认幕布编辑，保持内容皆节点；将用户截图认可的「大标题 + 轨道图形 + 正文 + 子条目」移入独立详情；保留关联与图谱，详情不取代编辑器 |
| 人物 | CharacterList 的左人物列表、列表/关系图切换；CharacterCenter 的姓名/角色/别名/头像/标签/自定义字段/小传/人物关系/关联关系；CharacterGraph 的筛选、圆形/网格、缩放、节点双击详情与引用卡入口 | 默认可编辑档案，不再以海报或关系图替代字段；肖像融入档案头；关系图独立切换，编辑操作仍然清晰可达 |

第三轮原型制作时，软件源码仅用于只读核对；本目录的 HTML/CSS/JS 为独立设计评审原型。参照文件的哈希见 software-readonly-baseline.json。该轮原型制作没有改动 Vue 组件、store、数据库、真实数据、应用配置或模型服务；此为当轮记录，不代表后续皮肤没有接入实际软件。

该独立原型可演示切换视图、目录定位、节点展开折叠、节点文本编辑、同级/子级新增、详情与定位往返、人物字段/角色修改、图谱切换、选中与浮层，状态仅保留在预览会话。复杂画布连线/拖拽、导入解析、拆窗、头像文件与 AI 在该原型中为入口展示；真实皮肤接入必须复用实际业务能力，不能继承原型的演示限制。
