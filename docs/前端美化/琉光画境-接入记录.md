### 与 C 版的明确差异

1. **保留完整工具比缩减成原型按钮更优先。** 正文宽屏使用两行工具，窄窗横向滚动；800px 大纲保留全部工具的横向滚动组。没有删掉历史、状态、字号、书签、AI 或故障检测来换取留白。
2. **真实数据决定内容密度。** 无头像使用首字，不套虚构肖像；无关联关系显示空态，不编造图谱。封面、书名、简介、字数、章节数和时间来自作品数据，长标题用稳定行数与完整标题提示。
3. **正文偏好优先。** 设计稿的标题字体用于界面题名，正文仍按用户原有中文、西文和字号设置；不会为了还原截图强行换掉正文。
4. **设置保持真实独立窗口。** 不在设置页伪造作品导航；只呈现原有可用设置，不添加尚无业务实现的行高、缩进或动画开关。减少动画遵循操作系统偏好。
5. **用户已保存的侧栏宽度不被改写。** 窄窗口仅在表现层约束宽度，800px 正文缩小目录与辅助栏，原来的收起／展开操作可用；灵感列表与人物表单在独立窄窗改为单列。
6. 大纲操作说明继续保留，帮助发现原有右键关系链接；人物小传提示降为次级文字。没有为了减字删除业务含义。多余的原型虚构数据与控制项未搬入。

### 交互与动效

- 玻璃卡片仅在短时阴影、边框、背景上响应；拼贴倾斜放在伪元素，命中区域不旋转、不遮挡相邻点击。
- 书架没有持续漂浮或晃动；画布节点没有逐卡片 backdrop-filter。
- 可见选中边框、键盘焦点、禁用状态、加载反馈及保存状态；菜单通过真实按钮可发现。
- 尊重 `prefers-reduced-motion`；没有为换肤改变现有编辑器和业务状态的挂载身份。

## 验证结果与方法

使用本机独立 Electron `glaze-skin-verify`（CDP 9224）与 `gravity-skin-verify`（9223），连接真实 Vite 组件、Pinia、Dexie、自动保存与原生窗口；脚本先校验数据目录且拒绝重定向到其他目录。仅创建／清理隔离测试作品，不操作日常用户配置。

- 受影响的 **24 个 Vue 组件编译、两份皮肤 CSS 解析**通过；注册／回退与图谱投影逆变换单元检查通过。
- 画布模型 **48 项**、引力大纲 **27 条通过输出**、引力工作台 **59 条通过输出**通过。
- 琉光书架和工作台集成检查各连续运行 **3 轮**，全部退出码 0。精确输出和轮次计数以 logs/results.json 为准。
- 覆盖真实新建编辑保存／重新读回、软删除、菜单隔离、六封面、默认卷、重载持久化、强制皮肤保存失败、跨窗口偏好同步、三种原版配色、正文中西文字体／字号与选区保持。
- 覆盖全部画布对象、用户尺寸与颜色保持、目录可见菜单重命名保存、人物图真实鼠标拖拽保存与端口连线、三皮肤往返坐标保持、人物小传保存重开、灵感真实转换、设定深层内容、详情层搜索／书签导航。
- 覆盖五种内容拆窗与关闭恢复、独立设置四页、独立灵感和 AI 拆窗后的可见对话入口；最小 800×500 大纲画布不低于 260px 高，目录保留独立滚动空间。
- 截图包含十个 1440×900 主状态、1080×680、800×500 独立模块、1000×700 设置、空书架、无结果、编辑表单、阅读与三栏并开等；对照页提供 100%／200% 查看。

测试期间修正了一个**脚本夹具时序问题**：直接将 shelf.works 清空会被待处理的跨窗口刷新补回，现改为在隔离库中临时写入可恢复的真实空状态，验证后还原。没有为此修改生产数据逻辑。CDP 在隐藏启动时会给出可见性预警；脚本使用焦点模拟与截图前置窗口，并等待实际 DOM／存储状态，本轮截图可正常取得并已实际查看。

最终复验还定位并修正了**关闭窗口时 CDP 返回值的竞态**：直接在求值中调用 native.panelCloseSelf 可能先销毁渲染进程，导致测试等待一条再也收不到的返回。脚本现在先确认关闭请求已排队，再通过调试目标列表等待实际窗口消失，接着检查主窗口锁恢复；没有改动原生关闭实现。调查记录保留在 logs/investigation，正式结果只统计修正后完整运行的轮次。关键区域的三张 200% 局部保存在 details/。

### 独立复核

- **代码复核一轮＋修复后复核**：发现独立灵感入口可能填入不可见对话的 P2 问题，已通过现有 AI 组件弹层修复；后续只读复核确认解决，未发现新的阻断问题。
- **视觉复核一轮＋修正后复核**：按存量界面润色协议、不打分。修正文本大纲标题层级、人物关系区过低、宽屏工具横滚、800px 大纲工具占高、设置口号过大及长封面字墙。复核未发现静态画面中的阻断遮挡；最终目录密度由主执行者再次截图与尺寸断言确认。
- 静态评审不替代交互测试。没有调用付费模型做生成质量评测，也没有运行生产构建或打包安装程序；外部模型服务的响应和所有文件格式导入导出的完整业务回归不属于这次皮肤验收结论。原服务与处理路径未改。

## 复现

```powershell

node node_modules/vite/bin/vite.js --host 127.0.0.1 --port 5173 --strictPort
```

```powershell
Start-Process -FilePath '.\node_modules\electron\dist\electron.exe' -ArgumentList @('.', '--dev', '--profile=glaze-skin-verify', '--remote-debugging-port=9224', '--disable-backgrounding-occluded-windows') -WorkingDirectory (Get-Location).Path -WindowStyle Hidden
```

### 正文：章节状态 / 字数 / 历史 归入顶栏右端（v1.1.2 第五轮）

按你的图做的搬移：这三件原先在章题下面自成一行（`.gravity-manuscript-status`，编辑皮肤专有），现在挪到正文顶栏（`.editor-toolbar`）的右端——`☆ 发送给恍然梦` 之后、`margin-left:auto` 推到本行末尾，窄窗跟着工具条换行或横向滚动。

- **组件**：`EditorToolbar.vue` 在工具条末尾加了一个 `bar-end` 具名插槽（插槽为空时不影响原版）；`EditorPane.vue` 把这三件从 `.gravity-manuscript-head` 里取出、通过该插槽注入，只在 `ui.isStudioSkin`（编辑皮肤）下渲染，原版仍是自己的 `.editor-head` 一行（章题上方，紧贴工具条）。状态存的是键（`draft/done/revise`）、顶栏显示中文标签，绑定沿用同一个 `work.setChapterStatus`，没有新增逻辑。
- **样式**：两个编辑皮肤各加一条 `.editor-bar-status{display:flex;align-items:center;gap:9px;margin-left:auto;padding-left:10px;opacity:.85}`；删掉随之作废的 `.gravity-manuscript-status` 规则。药丸（状态下拉）、浅底小片（字数）、纯文字（历史）沿用既有样式，就是图里那三件。
- **顺带**：章题下方少一行后，手稿区变成「卷 · 章号 → 章题 → 正文」，与设计稿的正文页一致。
- **验收**：`glaze-workbench-verify` 扩到 **72/72**，新增四条——三件都在顶栏里且是工具条最后一个子元素、字数片随真实字数、把章节状态改成 `done` 时顶栏标签跟着变「完成」（证明绑定是活的）、原版皮肤**没有** `.editor-bar-status` 且自己的 `.editor-head` 里仍有状态/字数/历史。另外三处「最小窗宽下工具条与批注/助手共存」的断言改为量 `.editor-toolbar` 的边界（原来量 `.editor-head button`，搬移后会变成空集合空过），`gravity-refinement-verify`（引力那批复查自己的套件）同步改同一处。
