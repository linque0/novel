## 三、代码结构

1. **registry**：`src/skins/registry.js` 增加 `{ id:'crimson', label:'赤月戏', description, surfaces, palette:{ background:'#171c1b', accent:'#cfb06b', text:'#f0e7d5' } }`；`isStudioSkin()` 改为 `value === 'gravity' || value === 'glaze' || value === 'crimson'`——这样手稿头、`⋯` 菜单、人物档案头、chip 标签、快记浮层等 studio 结构自动生效。
2. **样式**：新增 `src/styles/skins/crimson.css` 与 `crimson-workbench.css`，在 `App.vue` 与另两套一起 import；所有规则一律 `body[data-skin='crimson']` 作用域，新类名用 `crimson-*` 前缀，**不复用 `glaze-*`/`gravity-*` 前缀的样式规则**（共享的 studio 结构类如 `gravity-manuscript-head` 直接沿用，另记一次可选清理：统一改名 `studio-*`，不在本次范围）。
3. **素材**：`src/assets/skins/crimson/*.webp` + `SOURCES.md`（来源、SHA-256、提示词索引——沿用 `金屏夜梅` 的 `素材记录.md`）；布景用 **CSS `background-image`** 引用，浏览器只在皮肤激活时下载，不进入首屏包；封面与人物肖像继续由应用生成，不引入设计稿的参考图。
4. **皮肤选择器**：`SkinPicker.vue` 从 `SKINS` 自动列出，补一枚色卡（深底/旧金/纸白）。

## 四、动画实现（本次必须落地）

设计稿里只有 4 个入场关键帧 + 一组微交互过渡，全部是合成器友好属性（transform / opacity / clip-path / SVG stroke），可以直接搬进应用，不需要改结构。

### 4.1 入场关键帧（照抄设计稿的时长与缓动）

| 关键帧 | 定义 | 挂载对象 | 时长 / 缓动 / 延迟 |
|---|---|---|---|
| `scenery-reveal` | opacity .35→1；scale 1.025→1 | 布景层 `.scene-art`（书架/各模块的背景） | 1.2s `cubic-bezier(.2,.65,.2,1)` |
| `folio-reveal` | opacity .25→1；translate 0 14px→0；blur 2px→0 | 纸面/稿本/画布/肖像册/剧目册（`.paper`、`.c-book`、`.plot-canvas`、`.portrait-folio`、`.module-directory`） | 主线 .6s `cubic-bezier(.2,.7,.2,1)` 延迟 .06s；侧栏 .7s 延迟 .13s；画布节点 .45s 延迟 .1s；书架选书 .25s |
| `ink-reveal` | opacity .3→1；`clip-path: inset(0 100% 0 0)`→`inset(0)` | 模块大标题、竖题名 | .6s ease-out |
| `thread-reveal` | `stroke-dashoffset: 600 → 0` | 关系图连线、设定详情图谱 | .8s ease-out 延迟 .15s |

**触发方式（关键设计）**：沿用设计稿的 `body.playing` 语义——由「进入作品 / 切换模块 / 换肤 / 重播」写入 `document.body.dataset.stagePlay = '1'`（或加 `.is-playing` 类），动画以 CSS `animation` 播放，`animationend` 后移除标记；**不使用 JS 逐帧循环**。这样：

- 隐藏窗口 / 后台窗口不会因为 rAF 被节流而“动画卡住不结束”（此前书架翻动验收踩过这个坑）；
- 用户再次进入同一模块时重播一次，符合设计稿「每次进入都有一次开场」的约定；
- 换肤到赤月戏时播放一次**短促版**（.4s，只做 `folio-reveal` + `scenery-reveal` 的 opacity 段），避免换肤像“闪一下”。

**动效红线（继承现有皮肤约定）**

- 只动 transform / opacity / clip-path / filter / stroke-dashoffset；不改文档流、不改命中区、不遮断点击；
- 悬停不持续晃动、不旋转、不闪烁；按钮按下位移固定 1px；
- `prefers-reduced-motion: reduce` 时 `animation:none`、`transition:none`，直接显示终态（设计稿已有同名规则，照搬）；
- 模态、下拉、浮层的进出场使用 120–180ms 淡入 + 4px 位移，不抢主演出。

### 4.2 微交互

| 场景 | 实现 |
|---|---|
| 按钮 / 链接 | `transition: background-color .18s, color .18s, box-shadow .18s, translate .18s`；`:active { translate: 0 1px }` |
| 卡片 / 书目 | `hover { translate: 0 -3px ~ -5px }` + 双层投影（设计稿原值：大纲节点 −4px、人物卡 −3px、灵感纸 −5px），`transition: translate .2s, box-shadow .2s` |
| 书架选书 | 选中作品的书封与剧目信息用 `folio-reveal .25s ease-out` 重绘一次；不改变点击目标位置 |
| 大纲 / 图谱节点 | 新节点出现用 `folio-reveal .45s`；拖线端口显隐用 120ms opacity（端口命中区已有既有实现） |
| 视图切换 | 画布 ↔ 文本、列表 ↔ 图谱：纸面 `.3s` cross-fade（同一容器内，不用路由级转场） |
| 底栏状态 | 「已保存」圆点仅在状态变化时 400ms 呼吸一次，不循环 |

## 六、验收脚本与证据

- 新增 `tools/crimson-shelf-verify.mjs` / `tools/crimson-workbench-verify.mjs`，隔离 profile `crimson-skin-verify`、端口 **9225**（脚本内接受 `dev` 与 `crimson-skin-verify`，拒绝默认配置）。
- **动画断言**（每条都是可复核的数值，不看截图猜）：
  - 进入作品后 `document.getAnimations()` 中存在 `scenery-reveal`，`effect.getTiming()` 的 duration=1200ms、easing 含 `.2,.65,.2,1`；
  - `folio-reveal` 在纸面上存在且带 60ms 延迟；`ink-reveal` 作用于标题；关系图连线 `stroke-dashoffset` 从 600 收敛到 0；
  - `static-view` / `prefers-reduced-motion: reduce` 下 `animationName === 'none'` 且元素直接是终态（opacity=1、无位移）；
  - 换肤到赤月戏再切回，编辑器实例、正文、选区不丢（沿用现有 hot-switch 断言）；
  - 帧采样：过渡期间帧间隔中位/p95、无 longtask。
- 结构与功能断言沿用现有模式：控件齐套对照（原版 vs 赤月戏，按已批准的皮肤差异排除）、最小窗宽、DOM 契约、皮肤隔离（`data-skin` 下规则不外溢）。
- 证据目录 `docs/前端美化/赤月戏-验收/`：10 组「设计稿 ↔ 真实版」对照 + 1080×680 / 800×500 边界 + 入场录屏；`tools/crimson-evidence.mjs` 生成 `index.html` 与 `manifest.json`。
- 回归：把两个新套件接入 `glaze-regression.mjs`（连同 skin-unit / component-compile / canvas-model / gravity / glaze 各套），并复跑 `skin-verify`、`shelf-flip-verify`，确认新增皮肤不影响既有两套。

## 七、风险与取舍

| 风险 | 处理 |
|---|---|
| 素材 +3.8MB | 用 CSS 背景引用、按需下载；不 import 成 JS 资源；首屏包不变 |
| 深色皮肤 + 大字号正文 | 用用户的 19/20px 字号与偏好字体实测对比度；纸面用 `--paper` 实底，布景只露出边缘 |
| 设计稿的竖向书名 vs 真实长标题 | 竖排只用于短题名（≤4 字），超长自动转横排 + `line-clamp`，与琉光封面同一策略 |
| 手稿/档案等 studio 结构类名带 `gravity-` 前缀 | 本轮沿用，另记一次可选统一改名（`studio-*`），避免一次改动横跨两套已验收皮肤 |
| 设计稿演示交互（toast、modal、预览） | 一律用应用的真实组件承载，不复制原型的假交互 |
| 布景遮挡操作 | 沿用设计稿的 `.scene-shade` 顶部遮罩与纸面层级；每个模块验收时检查「亮部不压在正文/输入框后方」 |

## 八、不做的事

- 不改业务逻辑、数据结构、数据库与 AI 链路；不替换现有 `original` / `gravity` / `glaze`。
- 不引入设计稿的参考封面与人物肖像（继续用应用的生成式封面与首字字牌）。
- 不在本轮做类名统一重构、不做移动端适配（沿用 1080×680 与 800×500 两个窗口边界）。
