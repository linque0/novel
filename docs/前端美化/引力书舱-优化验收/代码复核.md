# 引力书舱本轮优化代码复核

复核日期：2026-10-16。仅审查本轮指定的 8 个组件/样式文件差异及新增的两个 refinement 验收脚本；未运行 UI、未操作用户数据库，未重新验收原版和 glaze。以下结论来自源码及当前安装的 Naive UI 实现。

## 发现

### [P2] 已打开的 AI 停靠栏拆窗后，灵感讨论入口仍消失

- 位置：`src/components/Workbench.vue:332`。
- 复现：在主窗口打开恍然梦停靠栏，再通过「拆出独立窗口 → 恍然梦」拆窗，然后进入灵感页。
- 原因：`onSplit`（132–133 行）只打开面板，不清除 `ui.aiDrawerOpen`。此时 `aiPopped=true`、`ui.aiDrawerOpen=true`；停靠栏因 `!aiPopped` 隐藏（342 行），但灵感卡仍因 `!ui.aiDrawerOpen` 为假而隐藏。虽然本轮去掉了 `!aiPopped`，这个常见操作顺序依然不能进入 `InspirationPrompt.discuss()` 已有的独立讨论分支。
- 影响：AI 已拆窗时，主窗口没有灵感指令卡和「带入恍然梦」入口。应按实际停靠栏是否显示决定是否隐藏卡片，并覆盖「先打开停靠栏，再拆窗」的状态。

### [P3] 新快记浮层不响应 Escape，提交或收起后也没有恢复触发按钮焦点

- 位置：`src/components/SnippetList.vue:37–40`。
- 复现：用键盘打开「记录灵感」，输入草稿后按 Escape；浮层仍打开。或 Ctrl+Enter 提交，随后继续按 Tab，焦点不会从「记录灵感」按钮继续。
- 原因：仅处理 Ctrl+Enter；未处理 Escape，也未在关闭后恢复触发按钮焦点。当前 Naive UI 的 `Popover.mjs:282–288` 仅在 `internalTrapFocus` 为真时处理 Escape，而此处未开启该选项。`addQuick()` 关闭时会销毁仍持有焦点的输入框。
- 影响：从常驻输入框改为浮层后，键盘关闭及连续记录的焦点路径不完整。草稿 `quick` 本身保留在组件中，普通收起/再次打开不会清空。

### [P3] 验收准备阶段中途异常时，已创建的测试作品无法清理

- 位置：`tools/gravity-refinement-verify.mjs:48`、`tools/gravity-shelf-refinement-verify.mjs:45`（对应清理：247 行、154 行）。
- 复现：让准备 fixture 的异步代码在首个 `createWork` 成功后、整段页面求值返回前抛异常，例如临时使后续一次 `addChapter` / 第二次 `createWork` 拒绝。
- 原因：外层 `id` / `fixtureIds` 只在整个页面端准备流程成功返回后赋值；失败时分别保持 `undefined` / `[]`。虽然后者在页面内维护 `__skinFixtures`，finally 没有读取它。
- 影响：finally 跳过已经创建作品的删除，后续验收 profile 留下污染；本轮脚本不完全满足异常路径清理。隔离目录校验在 fixture 写入前执行，未发现其会写入正常用户 profile 的路径。
