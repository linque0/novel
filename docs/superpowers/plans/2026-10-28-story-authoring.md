# 恍然梦故事主写界面实施

依据：[AI 故事主写与共同创作方案](../../恍然梦AI工作台/共同创作模式重设计方案-20261028.md)。用户于 2026-10-28 要求直接开始实施，并强调游戏般的故事生成体验、视觉与流畅交互。

## 本批交付

1. 一个故事现场：空白开场、无指导继续、原位编辑、最近一轮换版；章节与可选侧栏，不以阶段导航为默认入口。
2. 当前章节共同工作稿持久化，两个模式共享同一个编辑器；正式正文独立确认，复用提案应用、撤销和记忆登记。
3. 规划/独立审阅/选择意见修稿在故事现场发生；有界自动推进最多六轮，可停止，保留中断材料。
4. 夜航叙事视觉：深墨背景、暖白阅读正文、金色主操作；压下反馈、侧栏滑入、首次出场，支持减少动画和窄窗口。

## 接口与步骤

- Task 1：`story-core.js` 明确工作稿、轮次、变体、审稿版本和推进边界；先写 Node 确定性测试并见红。
- Task 2：`story-repo.js` + Pinia story store，用 airuns 的有类型 schemaVersion 记录持久化工作稿与执行状态，CAS 防覆盖、共享工作流租约、防止迟到结果。任务新增 `chapter.story`，冻结当前稿和控制策略；独立审稿不带生成历史。
- Task 3：共用 TipTap 工作稿编辑器在工坊与恍然梦之间 Teleport；保留原正式编辑器与旧高级工作台。原位手改进入下一轮上下文。作者确认时创建新的明确快照，仍经原应用服务。
- Task 4：故事现场组件/样式，开场模板、持续指导、继续/停止、换版、自动推进、就地审阅和高级入口。所有展示按钮均接通实际动作。
- Task 5：隔离应用验证空白开场、三轮自主继续、手改接力、换版/失效、重启、错误与确认；1440/1080 截图自查 + 独立评审。真实模型质量单独记录。

## 边界与实施裁定

- 本批复用 airuns，避免在已存在大量未提交代码上同时引入五张新表；story-document 内聚当前章节轮次与版本，独立于聊天消息，纳入现有备份。后续数据量测量再拆分索引。
- 沿用现有独立窗口整书编辑锁，本批不同时修改跨窗口锁协议；在此保护下实现同窗口两模式的同稿联动。不同窗口竞争仍由租约/CAS 拒绝，不能宣称按文档多窗口并行已完成。
- 章节顺序推进要求前章已确认；本批不新增未确认多章依赖链，旧高级批量工作流保留。
- 复用现有主题分支与未提交代码；不重置、不提交用户的混合修改、不创建丢失这些修改的新 checkout。
- Hindsight 工具目录查询为空，无法调用其检索/initiative API；这是工具可用性限制，未据记忆声称任何行为已实现。

## Review Focus

空白请求真正生成正文；中文组合输入不误发；取消/断网/切书/编辑中并发不追加迟到结果；改稿后审稿/变体绑定不串稿；旧正文及知识库在确认前不变；保存失败保留本地编辑；重新加载不自动发请求；高级旧功能入口可达。
