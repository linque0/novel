# 恍然梦独立工作台实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** 按产品方向方案落实导演式 AI 工作台，与手写界面共用作品、编辑会话与候选，提供可用的章级创作、审修、批量、资料与运行界面。

**Architecture:** 主窗口/完整 agent 面板复用一个 StudioWorkspace 壳层，两种视图共享一份 TipTap EditorPane，通过 Teleport 移动 DOM 而不销毁编辑状态。AI 工作台围绕现有 creative-workflow 和 airuns 产物组织。完整 AI 窗口可在持久租约保护下直接执行；独立窗口暂采用全作品正文编辑锁，防止多窗口覆盖。

**Tech Stack:** Electron、Vue、Pinia、TipTap、Dexie、现有 OIcon/Naive UI，无新依赖。

**Spec:** `docs/恍然梦AI工作台/产品方向与界面方案-20261027.md` 第 1–13 节；用户本轮明确要求开始实施，采用推荐 A 方向。

## Global Constraints

- 同一正式正文、已有候选/审稿与来源保护不变。候选编辑不写正式正文或知识库。
- 主窗口内切换保留同一个编辑器实例、选区和撤销；专用窗口与其他正文窗口互斥编辑。
- 原有手写、方向卡和聊天入口保留；AI 主力界面独立导航，不能只嵌入旧创作弹窗。
- 模型输出、证据定位、作者采纳、记忆更新分别展示；真实模型质量与固定响应验证分别报告。
- 章节批量至多 10 章；来源变化拒绝旧产物写回；保存失败可见并保留输入。
- 本轮交付独立工作台基础与已有闭环；从念头自动建立全书、富文本逐块合并和应用退出后的后台服务属于方案后续阶段，入口不能假装已实现。
- Hindsight 工具发现仍未提供可调用方法；无法 capture initiative，依据当前源码与已批准文档实施。

## Review Focus

- 未采纳候选转手写仍处于候选编辑状态，不能暗中覆盖正式正文。
- 切章、切工作台、双击启动、已有运行中切换作品和关窗均不重复派发/写入。
- 专用窗口不能绕开正文/设定锁；全模块锁与已有实体窗口相互冲突。
- 主窗口停在书架，完整 AI 窗口仍可执行/采纳；记忆任务使用保存后的正文。
- 1280×800 与 1440×900 下正文、审稿和导航可读；键盘可操作、低动态模式可用。
