## 1. 背景与痛点

大纲画布（自由模块画布）在长篇创作里承担「总纲—卷纲—章纲—事件链」的全部结构表达。随着作品推进出现三个真实痛点：

1. **画布失控**：总纲一层铺 6 个事件、每卷再铺一张画布状结构，全部摊在同一张画布上 → 想看全貌只能缩放到 30–40%，字完全看不清；想看细节又要反复平移缩放。
2. **关系不可见**：模块间的因果/伏笔连线只存在于画布上；侧栏（模块条目列表）只有 `↔n` 计数徽标，想知道「这个事件被谁铺垫、又推动了什么」必须回画布顺线找。
3. **跳转打断流**：画布上单击引用卡 / 双链卫星词会**立即跳走**（切模块、切视图），用户只是想确认"这张卡指向什么"；回来还要重新定位画布视角。

## 2. 现状盘点（代码事实，2026-09-24）

### 2.1 数据模型（零迁移红利）
`olnodes` 表（经 `work` store 读写）：每节点含
- `kind`: `event | note | cite | textbox | container | volume | anchor`（volume/anchor 为章节/卷锚点模块）
- `parentId`: 归组父指针——容器「拖入即归组」的载体，**嵌套方案直接复用此字段，无需任何 schema 变更**
- `rels[]`: 连线内嵌在节点上（`{ toId, label, kind, arrows, style, fromSide, toSide, … }`）
- `fold`: 折叠标记；`canvasX/Y`、`w/h`（容器盒为派生值，非存储值）

### 2.2 容器现状（`OutlineCanvas.vue` + `outline/canvas-model.js`）
- 拖入即归组：`reparentAfterDrop()`——落点中心命中容器盒改 `parentId`，拖出回根级；**L424 明确排除容器自身**（`n.kind !== 'container'` 才走归组）→ **容器目前不能嵌套容器**（本方案要打开的闸门）
- 循环防护已有：落点判定排除被拖子树（`olnodeDescendants`）
- 折叠：`fold` → `hiddenIds` 沿父链**递归隐藏全部后代**（L45–58）→ 递归收纳已天然成立，零改动
- 容器盒：`containerRect()` 由**可见子模块包围盒**派生（含标题栏/内边距常量）；无可见子项（空/折叠）回落基准 `280×120` → **折叠态是一张空盒，不紧凑也不带信息**
- 容器拖动连带后代（L397）→ 折叠态整组搬运的机制已存在
- **派生盒单遍无序构建**（`containerBoxes` computed 直接遍历 visNodes）→ 嵌套后父盒会拿到子容器的**基准尺寸**而非派生盒——嵌套需改拓扑序（见 §3.4）
- 无框选/多选（无 marquee 代码）

### 2.3 侧栏现状（`OutlineSidebar.vue`）
- 按 `parentId` 缩进树渲染，容器折叠与画布同步（`olnodeToggleFold`）
- 条目徽标：章节字数 / 容器项数 / **`↔n` 连线计数**（`relsCount` = 出边数 + 全库扫入边数——数据已备，只缺呈现）
- 断线检测：烂尾（无后继）/ 缺铺垫（无来源）筛选 chip
- 搜索/类型筛选时折叠容器内的匹配项平铺补充呈现

### 2.4 引用卡与双链现状
- 画布引用卡（`kind:'cite'`）：**单击 → `citeJump()` → `jumpTo()` 立即跳转**（人物跳关系图，其余跳对应模块）
- 画布双链卫星词（`om-sat`）：**单击 → `jumpTo()` 立即跳转**；`data-dl-target` 属性齐备
- 编辑器正文双链：hover 跟随预览；左键=光标；右键菜单「跳转」
- **`DLinkPopover.vue`（全局浮窗，Workbench/PanelHost 均挂载）已具备**：`previewFor()` 六类目标富预览（kindLabel/标题/meta/摘要 body 900 字截断）、跟随鼠标、**拖拽钉住**（v1.0.21 动画体系）、**「跳转 ↗」按钮**、Esc/点外关闭
- 结论：**「浮窗详情」的 80% 基建已在**，缺的是详情态增强（统计行、拆窗按钮、宽体）与三处点击改线

## 3. 方案一 · 嵌套收纳（容器 2.0）

### 3.1 设计原则
1. **自由度优先**：不引入「总纲/卷纲/章纲」强制类型，不做父子类型绑定。层级只是**空间收纳**，不是结构约束——容器想装什么装什么，标题想叫什么叫什么。需要标签感时用现有 `olTypes` 自定义类型体系贴「总纲/卷纲/章纲」自由标签（零新机制）。
2. **复用而非新建**：嵌套单元就是现有容器（拖入即归组语义自然延伸），折叠收纳复用 `fold` 递归隐藏。**零 schema 变更、零迁移**。
3. **空间收益来自折叠**：展开态照旧自由摊开；折叠态把整组结构收成一张摘要卡——画布的可读尺度由「展开的东西」决定。

### 3.2 交互规格
| 交互 | 规格 |
|---|---|
| 容器嵌套 | 拖容器 A 落入容器 B 盒内 → A.parentId=B；循环防护沿用（不可落入自身子树）；**深度软上限 4 层**，超出 toast 提示「层级过深，建议折叠上层」（不硬禁） |
| 折叠收纳 | 容器标题栏 caret 折叠 → 子代递归隐藏（已有），容器盒收敛为**摘要卡**（见下） |
| 摘要卡 | 高度 ≈44px 单行卡：标题 + 徽标串「`n 模块` · 类型构成 chips（事件×3 便签×1 引用×2）· `↔m` · 断线 `k`（有则红点）」；宽度按标题自适应（180–320px） |
| 整组搬运 | 摘要卡拖动 = 容器拖动（连带后代坐标，机制已有），收纳后的结构可整组搬进父容器/画布任意处 |
| 展开恢复 | 点 caret 或双击摘要卡展开；展开后子代原坐标重现（fold 只影响可见性不影响几何——现状语义保留） |
| 框选归组 | **新增 marquee 框选**（左键空白拖框，虚线框，命中模块高亮）+ 右键「归入新容器」→ 新容器盒自动按选区包围盒生成（`containerRect` 逆用）→ 一键把散装模块收成结构；`Ctrl+G` 归组 / `Ctrl+Shift+G` 解组（移出直属父容器）快捷键 |
| 层级感知 | 嵌套 ≥2 层时容器标题栏 hover 出面包屑 tooltip（`总纲 / 卷一 · 雾都钟楼 / 章三`）；侧栏缩进已天然呈现深度 |
| 跨容器连线 | 折叠后对外连线随子代隐藏（edges 只算 visNodes——现状语义）；摘要卡徽标显示 `外部连线 n`（可选增强），展开自动恢复 |

### 3.3 落文件改动点
| 文件 | 改动 |
|---|---|
| `OutlineCanvas.vue` L424 | 去掉 `n.kind !== 'container'` 排除——容器可拖入容器；`reparentAfterDrop` 的 `boxOf` 已排除被拖子树，循环安全 |
| `OutlineCanvas.vue` `containerBoxes` | 派生盒改**拓扑序**：按容器深度降序（最内层先算），子容器取派生盒而非基准尺寸——`sizeOf` 对 `kind==='container'` 先查 boxes map |
| `OutlineCanvas.vue` | 新增 marquee 框选（mousedown 空白 → 橡皮筋矩形 → 命中集合）；右键菜单「归入新容器 / 解组」 |
| `outline/canvas-model.js` `containerRect` | 折叠态返回紧凑摘要卡尺寸（`w: clamp(180, 标题宽, 320), h: 44`）；摘要卡徽标数据从 children 聚合（新增纯函数 `containerStats(n, kids)`） |
| `outline/canvas-model.js` | 摘要卡渲染模板（canvas-model 仅出数据，模板在 OutlineCanvas 节点渲染分支加 `n.fold` 分支） |
| `OutlineCenter.vue`（文本视图） | 验证幕布树对嵌套容器的渲染（理论已按树递归，需回归） |

### 3.4 边界与风险
- **几何派生顺序**是最大的实现坑：现单遍 map 构建，嵌套后必须拓扑序，否则父盒用子容器基准尺寸导致盒错位（v10 设计稿在 SVG 渲染上踩过同类坑，Edge 截图可抓出）
- 摘要卡与子代坐标无关性：折叠期间子模块坐标冻结，展开即回原位——用户在折叠态看不到内部，需在摘要卡徽标里给足信息（模块数/断线）防"黑箱焦虑"
- 深层嵌套 + 全展开的包围盒计算是 O(N) 纯几何，百模块规模无性能问题
- 拆窗面板窗口内同一画布组件，行为自动一致

## 4. 方案二 · 侧栏连线关系呈现

### 4.1 设计原则
1. 结构树保持主视图（父子从属）；**关系是第二维度**，按需展开、不混入树序、不加常驻噪音。
2. 双向联动：画布选节点 → 侧栏定位并自动展开其关联；侧栏点关联 → 画布定位对端（复用 `canvasFocusTick` + `flashIds` 闪烁机制）。

### 4.2 交互规格
| 交互 | 规格 |
|---|---|
| 关联展开 | 条目的 `↔n` 徽标变为**可点**：展开该模块的关联子列表（挂在条目正下方，缩进一级，视觉上从属于条目而非树层级）；再点收起 |
| 关联行内容 | 方向箭头（`→` 出边 / `←` 入边 / `↔` 双向）+ 关系类型色点（因果红/伏笔紫/冲突橙/关联蓝——沿用画布四类着色）+ 连线标签（有则显）+ **对端模块名** + 对端所属容器短前缀（`卷一/`） |
| 关联行点击 | 画布定位对端模块（选中 + 居中 + flash 闪烁）；hover 关联行 = 画布对应连线高亮（复用 flashIds） |
| 选中联动 | 画布点选节点 → 侧栏 scrollIntoView 定位该条目并**自动展开其关联**（设置项「选中自动展开关联」，默认开） |
| 筛选增强 | 新增快筛 chip：「有连线」「**孤岛**」（0 连线模块——与断线检测互补：断线=有边但烂尾/缺铺垫，孤岛=完全无边） |
| 折叠态 | 容器折叠不影响关联展开（容器自身 rels 照常可查） |

### 4.3 落文件改动点
| 文件 | 改动 |
|---|---|
| `OutlineSidebar.vue` | `relsCount` 升级为 `relsOf(n)`：返回 `[{ dir: 'out'|'in'|'both', rel, peer }]`（出边来自 `n.rels`，入边扫描 `liveOlnodes`——入边全库扫已有先例，可加 Map 缓存）；徽标 `↔n` 加 `@click.stop` 展开态 |
| `OutlineSidebar.vue` | 条目渲染加关联子列表分支（expandedIds Set）；对端容器前缀复用 `labelOf`/parentId 回溯 |
| `OutlineSidebar.vue` | 筛选 chips 加「有连线 / 孤岛」；`match()` 扩展 |
| `work` store | `selOlnodeId` 变化时侧栏 scrollIntoView（canvasFocusTick 反向联动已有基础） |

### 4.4 边界
- 入边全库扫描 O(N×rels)：百模块规模可忽略；如需可建 `incomingIndex` computed Map 缓存（liveOlnodes 变化时重建）
- 关联列表与树折叠正交：父容器折叠时被隐藏的条目其关联不可达——搜索/筛选的平铺补充机制（现状）同样适用于关联定位（点关联行时若对端被折叠隐藏，先展开其父链再定位）

## 5. 方案三 · 引用卡 / 双链 → 浮窗详情

### 5.1 设计原则
1. **三个入口统一语义**：hover = 轻预览（跟随鼠标，现状保留）；**单击 = 详情浮窗**（钉住态，原位换内容，不打断流）；**跳转只在浮窗内显式发生**（「前往 ↗」）。
2. **复用 DLinkPopover** 而非新建组件：`previewFor` 富预览、拖拽钉住、进出场动画、「跳转 ↗」全部现成——本次只做「详情模式」增强 + 三处点击改线。
3. 引用卡的隐喻回归「资料卡」：点击是查阅，不是传送。

### 5.2 交互规格
| 入口 | 现状 | 改为 |
|---|---|---|
| 画布引用卡单击 | 立即跳转 | **选中卡片 + 在其旁打开详情浮窗（钉住态）**；再点其他卡浮窗原位换内容（钉住态已有此语义）；Esc / × / 点画布空白关闭 |
| 画布引用卡双击 | （无） | **直接跳转**——保留熟练用户的快捷路径 |
| 画布卫星词（om-sat）单击 | 立即跳转 | 同引用卡：钉住详情浮窗；双击直跳 |
| 侧栏引用条目单击 | 定位画布 | 不变（浮窗随画布选中态出现） |
| 编辑器双链 | hover 预览；右键菜单跳转 | 不变（可选增强：左键也开详情浮窗，列为选项不默认） |

**详情浮窗（详情模式）规格**（对比现 hover 预览）：
- 头部：kindLabel chip（正文/设定/人物/灵感/大纲）+ 目标标题 + meta 行（卷名 · 字数 / 角色与别名 / 设定路径）
- 正文：`previewFor` 摘要（现状 900 字截断保留）
- **统计行**（新增）：章节 → 状态/最近更新；人物 → 关系数/出场章数（现有统计可查则显）；设定 → 子节点数
- **操作区**（新增）：「前往 ↗」主按钮（现 onJump）+「拆窗打开」（仅 chapter/lore/character/snippet 目标——调 `window.native.panelOpen`，大纲画布引用卡场景尤其顺手：边看引用边写）+ × 关闭
- 视觉：详情模式宽体（hover 预览 ~300px → 详情 ~360px），沿用 dl-pop 动画/钉住/把手体系

### 5.3 落文件改动点
| 文件 | 改动 |
|---|---|
| `DLinkPopover.vue` | 新增 `showDetail(view, target, x, y)`（钉住态打开 + detail class 宽体）；模板加统计行 + 「拆窗打开」按钮；`onJump` 保留 |
| `OutlineCanvas.vue` | `citeJump(n)` 改 `openCiteDetail(n)`（选中 + 定位浮窗锚点 + showDetail）；节点 `@dblclick` 加直跳；`om-sat` 的 `@click` 同改、`@dblclick` 直跳 |
| `OutlineCanvas.vue` | 引用卡点击后仍需 `work.selOlnodeId` 选中（现状 click.stop 不选中——顺带补上，侧栏联动才能亮） |
| `doublelinks.js` | `detailStatsFor(target)`（可选）：聚合统计行数据（全部从 store 现查，无新查询） |

### 5.4 边界
- 钉住浮窗与画布拖拽事件冲突：dl-pop 根节点已有 `@mousedown.stop` + `@contextmenu.prevent`，画布命中判定（`e.target.closest('.dl-pop')`）已在 DLinkPopover 全局 mousemove 处理——画布侧需确认 mousemove 节流不影响浮窗跟随（现状 hover 已共存，钉住态不跟随鼠标更安全）
- 引用卡目标被删除：`previewFor` 返回 null → 走 `missingView`（已有「目标不存在」文案）——详情浮窗同样适用，且不再发生"点了直接跳到空气"
- 面板窗口（拆窗）内的画布：PanelHost 已挂 DLinkPopover，行为一致

## 6. 分期、验收与顺序

| 期 | 内容 | 主要落点 | 验收口径 |
|---|---|---|---|
| **M1 浮窗详情** | 方案三全部 | DLinkPopover + OutlineCanvas 改线 | 新增 `outline-detail-verify.mjs`：引用卡单击不跳转且浮窗出现（钉住态含「前往」）、浮窗跳转后落点正确、双击直跳保留、卫星词同验；回归 olcanvas-verify 全量 |
| **M2 侧栏关系** | 方案二全部 | OutlineSidebar | 关联展开内容与画布连线一致（抽样对端/方向/标签）、点击定位对端并 flash、孤岛筛选数字正确、选中联动滚动；回归 shelf-verify |
| **M3 嵌套收纳** | 方案一全部 | OutlineCanvas + canvas-model | 容器套容器（含循环拒绝）、嵌套派生盒正确（父盒包住子容器派生盒——截图断言）、递归折叠、摘要卡尺寸与徽标、整组搬运、框选归组/解组、快捷键；回归 olcanvas-verify + 文本视图回归 |

顺序建议 **M1 → M3 → M2** 或按用户当下痛点排序；三期互相独立，M2/M1 可并行。

## 7. 不做的事（Non-goals）
- 不引入强制的「总纲/卷纲/章纲」类型系统或父子类型校验（层级是空间约定，不是数据约束）
- 不做自动布局/一键整理（嵌套收纳是手动空间管理，自动布局另立议题）
- 不改 olnodes schema、不做数据迁移（parentId/fold/rels 全复用）
- 不改变现有画布手势语义（拖线/塑形/吸附/端口全部不动）

## 8. 与既有设计的关系
- v8/v9/v10 封面美术线与本方案无交集（那是书架封面层）
- 折叠摘要卡的徽标视觉沿用画布徽标体系（`om-chip`/类型色点）；详情浮窗视觉是 DLinkPopover 的宽体变体，不新起样式体系
- 骨架模板（三幕式/章级清单）可在 M3 后增加「卷纲模板」（容器 + 预置事件链）作为可选增强，不列入本方案承诺范围
