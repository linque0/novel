# 恍然梦创作工作流实施说明

日期：2026-10-27。基于当前功能分支增量实现，未升版本、未自动提交。

## 使用入口

- 恍然梦输入框“功能”→“整章与连续创作 · 审稿修稿”。
- 已生成的完整正文候选→“独立审稿与修稿”。
- “功能”→“阶段模型与写作 Skill”：配置规划、起草、审稿、修稿、记忆；折叠区内可分类作品设定规则。

## 已实现行为

### 检索与必要材料

任务类型、目标、相关人物、章纲和写作位置共同决定检索查询与权重。普通创作任务接通可选向量检索，隐私模式不发起向量请求；失败和缺索引均记录降级原因。材料装配返回纳入/省略记录、来源版本和预算；必要条目整体保留或停止请求。

作者确认的全局规则与未分类旧规则保守保留；局部规则按章节、纲点和关键词匹配。规则分类只修改设定条目的 `rulePolicy`，保存遵守其他窗口的设定模块锁。

**预算取舍：**有总 Token 上限的工作流批次目前使用关键词检索，并明确提示停用额外向量请求；普通单项任务仍可使用向量。这样避免向量调用绕过批次预算。模型实际用量与估算用量分开，已发送但被取消的请求按保守额度计账。

### 审稿、修稿、复核

新增 `chapter.plan/draft/review/revise/recheck`。审稿独立请求，不携带生成者的自评作为审稿结论。问题有稳定 ID、严重程度、当前稿内定位与来源引文；重复引文需要坐标，无法定位保留待核实。前章候选的引用标记为 `candidate`，只表示本分支内衔接。

作者勾选、修改意见或填写补充要求后生成完整修稿候选，保留旧稿并可对照。每轮最多一次修稿、一次定向复核；重新全文审稿可开启新一轮。修改稿件会使旧审稿/复核失效。模型判断、证据定位、作者采纳分别展示；定位成功不代表语义正确。

### 章级与批量候选

选择 1–10 个既有章节，按作品章节顺序执行；章节必须有关联的未来章纲。场景计划可编辑目标、视角、冲突、转折、结束状态及字数。当前总目标超过 3500 字时按场景分步生成，否则直接写章。

前章候选、场景计划、作品版本均绑定检查点。后章只消费生成时冻结的前驱；修改、拒绝或采纳其他前驱分支后禁止旧下游应用。未解决的严重问题不会被“部分修好”的复核掩盖。自动修稿只针对已有定位证据的问题，仍不自动采纳。

运行记录和阶段输出存入 `airuns`。阶段输出完成、业务候选尚未登记的崩溃窗口可复用已经保存的完整产物，不重复请求模型。迟到回调、失效租约、恢复备份前的旧运行不能重新发布。主窗口执行，独立窗口可发起/暂停并接收状态；自身广播带来源标识避免覆盖本地执行状态。

正式应用继续使用原有来源版本、窗口锁、审计和撤销服务。采纳前需要在正文编辑器打开对应章节；替换原有正文或带保护标记的选段继续受既有规则约束。

### 章节记忆队列

成功采纳后，最终正文与记忆任务在同一 Dexie 事务保存。来源按实际保存正文计算，任务去重；主窗口在空闲时处理本轮新登记任务。失败保留正文，重试复用成功提取/摘要缓存。

每次模型调用前及发布事务中核验全书来源和任务租约，阻止编辑、撤销、同内容备份恢复后的迟到发布。重新启动与恢复备份不自动恢复请求。结构化人物、正式关系及作者设定仍需另行确认。

### 阶段配置与 Skill

各阶段默认继承当前供应商、模型和预设；运行开始冻结模型、非凭据配置指纹、预设与 Skill 文本。端点或模型参数变化后停止旧运行，密钥不进入任务记录。记忆提取也消费所选预设及文本 Skill，但保留固定的证据/JSON 合同。

本地 Skill 仅接受一个 `SKILL.md` 与本地 `.md/.txt` 引用，最多 64 个文件、24000 字符。先预览再安装，不执行脚本、Hook、工具或子代理，不从远程下载引用。

## 验证与证据

- 新增纯协议与集成工具：`creative-workflow-unit-verify`、`review-cycle-unit-verify`、`stage-config-unit-verify`、`stage-budget-unit-verify`、`creative-retrieval-unit-verify`、`memory-queue-unit-verify`、`rule-scope-unit-verify`。
- Electron 隔离 profile `booksource-verify` 下的 `creative-workflow-verify.mjs`：10/10，通过真实界面、Pinia、IndexedDB 和本地固定响应传输；覆盖重试、崩溃窗口恢复、作者修改失效、采纳/记忆原子登记、恢复防护及独立窗口完成通知。这不是模型质量证明。
- 保留原位置续写、任务协议、书库、预设、应用竞争与关系知识的定向回归。
- `creative-benchmark.mjs`：1000 章、1157890 字符、1012 文档、3012 块；本机一轮投影 377ms、重复投影 651ms，四类检索 4.7–24ms。Node 24.14 / Windows x64 / Ryzen 9700X。输入与重复投影哈希一致。仅为合成 CPU/进程内存样本，未测数据库落盘、完整 UI 或真实模型性能。
- `creative-quality-verify.mjs --real` 提供固定的时间、人物知情、能力代价、误报控制与伏笔样本，不会回退到固定响应。当前隔离配置 `ready=false`，真实模型评测未完成，报告见 `tools/_creative-quality-results.json`。

## 已知限制与后续验收

真实 DeepSeek 创作质量、长章合并质量、多章长距离一致性，以及旧版真实输出对照仍未验证；不能给出提升比例。需要在隔离 profile 的应用设置中配置要求的模型后运行真实评测。

场景计划是候选资料，不会自动改写正式大纲。修稿对照当前展示修订前/后全文，尚无逐段采纳。文风等建议由作者判断，系统不保证自动发现全部叙事问题。

索引仍沿用全书规范化与差异计算；本轮只建立可重复基准，没有放宽全书来源保护，也没有宣称解决大书数据库或界面性能。
