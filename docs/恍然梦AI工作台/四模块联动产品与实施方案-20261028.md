# 恍然梦 × 工坊四模块：故事资料联动方案

日期：2026-10-28。状态：**待用户审阅的设计提案，未实施**。这一轮只新增方案与核查记录，不修改产品代码、不运行模型请求。

延续 [AI 主写与共同创作方案](共同创作模式重设计方案-20261028.md) 和 [故事现场首批实现](story-ui-20261028/实施记录.md)：AI 可以从空白创作，作者随时编辑；正文、规划讨论与审阅保持在同一个故事现场。

## 1. 产品方向：在故事里使用工坊的全部创作资料

**让作者在恍然梦里就能查看、选择、编辑和生成设定、大纲、角色、灵感，同时继续使用工坊的同一份资料。**

默认依旧是一键开始或继续故事，不增加“填完四个模块才能写”的准备流程。已有资料自动辅助创作；缺少资料时 AI 可以先构思故事，其新人物、设定和走向作为待确认创意保留。正式资料修改仍由作者决定。

联动有三个具体结果：

1. **读得到**：工坊保存的资料进入合法检索和本轮材料选择，作者能看清是否真的纳入。
2. **改得动**：在故事现场原位修改正式资料，工坊展示同一实体；AI 建议先成为差异提案。
3. **接得上**：资料变化进入下一次创作，返回故事时保留稿件、章节、选区、阅读位置和未发送指导。

三条路径的取舍：

| 路径 | 能解决什么 | 代价与判断 |
| --- | --- | --- |
| 增加四个跳转按钮 | 快速打开工坊对应页面 | 仍需离开故事，缺少选材、回写和返回闭环，只作为辅助入口 |
| 在恍然梦复制四套管理页和资料库 | 独立界面内能完成操作 | 容易出现两份资料、两套保存规则，不推荐 |
| **共享原始资料，加故事资料侧栏和公共操作服务** | 同一实体、原位使用、双向修改、连续创作 | 需要补公共操作与上下文绑定，推荐作为实施方向 |

推荐默认“自动匹配相关设定/角色与当前章纲，作者可固定引用”；灵感自动推荐，作者选用后才加入创作。这里是本方案建议，并非已经获得用户批准的新增行为。

## 2. 当前代码提供了什么，缺口在哪里

| 已核验的现状 | 对本轮实施的意义 |
| --- | --- |
| `StoryScene.vue` 已有剧情、审阅、叙事配置和记录侧栏；`toWorkshop()` 主要切到正文章节 | 新增资料侧栏并接通准确目标，不能只复用“工坊编辑”按钮 |
| 正式资料分别位于 `mubu`、`olnodes`、`characters/relations`、`snippets`，同作品加载到 `work` store | 共享这些实体，不建恍然梦专用副本 |
| `projectBook` 已将设定、计划、已写内容纲、灵感区分为不同语义性质 | 沿用其性质与来源，不能把灵感和计划当已经发生的事实 |
| 上下文已有章纲、角色、设定、状态、知识召回；工具能跨模块只读检索 | 后台已有部分读取联动，需要增加明确选材和实际使用报告，不能声称从零接检索 |
| 故事任务以工作稿为本章参照，旧正式本章正文采用零位置边界 | 资料面板与新工具继续服从这个边界，不绕道带回已删章末 |
| 新增人物和灵感的 `work` 动作会同时改变 `work.tab`、选中项 | 抽出保存与导航的区别，侧栏新增不能把作者带离正文 |
| 专用任务分别限制提交工具；`chapter.story` 只允许提交正文 | 在故事里设计资料须路由到相应专用任务，不扩大正文任务的写库权限 |
| 已有来源广播、提案应用、版本保护、撤销和窗口锁 | 复用这些机制，但需补资料保存后的广播覆盖、脏表单冲突和返回位置 |
| `syncConfig()` 会整体重设故事配置；在途运行严格校验全书来源版本 | 资料引用另放独立字段；保存时机需要调度，不能随意塞进 config 或放宽校验 |

固定源码版本、符号位置与哈希见 [本次核查记录](material-linkage-20261028/source-ledger.json)。这是当前工作区的静态研究，不是运行验证。

## 3. 用户看到的界面

保留深墨、暖金和连续正文。正文是主角，资料在需要时出现；不恢复六页阶段导航。

```text
雾港来信 / 第一章       当前工作稿           [故事资料] [工坊编辑]
┌ 章节 ────┬─────────────────────────┬ 故事资料 ───────────┐
│ 01 第一章 │ 第一章                   │ 设定 大纲 角色 灵感 │
│ 02 第二章 │                         │ 本章相关 / 全部资料 │
│           │ 连续故事正文，可直接编辑 │                    │
│           │                         │ 林昭 · 角色库      │
│           │                         │ 身份、目标、声线   │
│           │                         │ [固定引用] [编辑]  │
│           │                         │ [安排出场]         │
├───────────┴─────────────────────────┴────────────────────┤
│ 本章方向：渡口试探  ·  固定资料 3 项  ·  [查看本轮使用依据]│
│ [可选指导，留空让 AI 继续……]                 [继续故事] │
│ 写故事 / 聊剧情    叙事偏好    [自动推进] [确认本章]      │
└────────────────────────────────────────────────────────┘
```

线框中的名称与数量只说明布局，不是实际召回结果或新界面截图。

交互约定：

- “故事资料”侧栏有 **设定 / 大纲 / 角色 / 灵感** 四个入口，记住上次查看类别；可筛“本章相关”或搜索全部资料。每类都有空状态，可直接让 AI 起草对应资料，仍可先写故事。
- 当前“故事设定”（题材、视角、控制方式、持续要求）改名为 **叙事偏好**，避免与工坊世界设定混淆。
- 正文中选中文字可执行“查相关资料”“另存为灵感”“据此起草人物/设定”。不把名字自动当实体，不自动把提取建议写入正式档案。
- 资料卡显示来源与状态，例如“角色库”“作者设定”“未来计划”“本分支草案”；不只用颜色区分。
- “固定引用”表示每轮提供资料，不表示人物必须出场；“安排出场”才生成明确的创作要求。两者不能混用一个开关。
- 顶部只显示简短材料摘要；详情才显示版本、选用原因、遗漏原因、预算和本轮变更。
- 1440 桌面可并排正文与资料；1080 桌面侧栏覆盖阅读区域，但止于底部创作区上方，继续/停止始终可操作。资料、剧情、审阅共用一个辅助区，避免叠三层面板。
- 小编辑在侧栏完成；完整设定树、大纲画布和关系图由“在工坊展开”打开。返回恢复原章、工作稿、选区、阅读位置与资料卡，不复制内容。

本轮提供结构方案，未制作或渲染新前端，不给线框打视觉分。

## 4. 四个模块分别怎样进入创作

| 模块 | 默认读取 | 作者在恍然梦中操作 | AI 产物与回写 |
| --- | --- | --- | --- |
| **设定** | 作者全局规则始终保留；按当前地点、人物、冲突匹配局部条目 | 查找条目、固定引用、编辑原文/标签；必要时展开原设定集 | AI 提出新增/修订草案，展示原文与变化，作者确认后保存到同一 `mubu` 条目或选定父节点 |
| **大纲** | 默认跟随当前章的关联章纲与必要祖先主线 | 查看本章目标、调整临时走向、选择其他纲点；需要时进入完整画布 | “按此继续”仅作本章指导；“保存到大纲”另行确认，绑定 `refId` 与节点身份；已写内容纲不冒充未来计划 |
| **角色** | 匹配角色档案、有效关系和合法历史状态；可固定核心角色 | 查看身份/目标/声线、编辑档案、安排出场、查关系；重名时选择实体 | AI 新人物先留分支草案；作者确认后入人物库。临时受伤、知情和情绪进入阶段状态，不覆盖长期身份 |
| **灵感** | 展示相关灵感推荐；未选灵感不作为正文创作意图自动落实 | “用于下一幕”“持续用于本章”“另存灵感”；可把讨论或正文选段收藏 | 明确选用后以“创作意图”进入请求，仍不当事实；AI 推荐新灵感先留候选，作者保存后进入同一 `snippets` 库 |

补充规则：

- 浏览哪个设定集是界面状态，不等于 AI 只能读那个设定集。资料范围由明确策略控制；固定树节点也不代表无限展开所有后代。
- 角色面板分“作者档案 / 截至当前的正式状态 / 本分支暂定变化”。作者可以查看资料，不代表故事角色已经知道资料中的秘密。
- 大纲偏离以提醒和作者选择处理；与正式事实冲突不能通过“临时改走向”静默改掉设定。
- “用于下一幕”默认在下一轮**完整成功提交工作稿**时消费；取消、截断或失败不消费。换一版复用同轮冻结的意图，不能重复消费或换成别的灵感。使用记录附着创作轮次，不在全局灵感条目上打不可逆“已用”标记。
- 从未确认工作稿收藏的灵感要保留工作稿来源；收藏不等于正文证据。跨分支自动推荐仍受来源范围限制，不能借灵感把未采纳剧情变成正式历史。

## 5. 两条完整使用流程

### 已有作品：拿工坊资料继续写

1. 打开当前故事：匹配关联章纲、角色和局部设定，作者无需逐项重选。
2. 资料栏显示“林昭、守灯人、铜符代价规则、渡口试探章纲”。自动匹配项与作者固定项可分辨。
3. 作者选中一条“旧船票显出航线”的灵感，点“用于下一幕”，继续故事。
4. 本轮明确使用代价规则与选择的灵感，正文仍是未确认工作稿；材料报告保存实际纳入的版本。
5. 作者原位改角色的说话习惯并保存，下一轮使用新版本；当前故事与上一轮证据保留。
6. 章末在同处审阅。确认正文后走原记忆队列；角色档案修改与正文确认分别有自己的审计，不重复保存。

### 新故事：AI 写故事，也逐步建设资料

1. 没有设定、角色表、章纲也能让 AI 开场。
2. 故事里出现新角色和规则时，系统提供可编辑的资料草案，例如“守灯人苏叶”“铜符的使用代价”；默认只属于当前分支。
3. 下一轮可读取本分支的草案以保持一致，必须标明“尚未收入工坊”；拒绝或换分支不会污染正式库。
4. 作者可逐项或批量预览后确认，保存到工坊角色库、设定树或大纲；人物和关联条目需要一致地处理临时 ID。
5. 作者尚未确认的草案可继续服务当前故事，但不更新正式阶段记忆。正式资料的确认与章节正文的确认保持清楚。

草案建议首版由“从当前稿整理资料”主动触发；后续才增加轻量自动建议。不在每轮自动弹出一堆建档窗口，也不承诺每个新名字都能被可靠识别。

## 6. 资料选用和预算机制

推荐新增统一 `StoryMaterialResolver`，服务开场、续写、剧情讨论、规划、独立审稿和资料设计；各任务有不同的选材策略，不共享写稿自评历史。

每次请求按以下顺序处理：

1. **确定范围**：作品、章节、工作稿修订、分支、当前位置、资料选择版本、隐私策略。
2. **解析引用**：以实体 ID 读取最新合法版本，不能只拿卡片名称或列表缓存；改名不丢引用，删除后不偷偷继续用旧内容。
3. **组织材料**：作者全局规则、当前工作稿/本轮指导、当前章纲、作者固定资料、相关自动资料；选用灵感单独标“创作意图”。当前生效规则不能因从卡片上取消固定而被忽略。
4. **核查性质**：正式事实、作者档案、未来计划、灵感和分支草案分别标注。未来计划可用于目标安排，未来正式正文不因“固定”而越过章节边界。
5. **计算完整预算**：必要输入、工具定义、输出预留与剩余运行预算一起计入。固定资料默认必要；放不下明确列出冲突，让作者取消固定或缩小任务。自动资料整项省略并说明原因。
6. **冻结本轮选择**：记录资料 ID、哈希、语义性质、选用原因、必要/可选、纳入/省略和预算结果。生成后“本轮已用”从这份记录读取，不把推荐列表冒充实际发送。

自动匹配通过姓名/别名、关联章纲、地点与冲突、当前工作稿和关系图邻接组合查询；相关性评分只是召回依据，不是事实有效性的证明。大书按索引分页召回，不每次把四类所有正文塞进提示词。

未选择灵感的正文任务不得通过 `search_book` 等只读工具绕过选用规则；推荐灵感的查询与正文生成的材料访问需有不同策略。所有入口仍受 `booksource` 的来源、历史、隐私及当前位置校验。

## 7. 数据与公共接口方向

沿用 Electron / Vue / Pinia / TipTap / Dexie，不新增服务端、外部向量库或另一套人物/设定数据库。

### 7.1 存储关系

| 数据 | 拟定位置 | 要点 |
| --- | --- | --- |
| 正式四类资料 | 现有 `mubu`、`olnodes`、`characters/relations`、`snippets` | 工坊与恍然梦读取相同实体 |
| 作品级引用偏好 | `airuns` 的 `story-material-policy` 有类型记录 | 固定核心资料、适用范围；版本与恢复身份受保护，不混入聊天 |
| 当前章资料绑定 | `story-document.contextBindings` 与独立 `contextRevision` | 章纲、固定/排除项、待用灵感；不塞进会整体覆盖的 `config` |
| 分支资料草案 | `airuns` 的 `story-material-draft` 有类型记录 | 作品、文档、分支与源稿修订绑定；与正式资料分开 |
| 本轮使用记录 | `story-run.materialSnapshot` | 明确源版本与预算；轮次/变体引用对应快照 |
| 待保存表单 | 有类型的资料编辑草稿记录 | 保留原始来源版本与作者输入；脏表单不被广播覆盖 |

以上为拟定接口，不表示已有这些字段。新增记录必须纳入现有备份恢复与 incarnation 防迟到规则；界面搜索词、折叠状态不应改变书内事实版本。

分支草案首版绑定当前文档、源修订及对应轮次/变体，并保存摘引快照与坐标。继续创作、手改或换版后，先校验所属变体和具体依据；不能仅凭文档 ID 相同继续当作有效资料。不匹配的派生条目标为待核对，保留作者编辑，不静默迁入新方向。本批不同时新增任意历史轮分支界面。

审稿绑定除稿件版本外还需要记录资料选择版本和来源版本；事实性资料变化后，修稿入口必须拒绝使用旧意见，不能仅改一个“过期”标签而继续执行。

### 7.2 操作接口

拟新增公共服务：

```text
listStoryMaterials(context, kind, query)       查相关/全部资料
bindStoryMaterial(context, ref, intent)       固定参考、关联章纲或选用灵感
resolveStoryMaterials(context, task, budget)  编译本轮合法材料与选择记录
saveMaterialEdit(ref, baseVersion, patch)     作者手改正式条目
proposeStoryMaterial(context, kind, request)  路由到对应专用 AI 任务
applyMaterialProposal(proposal, decisions)   作者确认差异并复用原应用审计
openWorkshopResource(ref, returnContext)     精确打开原对象并恢复故事位置
```

`ref` 使用明确的 `workId + sourceType + sourceId`，冻结使用时另记源哈希。UI 内部 `lore/outline/characters/snippets` 与规范层 `mubu/olnode/character/snippet` 的命名统一转换，避免别名引起越界或选错对象。

当前 `work` 保存动作和导航副作用应拆开或提供明确无导航模式；不以先改 tab 再悄悄改回来模拟原位操作。正式编辑和 AI 差异确认共用保存门禁，按来源性质决定是否需要作者确认，不让模型直接调用任意 CRUD。

正文任务仍只提交正文。角色设计、设定设计、大纲规划、灵感生成分别路由到已有专用任务；首版明确按钮触发，后续才扩展自然语言意图路由。写稿、设计资料、审稿按执行队列串行，保留当前全局模型忙态约束。

## 8. 修改同步、在途生成与撤销

**资料修改对下一轮生效，历史生成保留当时版本。** 不自动重写已经生成的故事。

- 同窗口保存后更新同一实体；跨窗口事件只携带 ID、版本与来源，接收方重新读库。补齐手改与提案保存的事件覆盖，不能只刷新知识列表。
- 有本地未保存表单时，外部更新显示“来源已变化”，保留作者输入并提供对照；不能覆盖或不加提示地另存成正式重复实体。
- 生成中可以浏览、搜索和本地编辑资料；作者点保存时，显示“本轮完成后保存，下一轮生效”。修改先持久化为编辑草稿，不直接改变正式来源。
- 首版可先交付“生成中只读，停止后编辑”的安全子集；完整体验用持久化命令在轮次边界执行保存。自动六轮推进遇到待保存修改时暂停后续轮次，先保存并让作者继续；不悄悄把新资料混入本轮请求。
- 若其他窗口绕过队列直接修改正式资料，沿用现有严格全书版本检查：迟到产物保留为恢复材料，当前工作稿不被覆盖，下一轮重新装配。首轮不放宽 `assertCurrent` 或原应用保护。
- 相关设定/角色变更后，旧审稿标注“资料版本已变化”，需要针对新来源重新审读；保留旧意见作为历史。单纯浏览、筛选与界面折叠不使稿件过期。
- 作者撤销资料提案时只撤销该次资料变更，不顺带撤销正文；若资料已经被后续编辑，拒绝覆盖并展示对照。依赖该资料的后续稿提示重新核对。
- 原窗口锁继续有效。资料被其他窗口占用时能查看和定位到持有者，不能在另一处编辑；本轮不以此为由重做整书正文锁协议。

## 9. 分三批交付

| 批次 | 可感知结果 | 主要实施点 | 本批完成条件 |
| --- | --- | --- | --- |
| **第一批：看得到、选得准、继续写** | 四类资料侧栏、当前章纲跟随、固定参考、灵感用于下一幕、实际使用清单、准确往返工坊 | 资料引用模型、resolver、只读访问策略、上下文与工具统一门禁、导航恢复 | 工坊更新的资料能实际影响下一轮；无资料仍能空白开场；作者能看出用了什么 |
| **第二批：原位编辑、双向同步** | 四类资料在故事现场编辑保存，工坊同步；脏表单、来源冲突和待保存状态可恢复 | 无导航保存服务、共享编辑字段、资源事件、CAS/编辑草稿、轮次边界保存调度 | 同一 ID 双向显示；生成中无混合版本；重开不丢编辑，不重复创建条目 |
| **第三批：AI 帮故事长出资料** | 起草/整理人物设定、章纲和灵感，分支草案参与连续创作，作者预览后收入工坊 | 专用任务入口、分支草案访问与证据、跨实体临时 ID 映射、提案差异与撤销 | 未确认草案不污染正式库；确认与撤销完整；拒绝、换版和分支切换不串资料 |

建议第一批完整跑通四模块，而不是先做完一个模块再只留三个空入口。第二批先支持内容与常用字段编辑，完整大纲画布、关系图布局和大树整理继续在工坊完成。

## 11. 验收样例

确定性验证与真实模型验证分别记录；不把“材料出现在提示词里”当成模型一定遵守。

1. 工坊把“铜符需要体力代价”改成新版本，下一轮实际选材记录使用新哈希，原轮次仍保留旧哈希。
2. 固定一名角色仅提供档案；不点“安排出场”时，不能把固定动作记录为剧情事实。
3. 当前章纲自动随选章变化；无章纲仍能开场；未来正式正文、旧本章已删文字不会经侧栏或新工具泄漏。
4. 推荐灵感未经选用不进入正文任务上下文；“用于下一幕”成功一次后消费，取消/失败不消费，换一版复用原意图。
5. 侧栏编辑角色不改变章节、不清空未发送指导；切到工坊看到同一实体，返回时稿件、选区、位置恢复。
6. 生成中保存资料不会形成混合来源；排队保存、外部直接修改分别按明确策略处理，后续自动轮次正确暂停。
7. 重名、改名、删除、来源回滚、脏表单、并发保存和备份恢复不会静默选错人、用旧资料或丢修改。
8. 本分支新人物可维持后续故事一致性，拒绝或切分支后不进入正式角色/关系/知识库；确认后沿用同一提案审计。
9. 必要资料预算不够明确停止，自动项按完整条目省略；报告与实际请求一致。
10. 在 1440/1080 桌面资料侧栏不遮住继续/停止；键盘、中文输入、减少动画与原故事/工坊功能回归通过。

真实模型使用仓库规定的应用配置 `deepseek/deepseek-v4.1-flash`，在独立验证作品中覆盖人物越权知情、设定代价、章纲偏离、灵感误落实、改资料后继续与新人物建档。与未联动样本比较人物/设定冲突、章纲完成度、灵感误用、作者重复交代次数、操作步数、延迟与 Token；本轮未进行这组实验。

## 12. 本方案的边界

不增加启动故事的必填资料，不自动把 AI 新创意保存成作者事实，不复制资料库，不重做四个模块全部布局，不在本批扩大多窗口编辑权限。

首个建议落地点：**故事资料侧栏 + 四类引用与选用 + 当前章纲跟随 + 本轮实际使用依据 + 工坊准确往返**。先让四个模块真正服务每一轮故事生成，再扩展原位编辑和 AI 建档。

Hindsight 工具目录本轮未暴露可调用方法，因此没有取得或引用知识页内容。该限制不影响本次源码核查，但不能据未读取的记忆声称某项决策已被批准。

设计检查：已由独立实施者阅读方案并检查关键决策缺口，返回 `nothing important left`。这只说明方案足以继续细化实施，不代表代码、交互或模型效果已经通过验证。
