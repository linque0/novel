所有作品内容修改由作者操作提案卡后进入作品 store。提取、分析、审稿及流程不会自动改正文。自动模式只影响作品记忆，需要手动开启并设置每日 token 上限。

## 入口与默认行为

恍然梦新增「创作与审稿」「知识库」「文风档案」「工作流」入口。

- 先在设置窗口配置现有服务商和模型。未指定角色模型时复用当前模型。
- 知识库默认手动「更新／继续」。全量重建逐章替换校验通过的结果，失败时保留旧卡；过期及证据无法定位的卡不作为生成事实使用。
- 隐私模式使用已有摘要、结构化字段及去除摘引的知识，不调用原文摘要生成，也不转发旧聊天原文、正文片段、人物小传或范文。手动知识提取、文风学习和改稿另有本次发送范围确认。
- 创作默认保守。开放模式的新实体单列为原创草案，关系提案不能自动新建人物。
- 续写默认截至当前章；工具也不能通过参数绕过历史范围。全书审稿可以读取全部章节。
- 改稿每段显示原文、替换文和理由。跨越双链或批注的片段禁用一键应用；其他片段通过编辑器事务修改，保留范围外标记。来源变化会阻断应用。
- 后台记忆由主窗口持有，关闭助手面板继续执行。暂停及退出保存已完成章节；异常退出后未释放的租约最长约两分钟过期，再由作者手动继续。
- 「撤销本次应用」核对应用后版本；后续作者编辑会阻止覆盖。批量应用校验落库结果，保存失败回滚本次变更。

## 数据与实现位置

新增 Dexie v8／v9 表：`aikb`、`aikbmeta`、`airuns`、`aidecisions`、`aistyle`、`aikbvec`。原有 `aisum` 保留。repository 负责作品隔离、事务替换、任务租约及每日预算预留。

主要模块位于 `F:/deepseek workplace/novel-studio/src/services/ai/`：

- `contracts.js`：快照、哈希、完整消息预算、分页和来源引用。
- `agent.js`／`tools.js`：协调器、五能力校验、六轮有上限的只读工具问答和重复请求缓存。
- `knowledge.js`／`retrieval.js`：章节事实、伏笔回放、聚合依赖、历史过滤、关键词与可选向量检索。
- `professional.js`：文风、审稿、改稿、按章恢复和提案复核。
- `application.js`：store 应用入口、窗口锁、来源检查、编辑器事务、审计、回滚与撤销。
- `runtime.js`：设置同步、来源失效、主窗口后台任务及自动更新队列。

跨窗口回归还修复了两处既有问题：只读状态切换不再触发旧正文保存；迁移实体的面板关闭后释放当前锁，而不是最初的锁。

JSON 备份明确包含摘要、知识、任务、人工意见、文风和向量；向量使用显式数组序列化。恢复在一个事务中完成，旧备份可省略新表，恢复后的来源由哈希重新核对。API 凭据不进入备份。正文导出范围不变。

## 验证方式

新增集成脚本仅允许隔离配置 `agent-v2-verify`，拒绝连接其他数据目录。Vite 使用 5173，Electron CDP 使用 9333，mock 使用本机 18700。所有 API 测试均使用 mock，没有调用真实服务商或真实作品。

```powershell
# 独立终端运行 Vite 和 mock
node node_modules/vite/bin/vite.js --host 127.0.0.1 --port 5173 --strictPort
node tools/mock-ai.mjs --port 18700

# 独立 Electron 测试配置
$env:NOVEL_STUDIO_DEV='1'
node_modules/electron/dist/electron.exe . --profile=agent-v2-verify --remote-debugging-port=9333

# Agent 集成及真实拆窗检查
node tools/ai-v2-verify.mjs
node tools/ai-v2-windows-verify.mjs

# 现有 UI 回归应顺序运行，避免同时操作同一个页面
$env:CDP_PORT='9333'
node tools/multiwindow-verify.mjs
node tools/annotation-verify.mjs
node tools/dl-verify.mjs
node tools/olcanvas-verify.mjs
npm run build
```

集成覆盖：出站隐私请求、取消后迟到响应、作品切换、生成锚点、空连线、重复应用、保存失败回滚、零事件章节、证据核对、卷移动、全文分块、伏笔删改回放、截至章节工具限制、预算上限、作者覆盖意见、文风确认、审稿恢复、逐段改稿、富文本标记、工作流检查点、向量失败降级、备份事务及旧格式恢复。

具体最终运行结果见本文末尾验收记录。完整请求预算包含系统、指令、历史、上下文、工具结果和输出预留；模型的最大输出会受当前总预算限制，不会挤占全部输入空间。

## 需要作者参加的质量验收

mock 验收证明请求与状态机制正确，不证明真实模型创作质量。实际服务商的结构化输出稳定性、长篇审稿漏检／误报、线路的实质差异、文风保持以及向量召回提升仍需要固定作品及作者人工评分。E1 在证明召回收益前保持关闭。

建议固定评测作品至少包含：两卷、已知时间线冲突、人物能力变化、同名歧义、伏笔埋设／推进／回收、一个零事件章节、一章长文本，以及带双链和批注的段落。记录期望证据、漏检、误报、文风评价及 token 成本；不要用模型自检代替作者判断。

并行专业角色、持续自动改稿和外部网站访问没有启用。各流程默认串行、停在待确认提案。
