## 三、九轴对照

| 轴 | 催更姬 | 恍然梦 | 谁更好 |
| --- | --- | --- | --- |
| 1 宿主与边界 | 宿主 DSH，插件只提供数据/工具/UI | 独立 App，Agent 内嵌 | 各有胜负：催更姬可复用宿主全部能力，恍然梦可自定体验 |
| 2 谁负责智能 | 宿主 `dsh-agent-loop`（规划/反思/子 Agent/模型路由） | 自写循环 + 22 类任务模板，多阶段流程硬编码 | **催更姬** |
| 3 工具面契约 | 66 action、强 schema、读写分离、幂等键 | 15 只读工具、人读字符串参数、无 schema | **催更姬** |
| 4 上下文哲学 | 先索引摘要→按需读全文，**上下文由模型决定拉什么** | 预设块全量拼装 + token 预算裁剪，**上下文由引擎决定给什么** | 各有胜负：催更姬省 token/更可缩放，恍然梦更可控可复盘 |
| 5 驾驶层 | 6 个渐进披露 Skill + guidance 模块 + 预设文本（不执行宏） | 预设编译引擎（宏/预算/CoT/导入导出） | 拆开看：**Skill 层催更姬强，预设引擎恍然梦强** |
| 6 存储与并发 | 文件+索引+文件锁+事务恢复；requestId+expectedRevision 前置 | IndexedDB+租约+hash 事后校验 | **催更姬**（前置校验优于事后发现） |
| 7 版本与审计 | 每章/每条设定/每次规划事务都有历史，可 revert | 章节版本 + `airuns` 审计 + 撤销；审计只增不清理 | **催更姬** |
| 8 检索 | 文本/摘要 | 关键词+向量+RRF | **恍然梦** |
| 9 UI 与数据位置 | React 注入宿主侧边栏；数据在磁盘 | Vue 七模块 + 四套皮肤；数据在 IndexedDB | 各有胜负：工坊 UI 远成熟，但数据位置是插件化最大障碍 |

## 四、相同点（同一问题的两种解）

1. **同一个工作对象**：正文/设定/规划同处一个工作台，Agent 围着同一份作品资料工作——不是「聊天窗 + 附件」。
2. **同一条红线**：AI 不直接改库。催更姬靠工具 action 白名单 + 作者面/Agent 面分离（`HUMAN_ACTIONS`）与 Skill 规则；恍然梦靠提案制 + `proposalGuard` + 审计撤销。
3. **同一套版本纪律**：都在改前读最新版本、发现并发就重读合并，而不是后写覆盖。
4. **同一份酒馆血统**：两边都做酒馆资产迁移（催更姬 `docs/tavern-import.md`；工坊 `docs/恍然梦Agent预设接入方案-本地酒馆调研.md`），但落点不同——催更姬只搬文本，工坊搬行为。

## 五、催更姬的优缺点

**优点（可搬运价值）**
1. 工具面契约工程化：66 action 强 schema、读写分离、幂等键、版本前置校验。
2. 上下文按需：索引摘要 → 分页读全文，`limit`/`resourceOffset`/`cursor` 处处有界。
3. Skill 渐进披露：`SKILL.md` + `references/` + guidance 分模块，把「写作规范」从巨型提示词拆成可按需加载的知识。
4. 存储层做得像数据库：分文件索引、文件锁、事务恢复、布局迁移快照、审计。
5. 零 Agent 自研成本：模型路由、子 Agent、权限、计划模式、反思循环全部继承宿主。

**缺点**
1. **没有向量/语义检索**：长书里靠名字与摘要检索，作者用自然语言描述情节时召回差。
2. **没有任务编排**：无「检索→生成→校验」工作流、无检查点续跑、无阶段级模型选择；这些只能靠宿主会话手工驱动。
3. **预设不执行**：宏、装填深度、触发条件一律不生效，只保留文本——对重度酒馆用户是降级。
4. **强依赖宿主版本**：DSH 插槽/工具 API 一改就要跟；`0.5.1` 已为兼容 DSH `0.2.1-rc.5`/`0.2.2-alpha.2` 做过适配。
5. **UI 受宿主形态约束**：面板、快捷键、多窗只能表达成宿主槽位允许的形状。

## 六、恍然梦的优缺点

**优点（可搬运价值）**
1. **预设编译引擎**：块顺序 + 预算裁剪 + 宏 + 采样 + CoT + Chat-Completion 双向导入导出，是催更姬没有的完整驾驶层。
2. **任务/工作流体系**：22 类任务模板，每类绑定输出工具与作用域约束（如 `memory.extract` 必须单章、`chapter.rewrite` 必须绑定替换范围）。
3. **语义检索**：关键词 + 向量 + RRF，可降级。
4. **写入安全做得最深**：提案→校验→落库复核→回滚→审计→撤销，14 层防护，且**Agent 永不直接改库**是贯穿设计的红线。
5. **成品级 UI**：七模块 + 四套皮肤 + 大纲分层画布 + 双窗并排，远超插件形态所能承载。

**缺点（正对催更姬的优点）**
1. **没有规划器**：多阶段流程是硬编码模板，做不到「给定目标→自主分解→按结果重规划」。⚠️ 部分被 22 类任务模板缓解，但模板本身不可生成/编辑。
2. **反思不闭环**：审稿/复核存在但不驱动重生成；直接「一致性审稿」路径不跑模型复核（`docs/恍然梦Agent能力评估.md` 判据仍成立）。
3. **工作记忆不持久**：会话历史只在内存，刷新即失。
4. **工具参数无 schema**：`executeTool` 只做「必须为对象」与几条范围校验（`tools.js:186-207`），模型给错参数靠运行时兜。
5. **数据位置锁死在渲染进程**：IndexedDB 让任何外部进程（含 DSH 插件、CLI、MCP）都无法直接读写作品——这既是它「本地优先」的优势，也是插件化的天花板。
