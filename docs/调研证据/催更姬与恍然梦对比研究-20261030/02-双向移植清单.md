## 三、为什么只挑这 8 项

- **不搬的**：催更姬的存储层（文件+锁+迁移）——工坊已有 Dexie 与备份体系，换存储是方案 B 的事；工坊的 14 层写入防护——催更姬的 action 白名单 + Skill 规则已覆盖同一红线，重复建设无收益；双方的桌宠/皮肤/3D 书架——与 Agent 能力无关。
- **先做 A 的原因**：A1–A4 全部落在「不改 UI 栈、不动 Electron、不引依赖」的范围内，且都有现成回归脚本可复用（见 03 文档各节「验收命令」）。
- **B 的本质是"给催更姬补短板"，不是移植难点**：它要求改的是另一个项目的仓库，是否做取决于你是否还要继续维护催更姬；如果只做一侧，B 可以直接略过。
