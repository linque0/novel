# 05 · 谱系图（Worldset Studio）

来源：布局引擎 = `pretty/chunks__3007-*` 模块 `52069`；页面/渲染层 = `pretty-pages/lineage.pretty.js`（模块 `72216`）。
**纯 inline SVG**，无 canvas、无 viewBox（单一 `translate/scale` 仿射），**无箭头标记**（方向靠世代行表达）。

## 1. 布局引擎（确定性，无物理迭代 —— 最适合直接移植）

### 1.1 几何常数

```
人像卡 120 × 188 ；封面区高 142 ；婚姻菱形 12
世代行距 = 188 + 84 = 272  ；世代列距（演化图）= 120 + 76 = 196
同一世代内：人像 120 + 间隙 16 ；婚姻标记 12 + 间隙 16 ；条带间距 26
连通分量之间 90 ；演化分量纵向 64 ；演化行距 188 + 22 = 210
```

### 1.2 世代分配（BFS）

- 从起点出发：父母 `gen-1`、子女 `gen+1`、配偶「同代」、手足「同代」、无父母/配偶者「同代」；最后整体平移使 `min(gen)=0`。
- 冲突处理（产出 `broken` 诊断，边跳过绘制）：
  - 自环 → `自环（自己与自己相连）`
  - 世代冲突 → `世代冲突（可能存在循环亲缘）`
  - 手足与亲子代际矛盾 → `世代冲突（手足关系与亲子代际矛盾）`

### 1.3 婚姻（union）节点

```
配偶对 (a,b)      → { id:"u_"+linkId, a, b, gen, x, y:0, dashed: link.status!=="active", linkId, children:[] }
共同父母对 (a,b)  → 仅当某子女有 ≥2 位「同类父母」且同代：{ id:"u_co_"+a+"|"+b, …, dashed:true, children:[子女] }
子女排序          = (link.sortOrder ?? 9999)*1e13 + Date.parse(link.createdAt)
裁剪              = 无 linkId 且无子女的共同父母对丢弃
```
性别仅用于决定配偶对内部顺序（`男/m/male/男性*`→m，`女/f/female/女性*`→f）。

### 1.4 边契约（渲染层直接消费）

```js
// 子女 n 属于某个 union a 时：
edges.push({ fromNode: 未入 union 的父母id, to: n, dashed: kind==="adoptive" || status!=="active", linkIds:[…] })
edges.push({ fromNode: a.id,               to: n, dashed: 任一收养/失效,                          linkIds:[…] })
// 子女 n 无 union（或父母未配对）时，按（parent 优先，再 createdAt）排序：
edges.push({ fromNode: parentId, to: n,
             dashed: kind==="adoptive" || status!=="active" || index>0, linkIds:[link.id] })
```
**虚线语义统一**：收养 / 失效(非 active) / 第二位父母。

### 1.5 横向打包（逐世代从右向左）

1. 同代人先按配偶关系组成「条带」（strip）：先取 `f` 的配偶，再取 `m` 的配偶，剩下的交替；无可配配偶者单独成条带。
2. 条带内元素序列：`[配偶, 婚姻标记, 配偶, 婚姻标记, …, 本人, 婚姻标记, 配偶, …]`。
3. 条带宽度 = `Σ(人?120:12) + 16*(元素数-1)`。
4. 条带排序锚点 `anchor` = 子女平均 x，否则入边落点平均 x；无锚点的排最后（按 sortKey）。
5. 摆放：`x = max(anchor - width/2, prevRight)`，最小间隙 26；最后整体归零最小 x（婚姻标记一起平移）。

### 1.6 输出结构

```js
{ nodes:[{id,gen,x,y}], unions:[{id,a,b,gen,x,y,dashed,linkId?,children[]}],
  remote:[union…], edges:[{fromNode,to,dashed,linkIds[]}], broken:[{a,b,reason}],
  width, height }
```

### 1.7 三个入口 + 演化图

| 函数 | 导出 | 作用 |
| --- | --- | --- |
| `of(entries, links, focusId?)` | `kinshipLayout` | 全项目：连通分量各自布局后横向打包（分量间距 90） |
| `JV(entries, links, entryId)` | `ancestorsLayout` | 单人：其**祖先 + 祖先的配偶** |
| `th(entries, links)` | `pickFocus` | 自动起点：在「无父母且（子女+配偶）>0」中选后代子树最大者 |
| `YF(entries, links)` | `evolutionLayout` | 演化图（独立算法）：自环→broken；DFS 破环（环边**跳过绘制**并报 `演化环（循环演化，该边已跳过绘制）`）；深度 = 最长路径；列距 196、行距 210 |

## 2. 渲染层

### 2.1 容器与坐标

```jsx
<div className="ln-viewport" ref onContextMenu={ctx({type:"canvas"})}>
  <style>{…ln-* 规则…}</style>
  <div className="ln-zoom">{ − / ＋ / ⤢ }</div>
  <svg onPointerDown={pan}>
    <g transform={`translate(${tx},${ty}) scale(${k})`}>
```
屏幕像素 = 布局像素，单一仿射。**`width/height` 不作用于 SVG**，只用于适配计算：
`k = clamp(min(cw/(w+160), ch/(h+140)), 0.25, 1.3)`，`tx=(cw-w*k)/2`，`ty=(ch-h*k)/2+10`；`mode|focus|(nodes===0)` 变化时自动适配一次。
绘制顺序：世代标签 → union→子女正交连接 → 节点→节点贝塞尔 → 婚姻横条 → 手足弧 → 远端连接 → union 菱形 → 人像卡。

### 2.2 人像卡（120×188，`<g class="ln-node ln-card">` + `translate(x,y)`）

```
rect 120×188 rx10  fill var(--panel-2)                    卡底
<g clipPath="url(#lnclip-{id})">
  有封面：image 120×142 preserveAspectRatio="{xMin|Mid|Max}{YMin|Mid|Max} slice"
  无封面：rect 120×142 fill=分类色 @0.14 + 名称首字 40px fill=分类色
  rect y142 h46 fill var(--panel-2)                       遮住封面溢出
  rect y142 h1  fill var(--line)                          分隔线
rect 120×188 rx10  fill none stroke={焦点?--accent:--line-strong} strokeWidth={焦点?2:1}
rect 6.5,152.5 6×6  rotate45 fill=分类色                  分类菱形
text 18,159 9px    {分类名，截断 10}
text 9,179 12.5px 600 {名称，截断 8}
重要度 core|major：circle 109,11 r5.2 rgba(0,0,0,.38) + circle r3 var(--accent)
<title>{名称}（点击设为焦点，双击打开条目，右键更多操作，可拖动调整位置）</title>
悬停胶囊行 translate(60-(40n-4)/2, 194)：n 个 36×16 rx8 的 accent 胶囊，间距 40
```
封面焦点来自 `entry.coverFocus {x,y}`（0–100）：`x<34→xMin`、`x>66→xMax`、否则居中；Y 同理。封面源 `entry.coverUrl || entry.images?.[0]?.url`。
**卡上不显示**：生卒年、纪元、称号、别名、性别、条目状态、摘要。

### 2.3 各种边

```js
// 单亲/父母 → 子女：三次贝塞尔，控制点在纵向中点
`M ${fx+60} ${fy+188} C ${fx+60} ${a}, ${tx+60} ${a}, ${tx+60} ${ty}`        // a=(fy+188+ty)/2
// union → 子女：正交（竖→总线→各子女）
`M ${u.x} ${u.y+6} V ${n}` + `M ${min} ${n} H ${max}` + 每个子女 `M ${cx} ${n} V ${child.y}`
// 手足：二次贝塞尔弧
`M ${a.x+60} ${a.y} Q ${midX} ${min(a.y,b.y)-34} ${b.x+60} ${b.y}`
// 婚姻横条：直线 + 12×12 菱形（rotate 45）
// 远端配偶（同代但已在他处摆放）：抬升控制点的三次贝塞尔
`M ${ax+60} ${ay+94} C ${mx} ${ay+54}, ${mx} ${by+54}, ${bx+60} ${by+94}`
```
每条可见路径**前面都有一条透明加粗的命中路径**（`stroke-width:12`，`cursor:pointer`）用于点选。

### 2.4 世代标签

- 亲缘/上溯：`x=-18`，右对齐，`第 {gen+1} 代`；有焦点时改为相对焦点：`焦点代` / `上 {n} 代` / `下 {n} 代`。
- 演化：`原型`（第 0 代）/ `衍生 · 第 {gen} 代`。

## 3. 交互

| 能力 | 说明 |
| --- | --- |
| 平移 | `<svg>` `pointerdown`（左键）→ window `pointermove/pointerup`，`tx = baseTx + (clientX-startX)`；无中键、无空格拖 |
| 缩放 | 滚轮 `{passive:false}` + `preventDefault`，每格 ×1.12，**光标锚定**：`k'=clamp(k*1.12,0.25,2.5)`、`tx'=lx-(lx-tx)/k*k'`；按钮 ±(×1/1.2 / ×1.2)；`⤢ 适应全图` |
| 拖动节点 | **允许且持久化**：写入 `entry.lineageDx/lineageDy`（`updateEntry`）；位移 >4px 视作拖动并吞掉其后的点击；拖动时加 `.ln-nomove` 关闭过渡 |
| 悬停 | 仅两处：卡上胶囊行淡入；菱形/命中边悬停 → 描边变 `--accent`（`对角线悬停 → 高亮`）。**无路径高亮、无他人变暗** |
| 单击节点 | 亲缘/上溯：设为焦点（同 id 不重复）；演化：打开条目页 |
| 双击节点 | 打开条目页 |
| 点击婚姻条/菱形 | 有 `linkId` → 打开「编辑关系」；无 → 确认后 `addLineageLink({kind:"spouse",status:"active"})` |
| 点击边命中路径 | 打开「编辑关系」对话框（含共路由的全部 linkIds） |
| 拖拽建边 | **不支持**（改用悬停胶囊 + 右键菜单） |
| 悬停胶囊 | 亲缘：`+父母 +配偶 +手足 +子女`；上溯：`+父母 +配偶`；演化：`+前身 +衍生` |
| 键盘 | **无**（仅右键菜单内部有 ↑↓←→/Home/End/Enter/Esc） |

**右键菜单**（共享 portal 菜单组件）：
- 画布：`添加成员关系…` / `添加演化关系…` · `亲缘视图`☑ `上溯视图`☑ `演化视图`☑ · `复位布局…`（无位移时禁用，提示「清除所有手动拖动的位置」）
- 节点：`打开条目页` · `更换卡片图片…`（无图集时禁用） · `设为焦点` / `取消焦点（查看全树）` / 当前焦点（禁用，上溯视图必须有焦点） · `添加父母（生身）/ 添加养父母 / 添加配偶 / 添加兄弟姐妹 / 添加子女`（或 `添加前身 / 添加衍生`） · `编辑 TA 的谱系关系…`（无关系时禁用） · `复位此节点位置`
- 婚姻：`编辑婚姻关系…` 或 `登记 A × B 为配偶` · `为这对伴侣添加子女…` · `解除配偶关系`（危险）
- 边：`编辑这 N 条关系…` · `反转方向`（spouse/sibling 禁用并提示原因） · `删除这条关系`（危险）

## 4. 录入对话框

- **添加亲属**（`为「X」添加亲属`，副标题「方向说明：父母/养父母是长辈，子女是晚辈；配偶与兄弟姐妹为平辈（双向）」）：当事人搜索 + `对方是当事人的 <Select>`（父母（生身）/ 养父母 / 配偶 / 兄弟姐妹 / 手足 / 子女；演化视图为 前身 / 衍生物）+ 对方搜索 + `新建并关联` 内联创建；手足子表单（同父同母 / 同父异母 / 新建共同父母 / 仅登记手足）；可折叠「更多选项（状态 / 备注 / 序齿）」：状态 `active 生效 / uncertain 存疑·传闻 / deprecated 已结束`、`序齿（排行）`、备注。有重复守卫。
- **编辑关系**：每条一张卡 —— 关系类型（仅 parent 类可切 parent/adoptive）、状态、`序齿（排行）`（提示「在「X」的子女中排第 n / 共 m」）、备注、`删除此关系`。
- **迁入亲属关系**（工具按钮，带计数）：把 `relations` 里亲属语义的关系一键转成 `lineageLinks`。转换规则基于关系类型正则：
  ```
  配偶|妻子|丈夫|夫妻|婚姻|前妻|前夫|未婚妻|未婚夫|亡妻|亡夫|伴侣      → spouse
  养父|养母|养子|养女|义父|义母|义子|义女|收养                        → adoptive
  父亲|母亲|…|^父$|^母$|^爸$|^妈$|^爹$|^娘$                            → parent
  儿子|女儿|孩子|…|后代|子孙                                          → parent（方向翻转）
  兄弟|姐妹|…|手足|孪生|双胞胎                                        → sibling
  血亲|亲属|家人|家族|亲戚                                            → parent
  ```

## 5. 布局模式与焦点

三种模式（按项目持久化 `ws_lineage_mode_<projectId>` / `ws_lineage_focus_<projectId>`，并同步到 URL `?focus=&mode=`）：
- `kinship 亲缘`：全部亲缘（或焦点的连通分量）
- `ancestors 上溯`：焦点 + 其全部祖先 + 祖先配偶
- `evolution 演化`：仅 `kind:"evolution"` 的独立图

焦点下拉：首项 `（全树）` = null；选项 = 出现在任一非演化关系里的条目。另有 190px 搜索框（占位 `搜索条目设为焦点`），只在「人物用途分类」下按名称过滤，取前 12。焦点若已不在任何亲缘边中则丢弃。

## 6. 诊断与空态

- 冲突面板（置于图上方，`borderColor:var(--warn)`）：`谱系数据存在 {n} 处冲突（相关边已跳过绘制）` + **最多列 5 条** `{A} ↔ {B}：{reason}`。无复制/导出/画布内标记。
- 更深的一致性检查在「设定检查」页（`lineage_cycle / evolution_cycle / lineage_dup / lineage_parents_count / lineage_birth_adopt / lineage_incest / lineage_sibling_conflict / lineage_sibling_mergeable`）。
- 四种空态：`还没有演化关系`（含演化视图说明）/ `还没有谱系关系`（+「迁入已有亲属关系（N）」）/ `没有可上溯的祖先` / `当前焦点下没有可显示的谱系`。
- 容器高度 `calc(100vh - 210px)`，`min-height:480`。

## 8. 移植备忘（→ novel-studio）

- **布局引擎是纯确定性算术（约 300 行，零依赖），最值得整体移植**；建议按 1:1 语义重写为 JS 模块并用单测/验收脚本覆盖：3 代同堂 + 再婚 + 收养 + 失效 的夹具。
- 渲染层需要自己写（原站页面代码），但契约已明确：`nodes/unions/edges/broken` 四个数组 + 上表的边形状与虚线规则。
- novel-studio 可复用：`graphview.js` 的 `usePanZoom` 替换原站的滚轮/按钮缩放（原站 ZOOM 上限 2.5、下限 0.25、步进 1.12 可直接作为初始参数）、`arrowHeadDir`（若要加箭头）。
- 与 novel-studio 现有 `relations`（人物关系图）的关系：**谱系是独立边表**（5 种 kind + 状态 + 序齿），不要塞进 `relations`；原站提供「从 relations 正则迁入」的桥接，可作为一次性迁移工具。
- 节点偏移持久化（`lineageDx/Dy`）应放在**节点自身记录**上（与 novel-studio `olnodes` 的 x/y 一样），而不是边或单独布局表。
