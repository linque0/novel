# 02 · 编辑器与引用系统（Worldset Studio）

来源：`pretty/chunks__6416-084cf8b52c14d0fd.pretty.js`（编辑器 + 引用 UI，305 条中文串）、`pretty/chunks__70e0d97a-*`（ProseMirror view）、`pretty/chunks__54a60aa6-*`（@tiptap/core+react）。
编辑器技术栈：**TipTap 2 / ProseMirror**（不是 Slate）。条目正文以 **HTML 字符串**存储，**没有 JSON doc 序列化**。

## 1. 语义块（callout）

唯一节点 `callout`，靠 `type` 属性分 6 种语义（`E:84-109`）：

| type | 标签 | 色变量 | 默认可见 |
| --- | --- | --- | --- |
| `info` | 提示 | `--info` | 是 |
| `caution` | 注意 | `--warn` | 是 |
| `warning` | 警告 | `--danger` | 是 |
| `conflict` | 冲突 | `--danger` | 是 |
| `secret` | 秘密设定 | `--accent` | **否**（默认折叠） |
| `note` | 作者注释 | `--fg-muted` | 是 |

节点定义（`E:139-158`）：

```js
bP.create({
  name:"callout", group:"block", content:"block+", defining:true,
  addAttributes:()=>({ type:{ default:"info", parseHTML:e=>e.getAttribute("data-callout")||"info" } }),
  parseHTML:()=>[{ tag:"div[data-callout]", contentElement:q(".callout-body") }],
  renderHTML({node,HTMLAttributes}){ return ["div", mergeAttrs(HTMLAttributes,{
      "data-callout":node.attrs.type, class:`callout callout-${node.attrs.type}` }),
    ["div",{class:"callout-label",contenteditable:"false"}, label], ["div",{class:"callout-body"},0]] },
  addNodeView:()=>ReactNodeViewRenderer(NodeView) })
```

NodeView 行为：标签点击 → `<select>` 切换 6 种 type（`updateAttributes({type})`）；右键菜单 `[块类型 ▸ 6 项(带勾选), sep, 删除块]`；`secret` 类型额外有 `隐藏/显示` 按钮（`Eye/EyeOff` 图标），**仅 React state，不持久化**，隐藏时用 `.callout-secret-closed` 类收合。

```js
// 插入 secret 块的调用（E:1869）
insertContent({type:"callout", attrs:{type:"secret"}, content:[{type:"paragraph"}]})
```

## 2. 折叠块与剧透

- **`collapsible`（详细内容）**：`details[data-collapse]`，属性 `title`（默认「详细内容」）+ `open`（默认 true，**持久化**）。NodeView 支持内联改标题（`input.collapse-title-input` → `updateAttributes({title})`）、`收起/展开`、`重命名标题`、`删除块`；收起时 chevron 旋转 `-rotate-90`。
- **`spoilerBlock`（剧透块）**：`details[data-spoiler-block]`，**无属性**，展开态是 per-session state。覆盖按钮文案「该内容为剧透，点击展开」；展开后头部为 `剧透` 徽章 + 「重新隐藏」。隐藏时内容是 `opacity-0 h-0 overflow-hidden` —— **DOM 里仍在，非真隐藏**。
- **`spoilerMark`（行内剧透）**：`span[data-spoiler-mark]`，`title="剧情遮罩"`，`inclusive:false`。
- **`annotation`（行内批注，mark）**：`span[data-annotation]`，属性 `{comment, resolved, createdAt}`，`data-resolved` 为 `"1"/"0"`，`inclusive:false`。
- **`footnote`（脚注）**：`sup[data-footnote]`，属性 `{content}`，文字 `※`。
- **`timeTag`（时间标记）**：`span[data-time-tag]`，属性 `{label, era, year, fuzzy:false}`。
- **`gradientText`（渐变字）**：给 `textStyle` 加全局属性 `{angle 0..359, stops[]}`，渲染成 `background-image:linear-gradient(...)+background-clip:text;color:transparent`。

**语义高亮预设**（只是 highlight mark 的 color 值，key 仅供 UI）：

| key | 标签 | 色值 |
| --- | --- | --- |
| normal | 常规高亮 | `#c99b5f45` |
| pending | 待确认 | `#c2a16352` |
| conflict | 冲突 | `#b56a5e4d` |
| secret | 隐藏设定 | `#9a86a84a` |
| foreshadow | 重要伏笔 | `#7497a94a` |

## 3. 引用系统（★ 最值得移植）

### 3.1 两个引用节点 + 一个关系节点

| 节点 | 类型 | 属性 | DOM |
| --- | --- | --- | --- |
| `entryMention` | inline, `atom:true, selectable:false` | `entryId, label, category, status, summary` | `span[data-entry-mention]` + `data-category/data-status/data-summary` |
| `entryCard` | block, `atom:true, selectable:true` | `entryId, name, category, status, summary, updatedAt` | `div[data-entry-card]` + `data-category/data-status/data-updated-at` |
| `relationBlock` | block, `atom:true` | `sourceId, sourceName, relationType:"属于", targetId, targetName, description, status:"pending"` | `div[data-relation-block]` + `data-source-id/data-rel-type/data-target-id/data-status` |

引用卡片 DOM 契约（同时是 TipTap 节点的 parse 规则）：

```
div[data-entry-card="<entryId>"][data-category][data-status][data-updated-at]
  └ .entry-card-head > .entry-card-cat + .entry-card-status
  └ .entry-card-name
  └ .entry-card-summary        （空时「暂无摘要」）
  └ .entry-card-meta           （「更新于 {updatedAt} · 点击卡片跳转」）
  失效引用加 .entry-card-broken
```

关系块状态 4 值（`E:110-120`）：`confirmed 已确认(--ok) / pending 待确认(--warn) / conflict 存在冲突(--danger) / hidden 隐藏设定(--fg-subtle)`，默认 `pending`，仅用于 `relationBlock`。关系类型下拉取那 24 个建议类型 + 「自定义…」。

### 3.2 三种触发方式

1. **`/` 斜杠菜单**：分组 `设定`（折叠块/提示块/脚注/设定引用卡/角色引用/地点引用/势力引用/事件引用/物品引用/关系声明/时间块）与 `高级`（剧透块/秘密设定块，**受 `advanced_editor_blocks` 功能位门控**，未解锁时整组隐藏）。
2. **`@` 提及**：TipTap suggestion，`char:"@"`，`allowSpaces:false`，`allowedPrefixes:null`。
3. **打字自动联想**（`entrySuggestAuto`）：每次 update 取光标前「词」（`iP`，最大 12 个码点，遇中英标点/空白即断），若为某条目的 name/alias 前缀则浮层提示，`Tab` 接受，`↑↓` 选择，`Esc` 关闭；已在 `codeBlock`/`link` 内或紧邻已有引用节点时跳过。

### 3.3 引用选择器（`entry-picker`）

```js
function EntryPicker({projectId, onClose, onPick, categoryFilter, seedText,
                      allowCreate=true, title="搜索设定条目"})
```
- 候选 = 按 name / summary 的**小写子串匹配**，取前 **8** 条；空查询也返回前 8。
- 有输入且无匹配时，末行显示 `新建「{text}」并引用`；新建走 `createEntry({projectId, categoryId: categoryFilter||首个根分类, name, status:"draft", summary:""})`。
- 占位符：`搜索设定条目，支持新建`；空态：`没有匹配的条目`。
- ⚠️ 原站缺陷：新建分支返回给调用方的 `id/updatedAt` 是**本地临时生成**的，可能与落库记录不一致 —— 移植时勿复刻。

### 3.4 未绑定引用检测与批量绑定（★ 高价值）

正文侧栏「引用检查」：扫描纯文本中**出现但未被包成 mention** 的条目名/别名，给出出现次数与一键绑定。

```js
// 候选：对每个条目数 name/alias 的非重叠出现次数（上限 99），按次数降序取前 max
scan(plainText, entries, {minChars:2, matchAlias:true, max:8})

// 批量替换：跳过与既有 entryMention 范围重叠的出现
let hit = a.indexOf(n); while (hit!==-1 && out.length<max) {
  const from=pos[hit], to=pos[hit+n.length-1]+1;
  if (!existingMentions.some(r => from<r.to && to>r.from)) out.push({from,to});
  hit = a.indexOf(n, hit+n.length);
}
out.sort((x,y)=>y.from-x.from).forEach(r => tr.replaceWith(r.from, r.to,
  schema.nodes.entryMention.create({entryId, label:n, category:"", status:"", summary:""})));
```
文案：`未检测到疑似未绑定的设定引用。` / `正文中出现疑似未绑定的设定名称，点击全部绑定为内联引用：` / `{n} 处` / 按钮 `全部绑定`。

粘贴内部条目 URL（`/p/{projectId}/entries/{id}`）时询问：`检测到内部设定条目链接。确定：作为设定引用插入 / 取消：作为普通链接插入`，选「确定」即转成 mention。

### 3.5 反向链接

**原站没有任何反向链接索引或 UI**。反向导航只有两种：显式 `relations` 记录，与上面那个临时的「引用检查」扫描。移植时应视为**需要补齐的能力**（novel-studio 已有 `findBacklinks` 字符串扫描可继续用）。

## 4. 搜索（三条互独立的路径，全部是 `includes`/`startsWith`，无分词无模糊）

### 4.1 引用索引（供 @ 与自动联想）

```js
buildIndex(entries) → { buckets: Map<首码点, Entry[]>, total }
// 每个条目按 name 与 alias 的「首码点」入桶（去重）
search(index, query, {minChars=1, matchAlias=true, excludeEntryId, limit=8})
// 查询长度 >12 码点直接返回 []
// 候选必须 name.startsWith(q) 或 alias.startsWith(q)
// tier: 精确=0 > 名前缀=1 > 别名=2
// 排序: tier → name 长度 → name localeCompare("zh-CN") → id
// 返回 {id,name,alias,categoryId,summary,status,updatedAt,matchedName,isAlias,exact}
```

### 4.2 顶栏全局搜索

字段优先级固定 `name > alias > tag > summary > content`；content 命中返回 ±20 字摘要片段（前后加 `…`），其余字段返回 `summary.slice(0,50)`；按字段优先级排序，取前 8。触发：非输入框内按 `/` 聚焦；`Enter` 打开第一条。

### 4.3 文内查找（Ctrl+F）

对 `doc.descendants` 的每个 text 节点跑正则（可选 `g`/`i` 开关）收集 `{from,to}` 区间。

## 5. 序列化与清洗

| 阶段 | 实现 |
| --- | --- |
| 载入 | `content: sanitize(content looksLikeHtml ? content : marked.parse(content,{gfm:true,breaks:false}))` |
| 落库 | `onUpdate → getHTML()`（空文档存 `""`） |
| 自动保存 | 1500ms 防抖 + `Ctrl+S` |
| 只读渲染 | DOMPurify `FORBID_TAGS:["script","style","iframe","form","object","embed"]` → `dangerouslySetInnerHTML` |
| 存储前清洗 | DOMPurify `FORBID_TAGS:[…,"link","meta","base","noscript","template","svg","math"]`，`KEEP_CONTENT:true`，`ALLOW_DATA_ATTR:true` |

边界常量：`maxContentLen 1e6`、`maxJsonBytes 32MB`、`maxStringLen 1e4`。

### Turndown 导 Markdown 映射（13 条自定义规则）

| 节点 | Markdown |
| --- | --- |
| `callout` | `> [提示\|注意\|警告\|冲突\|秘密设定\|作者注释] …` |
| `collapsible` | `### {title}\n\n…`（title 默认「详细内容」） |
| `spoilerBlock` | `> [剧透] …` |
| `spoilerMark` | `\|\|text\|\|` |
| `annotation` | `text（批注：{comment}）` |

| `entryCard` | `> 条目：{name}（{category}）` |
| `relationBlock` | `source —relType→ target` |

| 任务列表项 | `- [x]/- [ ] …` |
| 删除线 / 高亮 / 下划线 | `~~…~~` / `==…==` / 直通 |

## 7. 移植备忘

- 原站在正文编辑器里做语义块；**novel-studio 的设定模块（MubuView）目前是裸 contenteditable + execCommand**。若不想把 TipTap 引入设定面板，可先以「HTML 契约 + CSS」落地 callout/折叠/剧透（节点 html 字段天然可存），待需要更强编辑体验时再换 TipTap。
- 三个引用节点的 DOM 契约（`data-entry-card` / `data-entry-mention` / `data-source-id` 等）是导出导入与重映射的锚点，**移植时应保留等价契约**。
- novel-studio 已有 `.dl-link[data-dl-target]` + `[[标题]]` 双链契约与 hover popover，与本系统的 `entryMention/entryCard` 是同一层能力：**建议在 `.dl-link` 基础上扩展块级卡片形态，而不是再造一套**。
- 「未绑定引用检测 + 全部绑定」成本低、体感强，建议优先。
