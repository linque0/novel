# 01 · 数据模型（Worldset Studio）

来源：`pretty/chunks__4673-7b7f0420d2a3ee0b.pretty.js`（Dexie + Zustand store）、`pretty/chunks__3007-d2633dd2dbd0fe7a.pretty.js`（枚举与工具）。

## 1. Dexie schema（库名 `worldset-local`，多账号时 `-u-<userId>`）

```js
v1: projects:"id" · categories:"id, projectId" · entries:"id, projectId, categoryId"
    relations:"id, projectId" · tags:"id, projectId" · events:"id, projectId"
    snapshots:"id, entryId" · inspirations:"id, projectId" · meta:"key"
v2: branches:"id, projectId"
v3: lineageLinks:"id, projectId"
v4: ops:"id, [world+author+seq], world, hlc" · syncMeta:"key" · members:"id, world" · syncState:"key, world"
v5: conflicts:"id, world, targetId, kind"
```

要点：
- 仅 `entries` 有二级索引 `categoryId`；**其余按项目/纪元过滤都是内存全表扫描**（Zustand 把整表读进内存当单一数据源）。
- v4/v5 是协作层（CRDT ops + HLC + 冲突），**与本文档其他部分解耦**，移植时可整体忽略。
- 每张表都有 `creating/updating/deleting` 钩子写脏标记（`worldset:dirty` 事件 + `worldset-dirty-at` localStorage），用于云备份与 AI 快照的增量判定。

## 2. 实体字段

### 2.1 project

```js
{ id, name, worldName, description:"", genre:[], status:"draft",
  coverUrl, coverFocus:{x,y}, images:[],
  mapImage, mapPins:[], maps:[{id,name,image,pins:[{id,entryId,x,y}]}],
  fieldTemplate:[], fieldTemplates:[{id,name,fields:[…]}],   // 模板可多组（旧字段 fieldTemplate 仍读）
  fieldDisplay:{hideEmpty:boolean},                          // 默认 false
  editorCfg:{suggest:{enabled:true,trigger:"both",minChars:1,matchAlias:true}},
  versionCfg:{enabled:true,maxPerEntry:20,minIntervalMin:10,maxBytesPerProject:50MB,includeMedia:false},
  chronology:"linear"|"segmented"（省略即 linear）, eraOrder:[string],
  mainBranchName, createdAt, updatedAt }
```

`status` 枚举：`draft 草稿 / building 构建中 / stable 稳定维护 / archived 归档 / deprecated 废弃`。
`genre` 预置 12 种：奇幻 / 科幻 / 末日 / 赛博朋克 / 蒸汽朋克 / 都市怪谈 / 架空历史 / 神话史诗 / 太空歌剧 / 废土 / 黑暗奇幻 / 现代异能（另有「自定义…」，自定义时存单元素数组）。

### 2.2 category

```js
{ id:"cat_*", projectId, parentId:string|null, name, description:"",
  icon:"Package", color:"#c99b5f", sortOrder:number,
  isDefault:boolean, hidden:boolean,
  defIds:[string],                 // ★「分类用途」= 预置定义 id，结构视图只看用途不看分类名
  fieldTemplate:[Field],           // 旧：单模板组
  fieldTemplates:[{id,name,fields:[Field]}],  // 新：多模板组
  fieldDisplay:{hideEmpty} }
```

- 预置定义 18 个（`Yp`），id 即用途：`overview 世界观总览 / laws 宇宙与自然法则 / geography 地理与地点 / faction 国家与势力 / history 历史与事件 / timeline 时间线与纪元 / species 种族与物种 / ecology 生态与资源 / power 魔法科技体系 / religion 宗教与神话 / culture 社会与文化 / economy 经济与贸易 / character 人物与角色 / org 组织与团体 / item 物品与遗物 / language 语言与文献 / conflict 冲突与主题 / inspiration 灵感与素材`。
- 用途解析：`tB(categories, projectId, purpose)` → 沿 `defIds` 与父链解析出分类 id 列表（按 `sortOrder` 排序）；无绑定则回退到「同名且无自定义 defIds」的分类。
- 图标白名单：`Globe, Orbit, MapPin, Landmark, Scroll, Hourglass, Users, Leaf, Sparkles, Moon, BookOpen, Coins, User, Shield, Sword, FileText, Flame, Lightbulb, Package, Network, Link2`。
- 调色板 10 色：`#c99b5f #7ba37e #7497a9 #b56a5e #9a86a8 #c2a163 #6f9a94 #a8788c #8a9a6b #997966`。
- **字段描述符**：`{key, label, type:"text"|"textarea"|"select", options?:string[], placeholder?:string}`；新字段 key 生成规则 `"f_"+Date.now().toString(36)`。
- **改名保护键**（检查引擎与结构视图依赖，改名时只改 label 不改 key）：`char_state, start_year, race, occupation, danger, place_type, region`。

### 2.3 entry（设定条目 = 本产品的基本单元）

```js
{ id:"ent_*", projectId, categoryId, name, alias, summary:"", content:"",  // content = HTML 字符串
  status:"draft", importance:"normal", visibility:"public",
  tags:[], coverUrl, coverFocus:{x,y}, images:[{url,…}],
  fields:{ [fieldKey]:string },            // ★ 扁平字符串表，无类型强制
  parentId:null, fieldTemplateId, mutedFields:[key],  // mutedFields = 该条目不适用的字段
  notes:"",
  lineageDx, lineageDy,                    // 谱系图节点手动偏移（±1e6）
  createdAt, updatedAt }
```

枚举：
- `status`（7）：`inspiration 灵感阶段(--info) / draft 初稿(--warn) / refining 待完善(--warn) / confirmed 已确认(--ok) / deprecated 已废弃(--fg-subtle) / conflict 存在冲突(--danger) / verify 待考据(--info)`
- `importance`（5，含权重）：`core 核心设定=5 / major 重要设定=4 / normal 普通设定=3 / background 背景设定=2 / optional 可选设定=1`
- `visibility`（4）：`public 公开 / semi 半公开 / hidden 隐藏 / private 作者私有`（隐藏/私有条目在导出网页时被排除）

### 2.4 relation

```js
{ id:"rel_*", projectId, sourceEntryId, targetEntryId,
  relationType, reverseRelationType:"", isBidirectional:false,
  description:"", status:"active", createdAt }
```

- **有向边 + 可选的独立反向标签**。视角标签三函数：
  ```js
  label(fromId)  = sourceEntryId===fromId ? relationType : (isBidirectional && reverseRelationType?.trim()) || relationType
  asymmetric(e)  = isBidirectional && reverseRelationType?.trim() && reverseRelationType !== relationType   // 双向但两向叫法不同
  label(otherId) = 对方视角的名字
  ```
- 24 个建议类型（自由文本，无枚举校验）：属于 / 统治 / 控制 / 敌对 / 同盟 / 发源于 / 信仰 / 参与 / 制造 / 持有 / 影响 / 位于 / 建立 / 摧毁 / 分裂自 / 合并自 / 效忠于 / 亲属 / 背叛 / 守护 / 封印 / 研究 / 交易 / 前置于。

### 2.5 tag

```js
{ id:"tg_*", projectId, name, color:"#8a9a6b", description:"" }
```
`ensureTag` 大小写不敏感去重；`updateTag` 改名会**重写该项目所有条目里的标签字符串**；`mergeTag(from,to)` 重写并 `new Set()` 去重后删除源行；`deleteTag` 从条目上摘掉。

### 2.6 event（时间线事件）

```js
{ id:"ev_*", projectId, name,
  era:"未分纪元",                 // 自由文本；"未分纪元" 是内置未归类桶，恒定排最后
  branchId:null,                  // null = 主线
  startYear:number|null, endYear:number|null,
  startMonth, startDay, endMonth, endDay,     // 经 IC() 校验（公历闰年感知），非法 → null
  timeType:"confirmed",
  locationEntryId:null, participantEntryIds:[], relatedEntryIds:[],
  description:"", displayDate,    // displayDate：纯展示文本（仅分段纪年用），不影响排序
  content:"",                     // 富文本
  inWorld:true,                   // false 时省略字段存储；false = 不进世界时间线，只在「条目时间线」
  treeDx, treeDy,                 // 时间树手动定位（±1e6）
  manualOrder, createdAt }
```
`timeType`：`confirmed 确定时间(--fg-muted) / uncertain 模糊时间(--warn) / legend 传说时代(--accent) / secret 秘密历史(--danger)`。

### 2.7 branch（时间线分支）

```js
{ id:"br_*", projectId, name, color:"#c99b5f", description:"", sort:number, createdAt,
  mountParentId, mountEventId, mountAtYear }   // 三者齐备 = 挂载支线；否则为独立分线
}
```
- 挂载支线：从父线的**某个事件**或**某个年份**分叉，可再分叉；`setBranchMount` 有环保护（沿父链走 ≤64 跳）。
- 分支排序色板 8 色：`#c99b5f #8a9a6b #6b8a9a #9a6b8a #b05c5c #5cb0a0 #7c6bc9 #c9a06b`。

### 2.8 lineageLink（谱系/演化边）

```js
{ id:"lg_*", projectId, sourceEntryId, targetEntryId,
  kind:"parent"|"adoptive"|"spouse"|"sibling"|"evolution",
  status:"active"|"uncertain"|"deprecated",
  sortOrder?:number,        // 手足间序齿
  note:"", createdAt }
```
方向规则：`parent|adoptive` → 记入 `parentsOf[target]` / `childrenOf[source]`；`spouse|sibling` → **两端都记**；`evolution` → 独立图。
种类标签：`parent 生身父母 / adoptive 收养 / spouse 配偶 / sibling 手足 / evolution 演化`。

### 2.9 snapshot（条目版本）

```js
{ id:"ver_*", entryId, trigger:"auto"|"manual"|"restore",
  note, createdAt,
  contentSnapshot, summarySnapshot,   // 旧格式兼容的扁平字段
  data:{ name, alias, summary, content, status, importance, visibility,
         tags:[…], fields:{…}, parentId, fieldTemplateId, categoryId, notes },  // ★ 14 字段载荷
  hash,      // FNV-1a 32 位（canonical JSON，字典序键）→ 8 位小写 hex
  bytes,     // canonical JSON 的 UTF-8 字节数
  media,     // 仅 includeMedia 时：{coverUrl,coverFocus,images}
  starred }
```
详见 `06-快照检查与字段.md`。

### 2.10 inspiration（灵感）

```js
{ id:"ins_*", projectId, title, content, type:"场景灵感", tags:[],
  maturity:"raw", linkedEntryIds:[], createdAt }
```
- 10 种类型：`场景灵感 / 角色灵感 / 势力灵感 / 情节灵感 / 视觉参考 / 音乐参考 / 关键词 / 台词 / 梦境 / 临时设定`。
- `maturity`：`raw 原始想法 / developing 整理中 / ready 可入设定集`。
- 双出口设计：**「保存为待整理条目」**（建 entry，`status:"inspiration"`，`categoryId` = 用途 `inspiration` 的分类，写 `fields:{inspiration_type, maturity:"原始想法"}`）vs **「保存为灵感」**（建 inspiration）。

## 3. 导出包（跨项目迁移格式）

```js
{ version:1, exportedAt, project, categories, entries, relations, tags,
  events, branches, snapshots, inspirations, lineageLinks }
```
- 导入接受裸包或包装 `{worldsetBackup, bundle}`；id 前缀规范：`prj_ cat_ ent_ rel_ tag_ evt_ br_ snap_ insp_ lin_`（注意运行期谱系 id 是 `lg_*`，导出重映射前缀却是 `lin_` —— 原站自身的不一致）。
- 导入会**重新分配全部 id** 并重写正文里的引用：
  ```js
  /(data-entry-card|data-entry-mention|data-source-id|data-target-id)="([^"]*)"/g
  ```
- 硬上限：JSON ≤32MB、entries ≤20000、categories ≤2000、relations ≤50000、events ≤20000、branches ≤500、tags ≤5000、snapshots ≤20000、lineageLinks ≤50000、maps ≤100、pins/map ≤5000、fields/entry ≤200、templates/category ≤20、fields/template ≤200、participants ≤500、string ≤10000、content ≤1e6、depth ≤32。

## 4. 移植备忘

- `fields` 扁平字符串表 + `select` 选项是**最省钱的结构化方案**：不需要迁移，任何节点加一组 `fields` 即可获得「档案字段」能力。
- 「分类用途（purpose）」而非「分类名」的判定思路值得借鉴：结构视图按用途找分类，用户可任意命名分类、一个分类可担任多用途。
- `project.fieldDisplay.hideEmpty` 与 `entry.mutedFields` 是**两个不同语义**：前者是全局显示策略（只读详情页隐藏空字段），后者是单条目「此字段不适用」（并会从完整度分母里剔除）。不要合并。
