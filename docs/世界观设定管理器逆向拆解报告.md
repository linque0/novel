## 1. 一句话结论

这是一个**单作品（一座世界观）的本地优先设定档案馆**：把「角色、势力、地点、千年历史」收进结构化的条目体系里，再用四张结构视图（关系图谱 / 时间线 / 谱系图 / 地点地图）把它们之间的关系显性化，并用一套**可维护性机制**（完整度评分、17 条一致性检查、条目级版本历史）对抗长周期创作中的设定腐化。

它的产品密度远高于「设定集 = 一堆富文本页」的常见形态。**最值得学的不是界面，而是三件事**：

1. **把设定当结构而非文档**：条目 = 属性（状态/重要度/可见性/标签）+ 档案字段（扁平的 key→字符串表）+ 正文（富文本）+ 关系边。
2. **把交叉引用做成一等公民**：正文里可以插入设定引用卡与内联提及，还能扫出「提到但没绑」的名字一键全部绑定。
3. **把结构视图当检查工具**：图谱/谱系/时间线不只是好看，它们同时喂给完整度与一致性检查，形成「写 → 看见 → 修」的闭环。

## 2. 产品形态与信息架构

单项目下 13 个路由，侧栏分四段：

| 段 | 页面 |
| --- | --- |
| 概览 | 仪表盘（七块派生组件：Hero 统计 / 快捷创建 / 健康度 / 写作统计 / 最近编辑 / 待补全 / 图谱与时间线预览） |
| 设定库 | 全部条目 · 分类浏览 · 标签管理 · 灵感清单 |
| 结构视图 | 关系图谱 · 时间线 · 谱系图 · 地点与地图 · 人物与角色 |
| 维护 | 设定检查 · 项目设置 · 多人协作 |

交互层面有三处做得克制而有效：`Ctrl+K` 命令面板（固定段「跳转/操作」+ 动态段「条目/标签/切换世界/最近编辑」）、`Ctrl+N` 快速捕捉灵感（随时记下，两个出口：存为灵感 或 存为待整理条目）、顶栏 `/` 直接聚焦全局搜索。

## 3. 数据模型（本报告最重要的部分）

11 张表，全部围绕一个核心实体 **entry（设定条目）**：

```
project ─┬─ category（分类，可无限嵌套；靠 defIds 声明「用途」）
         ├─ entry ─┬─ fields{}        扁平字符串表（key → string）
         │         ├─ tags[]          标签串
         │         ├─ content         HTML 字符串（TipTap 产出）
         │         └─ parentId        区域/上级
         ├─ relation（有向边 + 可选独立反向标签）
         ├─ event（时间线事件，era 自由文本 + branchId + 起止年月日 + 时间性质）
         ├─ branch（时间线分支；可挂载到父线的某事件或某年份）
         ├─ lineageLink（谱系边，5 种 kind + 状态 + 序齿）
         ├─ tag（可改名/合并，改名会重写所有条目上的标签串）
         ├─ inspiration（灵感，含成熟度与已关联条目）
         └─ snapshot（条目版本，14 字段载荷 + FNV-1a 哈希 + 字节数）
```

三个设计亮点：

- **「分类用途」而非分类名**：分类带 `defIds[]` 声明自己担任哪些用途（人物与角色 / 地理与地点 / 国家与势力 … 共 18 种）。结构视图**只看用途不看名字**，用户可以随便命名「我的英雄们」而不影响任何视图；一个分类可担任多个用途，一个用途也可由多个分类共担。
- **档案字段是扁平字符串表**：`{key, label, type: text|textarea|select, options?}` 描述，值统一存字符串。没有类型系统、没有迁移成本，却足够撑起「档案卡」的全部展示。
- **改名保护键**：`char_state / start_year / race / occupation / danger / place_type / region` 这几个键被检查引擎与结构视图读取，改名时只改显示名（label），键名保持不变 —— 于是检查规则永远不会因用户改名而失效。

## 4. 四张结构视图

### 4.1 关系图谱 —— 双渲染器，零图库

- **平面**：inline SVG，940×560 固定世界坐标，手写 Fruchterman–Reingold（`k=0.62√(面积/节点数)`、弹簧刚度 0.06、重力 0.0015、α 每帧 ×0.985、位移每帧限幅 `0.12k`）。**位置积分，无速度状态**。
- **星球**：Canvas 2D，Fibonacci 球面播种 + 球面松弛（一次性，≤120 次迭代），摄像机透视投影（`R=0.36·min(w,h)`，距离 2.4 可调 1.7–4），带惯性、闲置自转、聚焦 lerp、线框经纬环。
- 交互：ego 聚焦（一度/二度 + 非成员变暗）、分类多选与标签过滤、节点定位、关系名开关、**谱系边虚线投影**、拖动节点（不持久化）。
- 详情轨显示视角化关系行：`←/→ 方向 + 本节点视角标签 + 对端`，双向不同名时附「⇄ 对方视作「…」」。
- 缺失的能力：**不支持拖动建边、不支持编辑边、无导出**。

### 4.2 时间线 —— 四种视图，纪元可分段

- 竖向（默认，DOM + 绝对定位，左轴 101px）/ 横向对比（唯一可缩放的，年份轴 + 纪元年带 + 泳道贪心避让 + 标签三态避让）/ 双线对比 / **时间树**（SVG，主线为干、支线扇出）。
- **纪年方式二选一**：统一纪年（一条年份轴，纪元顺序由年份推导）vs 分段纪年（各纪元各自从 1 计年，纪元顺序由用户手排并持久化 `eraOrder`；「未分纪元」是内置桶，恒定排最后）。
- **分支与挂载支线**：分支可挂到父线的**某个事件**或**某个年份**（`mountParentId/mountEventId/mountAtYear`），可再分叉；有环保护（≤64 跳）。
- 事件含 `timeType` 四态（确定/模糊/传说/秘密），四态**贯穿色彩与线型**（非确定时间的事件在横向视图是虚线，带徽章）。
- 细节考究：横轴指针处显示年份且**点击即按该年份新建事件**、点事件有 `minSpan` 最小可视宽度、拖动到视口边缘自动滚动、`rY` 排序键以年为大权重（月/日不会越过年份差）。

### 4.3 谱系图 —— 确定性布局引擎（最值得整段移植）

没有物理迭代：BFS 定世代 → 生成婚姻（union）节点 → 逐世代从右向左做**条带打包**（配偶相邻成条，宽 = Σ人/标记宽度 + 间隙）→ 输出 `{nodes, unions, edges, broken, width, height}`。

- 三种模式：亲缘（全图或焦点连通分量）/ 上溯（焦点 + 全部祖先 + 祖先配偶）/ 演化（独立图，破环时跳过环边）。
- **虚线语义统一**：收养 / 关系失效（非 active）/ 第二位父母。
- 破环与冲突不静默：产出 `broken[]` 诊断（自环 / 世代冲突 / 手足与亲子代际矛盾），最多列 5 条。
- 节点拖动偏移写在**条目自身**（`lineageDx/Dy`），不另立布局表。
- 亲属录入走「悬停胶囊 + 右键菜单」而非拖拽连线；并提供「从已有 relations 一键迁入」的正则桥接（配偶/养父母/父母/子女（方向翻转）/手足/血亲 六类）。

### 4.4 地点与地图

`maps[{name, image, pins[{entryId, x, y}]}]`，**坐标是容器百分比 0–100（1 位小数）**；缩放 1–5 且**光标锚定**，图始终铺满；图钉拖动落库、点击放置；底图超 3MB 自动压缩（尺寸档 × 质量档双重下降，WebP 优先）；层级列表里的「控制势力」列**由 `控制`/`统治` 关系推导**，并可就地增删这些关系 —— 把关系边反向用成了列表列，是很有启发的一处设计。

## 5. 可维护性机制（产品最硬的内核）

### 5.1 条目级版本历史

三态触发 `auto / manual / restore`；`auto` 只在「显式保存 + canonical 哈希变化 + 距上次 ≥ 间隔」时产生（**1.5s 防抖的自动保存不产生快照**）；清理算法 = 每条目独立保留「最新 + 全部星标 + 最新 N 条非星标」，再按项目体积上限从最旧的非星标开始删；**恢复前自动记录当前状态**，所以恢复可撤销；提供逐字段 diff。免费档限 5 版/条目且不含封面图集。

### 5.2 完整度评分与一致性检查

完整度 100 分 = 摘要 10 + 正文 20 + 标签 10 + 关联 20 + 字段 40（按已填比例）。项目级再派生 **关联密度 / 孤立条目数 / 未完成数 / 冲突数** 四个指标，直接喂给仪表盘「健康度」与侧栏徽标。

检查引擎 17 条规则分三级（`error/warn/info`），涵盖：

- 人物：`状态为死亡/封印/失踪但仍在参与事件`（可加「复活/亡灵/回忆/数据体」标签豁免）、`同时效忠于互相敌对的两个势力`（可加「卧底」豁免）
- 地点：`被两个敌对势力同时控制`（可加「争夺中」豁免）
- 时间：`前置于关系与发生时间矛盾`、`起因于关系时间倒置`
- 谱系：循环、重复边、生身父母 >2、生身与收养并存、近亲配偶、手足与亲子/配偶冲突、可由共同父母推导的手足
- 一般：孤立条目、缺标签、完整度 <50、人工标记待考据/存在冲突

**规则即产品**：它把「设定腐化」这种软问题变成了可枚举、可定位、可豁免的清单。且没有「忽略」按钮 —— 要么修数据，要么打豁免标签，避免了检查页被静音。

### 5.3 交叉引用的闭环

正文可插入**引用卡**（块级，带分类/状态/摘要/更新时间）与**提及**（行内芯片，带状态色）。更有价值的是**引用检查**：扫描纯文本中「出现但未绑定」的条目名/别名，列出出现次数，一键**全部绑定**为内联引用。这是把「作者不自觉用了设定名却忘了连线」这类隐性问题自动收敛的机制。

（原站**没有反向链接索引**，这是它明显的能力缺口。）

## 6. 值得称道的工程选择

- **编辑器**：TipTap 2，但正文存 **HTML 字符串**而非 JSON doc —— 换来的是「老数据（Markdown/纯文本）零成本接入」（`marked` 兜底）与「导出/清洗都是字符串操作」。代价是 Markdown 导出有损（callout 类型不可逆）。
- **语义块**：`callout` 一个节点 + `type` 属性表达 6 种语义（提示/注意/警告/冲突/秘密设定/作者注释），另有折叠块、剧透块、行内剧透、脚注、时间标记、批注 mark，以及 5 种语义高亮预设（含「重要伏笔」）。
- **图片一律 base64 内联存储** + 分级压缩（封面 1600px/320KB，地图长边 4096px/3MB）。换来了「导出 JSON = 完整可迁移」，代价是体积。
- **本地优先的完整闭环**：IndexedDB 为唯一真源 → 浏览器存储保护（`navigator.storage.persist`）→ 本地备份文件夹（每 5 分钟 + 关页面前，保留最近 N 份）→ 增量写出「明文快照目录」供 AI/MCP 读取（附 `worldset-mcp.mjs`，工具 `search_entries/get_entry/list_relations/get_events`）→ 可选的端到端加密云备份。**AI 接入走本地目录而不是 API key，这个思路对隐私敏感的产品很有参考价值。**
- **导出产品化**：除 JSON/Markdown 外，还能把整座世界观打包成**单文件多页 Wiki**（首页/分类/条目/时间线/关系图谱/搜索），或带水印打印 PDF。

## 7. 原站的明显短板（移植时不要复刻）

| 问题 | 说明 |
| --- | --- |
| 无反向链接 | 只有显式关系与一次性的「引用检查」扫描 |
| 图谱不可编辑 | 不能拖动建边、不能编辑/删除边、无导出；`relation.status` 存在于模型却从不参与样式 |
| `status` 有 7 态但图谱只用分类色 | 重要度只影响节点半径与描边，状态在图上完全不可见 |
| 引用选择器「新建并引用」返回本地临时 id | 可能与落库记录不一致（真 bug） |
| 隐藏/剧透不是真隐藏 | 内容仍在 DOM 中（`opacity-0` + `h-0`） |
| 无分页/虚拟化 | 列表全量渲染、图谱无节点上限，大数据量靠 `slice()` 硬截断 |
| 时间线无「今天」标记、无导出 | 横轴的指针游标只用于新建事件 |
| 树/列表/看板之外无批量编辑 | 批量仅支持打标签/改状态/移动分类/删除 |
