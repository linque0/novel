# 正文 Agent 工作流第一阶段：实现与验证

实施日期：2026-10-24。依据 `docs/agent-knowledge-fix-20261023/正文续写与改写工作流细化方案-20261024.md`，复用当前 checkout，保留既有未提交改动。未升级版本、修改数据库版本或自动提交。

## 使用方式

在正文定位光标，点击「恍然梦 · 正文助手」；也可在正文右键选择续写或选段改写。

1. 选择光标处、章末、选段后续写，或改写选段，填写本次要求。
2. 续写默认先生成 5 个剧情方向，可选 4 或 6 个。完整卡片返回后即可直接改标题与剧情演变；编辑不会切换选中项。
3. 手改方向自动保留。支持单卡换版、复制、手写、恢复原稿和移除；迟到的生成结果不覆盖手稿，也不复活已删除卡片。
4. 选一个方向续写。正文请求只带该方向的编辑稿快照，不混入未选方向或其他候选历史。仍保留明确的「直接续写」入口。
5. 在候选里编辑正文、查看接入预览，再采纳到冻结位置。重复段落按编辑器坐标定位，来源或方向版本变化时停止直接采纳。
6. 「接着写草稿」以父候选的编辑稿、原位置和原方向生成派生候选；「采纳后再续写」从当前已保存正文准备新任务。正文采纳与章节记忆提取分开，记忆提案仍需确认。

任务要求、方向、选择、候选编辑稿和应用状态按作品保存到现有 airuns。关闭浮层不会清空任务或取消生成；正常重启恢复保存状态，不自动调用模型。多窗口同时编辑同一任务发生冲突时，本地稿另存为独立分支，保留双方数据。

## 关键实现

- `writing-anchor.js` 区分编辑器坐标和正文纯文本偏移，冻结来源版本、原选段、前文与后文衔接范围；全选正文可改写。
- `writing-directions.js` 解析完整流式对象，稳定映射槽位，保护编辑稿，忽略过期批次与删除槽位。
- `stores/writing.js` 和 `db/writing-repo.js` 管理会话、版本比较、冲突另存、关闭前刷新及恢复。恢复优先最近创建的任务，旧任务迟到保存不能抢占。
- `WritingWorkspace.vue` 提供方向先行的正文工作区；`DraftCard.vue` 提供编辑、预览、采纳、撤销及独立记忆入口。
- 正文位置边界贯穿上下文、书库检索、原文读取、状态回放和证据定位；当前章位置之后不参与事实回放，右侧片段仅作为显式衔接材料。
- `application.js` 在等待保存后重新验证目标。未提交 AI 事务的失败不回滚编辑器，避免切章或继续输入时抹掉作者正文。
- `EditorPane.vue` 共用一个 EditorContent，通过 Teleport 在皮肤和阅读布局间移动，避免切入赤月戏后正文节点脱离页面；编辑器实例和内容保持。

## 验证环境与结果

所有模型机制验证使用独立 `booksource-verify` profile 与登记的《AI 验证书》。使用本地确定性 SSE 服务，通过真实 provider/tool 接线验证；不请求真实模型，模型配置仅替换窗口内存并在结束后恢复，不改作者作品。
