# 恍然梦 Agent 能力评估报告

> 评估日期：2026-10-12
> 评估对象：当前工作区「恍然梦」实现（v2 基线 + 增强交付，未提交版本）
> 评估方式：三路只读代码审计（运行时/记忆检索/行动安全，逐文件核验）+ 核心循环逐行人工复核
> 关联文档：docs/AI助手优化方案-恍然梦v3-酒馆式注入引擎.md（v3.2 第十三章承接本报告缺口）、docs/恍然梦Agent增强实施说明.md（现状交付清单）

## 一、评估基准：agent 应有部件框架

按主流 agent 架构（感知—记忆—规划—行动—反思闭环 + 运行时与治理层）拆为 14 个部件：

| 部件 | 定义 |
|---|---|
| 1 模型接口层 | LLM 调用：流式、超时、错误分类、重试、用量计量 |
| 2 感知与上下文装配 | 把作品数据按任务装配为发送上下文：分层、预算、裁剪、隐私、发送范围透明 |
| 3 记忆·工作记忆 | 多轮交互的会话状态（对话历史/会话槽），跨轮可用 |
| 4 记忆·长期 | 持久化的作品知识（摘要/卡片/决策/审计），带失效机制 |
| 5 记忆·检索 | 从长期记忆中按相关性召回（关键词/向量/结构化），含融合与降级 |
| 6 规划（Planner） | 目标分解为多步计划、按结果重规划（plan-execute-replan） |
| 7 工具系统 | 工具注册、参数校验、循环调用、结果回喂、终止条件 |
| 8 行动与执行 | 产出落到作品数据：提案制、校验、快照、回滚、撤销、审计 |
| 9 反思与校验 | 自检/复核/证据验证，且结果能驱动修正（闭环） |
| 10 运行编排 | 任务生命周期：队列、并发控制、租约、中断、检查点、恢复 |
| 11 可观测性 | 用量成本、运行报告、审计浏览、异常可追踪 |
| 12 安全护栏 | 隐私模式、密钥安全、只读默认、写入防护、成本护栏 |
| 13 驾驶层（Steering） | 人设/世界书/角色卡/预设等可编辑的「如何生成」资产（ST 三件套等价物） |
| 14 学习与自适应 | 从作者行为/偏好中学习并回灌（文风、决定、纠错） |

判定标准两档：
- **自主 agent**：给定目标后可自主规划多步、执行、按结果反思重规划，直到达成或请求确认；
- **任务型 copilot agent**：以明确任务为单位被调用，具备记忆/工具/校验/安全护栏，产出经人确认落库。

## 三、合格性判定

**作为自主 agent：不合格。** 三个结构性部件缺失：
1. 无规划器——不存在「给定目标 → 自主分解 → 按结果重规划」的能力，多阶段流程是硬编码模板；
2. 反思不闭环——verify/复核存在但不驱动修正，直接审稿路径甚至不跑复核；
3. 无统一主循环——两条互不相关的执行路径，谈不上统一的感知-行动-反思循环。

**作为任务型写作 copilot agent：合格且成色高。** 记忆（长期 + 失效 + 回放）、工具、执行安全（14 层防护）、运行编排（租约/检查点/恢复）、审计回滚、隐私护栏这些硬部件真实存在且经过打磨；「agent 永不直接改库、一切经提案确认」的红线贯穿全链路。体检中「agent 味」最弱的即规划/反思/驾驶三块——其中驾驶层正由 v3 方案承接，规划与反思路线由 v3.2 承接（见 v3 文档第十三章）。
