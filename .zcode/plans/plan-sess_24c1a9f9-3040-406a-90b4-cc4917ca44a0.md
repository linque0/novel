# 人物关系图「顶部」剩余未对齐的三处

## 一、先说清楚你两张图

- **你图 2（应有效果）**：标题行「人物关系图 + 人物与人物的关系 · 双击节点打开档案」，下面一行是 `全部 主角 配角 反派` + 一个干净的「全部标签」下拉，右侧是 −/＋/适应。
- **你图 1（实际版）**：没有标题行，且标签筛选是那个挤成一团、带上下箭头的方框。

诊断：那个方框是**原生 `<select multiple>`**（`CharacterGraph.vue:474`）——`multiple` 会被渲染成一个 22px 高的列表框，所以永远长这样。标题行我上一轮已经加了，刷新后的对照截图（`screenshots/_glaze-work-character-graph.png`，18:21）里是在的；你图 1 里没有，而**同一改动里的底部提示条在你图里显示正常**（CSS 生效但那次模板热更新没换），所以最可能是那个实例的 bundle 陈旧。这一条我会在你实例上核对并在报告里给结论（若确认缺，重启 `npm run dev` 即可看到）。

## 二、要改的三处（都限 `data-skin='glaze'`）

| # | 项目 | 现状 | 改成（设计稿逐字规格） |
|---|---|---|---|
| 1 | **标签筛选** | 原生 `<select multiple class="rg-tagselect">` → 22px 列表框 | glaze 下换 naive-ui `NSelect`（`multiple` + `clearable` + `size=small` + 占位「全部标签」+ `max-tag-count=1`）：宽 110px、圆角 8px、13px、底 `#f6faf9`、描边 `#afc8cc`（`.af-canvas-tools select` 的有效值）。仍绑 `tagFilter` **数组**（`focusCharById` 会 `tagFilter.value = []`，语义必须保持）。其他皮肤继续用原生 select |
| 2 | **页头右侧动作** | 只有标题+副题 | 补「发送为大纲引用卡」（`.af-head-actions` 里那颗），复用已有动作——选中人物时调 `work.sendCharToOutline(selCharacterId)`，未选中则禁用并给 title 说明 |
| 3 | **布局切换** | 两颗纯图标按钮 | 改成带文字的「圆形」「网格」（`.af-tool` 形态：13px、圆角 6px、`#afc8cc` 描边；位置仍在 −/＋/适应 之前） |

**硬约束（依赖排查结论，必须遵守）**：
- 这五颗按钮的 `title`/类名/文本原样保留：`圆形排布`、`网格排布`、`缩小`、`放大`、`适应视图`。`glaze-workbench-verify.mjs:141,158`、`chargraph-verify.mjs:33`、`relfollow-verify.mjs:312` 等按 `title` 或 `.om-btn.text` 的文本「适应」定位——文字化后我会保留 `om-btn` 类 + `title`，只加一个 `om-btn-label` 修饰类补宽度。
- `.rg-toolbar` 容器类名保留；全仓脚本对 `.rg-tagselect`/`tagFilter` **零依赖**（已确认），所以换控件不会踩脚本。
- 不动的部分：芯片保留「龙套」「孤岛」与计数（真实角色预设/功能；设计稿只有 4 颗芯片，这条已在 `琉光画境-接入记录.md` 登记为有意差异）、节点几何（`graph-presentation.js` 的 150×210 投影）、曲线走线。
