# 书架「点击左右书翻动」实现方案（引力书舱 skin）

## 一、已确认口径（来自你的选择）

| # | 决策 |
|---|---|
| 1 | 舞台中央区：点左右两侧的书 → **方案1「翻转亮相」**（旋转到正面 + 移到中央；原中央书反向转身、缩小变暗退到对面书位） |
| 2 | 下方「其余的宇宙」：点列表书 → **送到中央**，用**方案2「抽书让位」**，**舞台内演绎**（不做跨区域飞行） |
| 3 | 可达范围：**相邻滑动窗口**，可以一路点着走遍整个书架 |
| 4 | 附加：**← / → 方向键**翻动（不做滚轮） |
| 5 | 中央书点击仍是「打开作品」；列表的一键打开走它已有的 `⋯ → 打开` |

## 二、现状与四个必须先拆掉的障碍

| 障碍 | 位置 | 后果 |
|---|---|---|
| 舞台挂 `:key="featured.id"` | `src/components/GravityShelf.vue:56` | 中央书一变，整块 stage 重建 → **任何过渡都活不下来**（这也是现在切换显得生硬的原因） |

| 两侧书 `pointer-events: none` + `aria-hidden` | `gravity.css:74`；`GravityShelf.vue:68` | 根本点不到；且只是 `works[1]/works[2]` 的静态摆放，**没有位置语义** |
| 只有两套绝对定位、无过渡，`overflow: clip` | `gravity.css:47,74-76` | 需要改成「姿态」体系才能插值 |

## 三、结构改造：每层只负责一个变换来源

每个渲染出来的书 = 一个 slot，内部 4 层，避免任何两个动画抢同一个 `transform`：

```
.gravity-slot   满舞台盒（inset:0 + grid 居中）→ 只做 translateX
  .gravity-pose 书尺寸盒 → rotate / rotateY / scale / opacity / filter
    .gravity-lift → 只承载「抽书」的一次性关键帧手势
      .gravity-book（仅中央那本多一个 .gravity-main-book）→ 只承载呼吸浮动
```

四个关键点：

1. **`.gravity-slot` 负责「与舞台宽度成比例」的位移**：它是满舞台尺寸，所以 `translateX` 里的 `%` 正好等于舞台宽度 —— `calc(var(--g-sat-gap) - 50%)` 能**精确复刻今天「侧书贴边留 78px」的摆位**，且不需要用 JS 量宽、resize 也不失真。
2. **`perspective` 留在舞台上**（与今天同级），旋转放在书尺寸的 `.gravity-pose` 上 → 绕书自己中心旋转，投影与今天的侧书一致。**不做 `preserve-3d` 真翻页**（仓库无先例，且会把 z/重叠搞复杂）。
3. **`.gravity-slot { pointer-events: none }` + `.gravity-book { pointer-events: auto }`**：满尺寸 slot 共 5 个互相重叠，不这样处理会挡住中央书的点击 —— 那会直接让 `skin-verify.mjs:82`「单击中央书打开」失败。
4. **倾斜从 `gravity-float` 关键帧搬到姿态层**，关键帧只留 `translateY` → `.gravity-main-book` 仍然持有该动画，`skin-verify.mjs:167` 的「reduced motion 关掉浮动」断言**仍然有意义**（不会退化成恒真）。远端缓冲位（±2）加 `inert`，排除出 Tab 顺序与指针命中。

## 四、姿态表（静止外观与今天一致）

| 位 | translateX | rotate | rotateY | scale | opacity | saturate | z |
|---|---|---|---|---|---|---|---|
| 中央 | `0` | −6° | −16° | 1 | 1 | 1 | 2 |
| 左 | `calc(var(--g-sat-gap) - 50%)` | −13° | 15° | .68 | .38 | .55 | 1 |
| 右 | `calc(50% - var(--g-sat-gap))` | 13° | −15° | .68 | .38 | .55 | 1 |
| 远（±2 缓冲） | 再外扩 56px | ∓13° | ±15° | .62 | 0 | .55 | 0 |

- **四个位的变换函数列表完全同构**（translateX → rotate → rotateY → scale）。缺项会让浏览器退化成矩阵插值，旋转会走形 —— 这是「丝滑」的前提。
- 统一用「书盒 228×330 + `scale(.68)`」复刻今天的侧书 155×230：连字号缩放都对得上（30→20.4 vs 今天 21、10→6.8 vs 7、11→7.5 vs 8），因此可以删掉 `.gravity-satellite` 的三条字号覆盖和 `top`/`left`/`right` 定位。
- 新增令牌（定义在 `.gravity-shelf`）：`--g-flip-dur: 520ms`、`--g-flip-ease: cubic-bezier(.22,.68,.28,1)`（强 ease-out、不弹跳）、`--g-sat-gap: 78px`（`≤750h` → 68px，组合查询 → 56px，对齐今天三档）、`--g-sat-scale: .68`。
- **翻转为什么像「翻」**：左位 `rotateY(15°)` → 中央 `rotateY(−16°)` 会**经过 0°**，途中那本书有一瞬正对读者 —— 这就是「转正亮相」的观感来源，且角度完全沿用今天，不外扩（`overflow: clip` 不会切到）。

## 五、两种手势

- **方案1（舞台点击 / ←→ 方向键）**：纯 CSS 过渡。每本书的元素按 `:key="book.id"` 持久存在，只换姿态 → 从旧姿态插值到新姿态；到达者 `z` 立刻到 2，**中途始终压在退场者之上**（退场者从它身下退向侧位，读起来就是「被让位」）。
- **方案2（列表点击 = 抽书让位）**：入场的书在 `.gravity-lift` 上播一次 `gravity-rise` 关键帧（`translateY(56px)→0`、`opacity 0→1`，结束态即恒等 + `fill:none` → 无缝交棒给姿态层）；原中央书照常姿态过渡并轻微下沉；列表项做一次轻抬淡出，刚下台的那本在新列表里淡入。
- **文案区**（`.gravity-feature-copy` / `.gravity-detail`）按 `activeId` 重挂并播 260ms 淡入 —— 复用现有 `gravity-arrive` 的「关键帧驱动、不依赖 rAF」套路，避开 `DLinkPopover.vue:130` 注释里记载的 rAF 冻结坑（它是淡入而非真交叉淡出，够用且稳）。

## 六、状态与数据流

- `activeId`（存 id 不存下标，数据变动不丢）+ `activeIndex`（找不到回 0）+ `activeBook = works[activeIndex]`。
- 监听 `props.works` 的 id 序列：**一变就回到 `works[0]`** → 任何数据刷新后中央仍是「最近更新」，与今天的语义一致，也保证 `skin-verify` 的搜索 / 新建 / 编辑三处断言不变。
- `slots`：以 active 为中心取最近两本，小下标在左、大下标在右。
- `others = works.filter(w => w.id !== activeId)` → 数量仍是 **N−1**，`skin-verify.mjs:60/75` 不变。
- dock 的「正文/大纲/设定…」、右侧详情、左侧文案统一切到 `activeBook`。

## 七、端点行为（这是我要请你确认的一点）

在「按最近更新排序」下，第一本左边没有「更早」的书。**今天的设计其实是把 `works[1]` 摆在左边、`works[2]` 摆在右边 —— 本来就没有前后语义。**

**我建议沿用这个摆法**：默认视图与你已通过的稿子一模一样，且左右两侧**永远都有书可点**（否则默认视图会缺一本书，「点左边那本」这个核心手势在第一本时直接不可用）。代价：第一本时左边的书其实是「下一本」；从第 2 本起，左右严格是「前一本 / 后一本」。

备选（你要的话我改）：① 不环绕、端点空一侧；② 首尾环形（侧位会出现列表最旧的一本，与「按最近更新排序」的读法冲突）。

## 九、验收

新增 `tools/shelf-flip-verify.mjs`，按仓库既有纪律（`_cdp-lib.mjs` + CDP 真实鼠标事件 + 独立 profile + 走注册表种子，不内联 `db.works.add`）：在 `--profile=gravity-skin-verify --remote-debugging-port=9223` 实例上，用 `buildSeedExpr(..., { reset: true })` 按已知顺序重置三本既有验证书，得到确定的最近三本。

检查项（逐条对应本方案）：

1. 基线姿态：中央书最大且居中、左书在左、右书在右（记录 rect 与 computed transform 作为基准）。
2. **方案1**：真实鼠标点击左侧书 → 该书名出现在 `.gravity-feature-copy h2`、`.gravity-main-book` 落在它身上、它的 rect ≈ 原中央书 rect，原中央书变成侧书。
3. **丝滑证据**：过渡期间每 ~60ms 采样一次移动中书的 x，断言**严格单调且落在起止之间**（证明是插值而不是瞬移）；同时断言过渡接线（`transitionProperty` 含 `transform`、时长为 520ms）。窗口不可见时按 `dlpop-verify.mjs` 的先例**跳过并计数**，不假失败。
4. **方案2**：真实鼠标点击列表项 → 它成为中央书、原中央书出现在列表、列表数量仍为 N−1、**没有打开作品**（`ui.view === 'shelf'`，这是相对今天的行为变更点）、入场书跑过 `gravity-rise`。
5. 方向键：舞台上 `ArrowRight/ArrowLeft` 使中央前进/后退一本；焦点在搜索框内时方向键**不改中央书**（不抢输入）。
6. 回归：点中央书仍打开作品；`⋯` 菜单仍不触发打开；Tab 顺序里不含远端缓冲书（`inert` 生效）。
7. reduced motion：同一套点击后中央书直接到位，`transitionDuration ≈ 0`、无中间帧。
8. 截图 `tools/_shot-shelf-flip-*.png`，结束时恢复 skin/theme 与临时种子。

**必须保持全绿**（我已逐条核对，本方案不影响）：`skin-verify.mjs` 的 60（列表数 = N−1）、64（1080px 无横向溢出，`overflow: clip` 不变）、75/76（搜索后列表归零 + 标题随搜索）、82/92（单击/回车开中央书、只开一次）、102（菜单不开书）、167（reduced motion 关浮动）；以及原版皮肤的 `shelf-verify.mjs`（`.book-card`，本方案不碰 `themes.css`）。

另外按 `docs/前端美化/前端美化方案-v3…md:170` 的要求，做一次**真实性能实测**（翻动过程中录一段 trace，看帧时间/长任务），不以「只动 transform/opacity」替代实测。

## 十、不做的事

不加任何动画依赖（gsap/motion 等）；不做滚轮翻动；不做首尾循环（除非你要）；不做跨区域飞行的 ghost；不做 `preserve-3d` 真翻页；不改原版皮肤与 `themes.css`。

## 十一、风险与回退

- 4 层结构略深。若嫌 DOM 深，可把 `lift` 与 `pose` 合并，代价是「抽书」手势要改成 `nextTick` + 强制回流的两阶段写法（可做但不如关键帧干净）。
- 浮动与倾斜分离后，呼吸的 5px 落在倾斜坐标系里，视觉差 <1px。
- 姿态角度全部沿用今天的数值，`overflow: clip` 不会切到书。
- 回退：只动 gravity skin 的三个文件 + 一个新增脚本，可单点 revert。
