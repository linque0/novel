# 模型设置改造：ZCode 式多供应商预设管理

已确认决策：**双 API 格式（OpenAI 兼容 + Anthropic Messages）、生成参数随预设走、即时保存（无保存按钮）**。

## 一、数据模型（新 appconfig 结构 + 迁移）

新增键（沿用 `ai.` 前缀，自动被 `loadSettings` 扫描与跨窗口广播覆盖）：
- `ai.providers`：预设数组；`ai.activeProviderId`：当前预设；`ai.cred.<providerId>`：每预设一把 DPAPI 密文密钥

```js
Provider = {
  id: 'p_xxx', name: 'DeepSeek',
  apiFormat: 'openai' | 'anthropic',
  baseURL: 'https://api.deepseek.com/v1',
  enabled: true,                                  // 总开关（启动/停止该供应商）
  models: [{ name: 'deepseek-chat', enabled: true }],
  activeModel: 'deepseek-chat',                   // 该预设内"使用中"模型
  modelCfg: { 'deepseek-chat': { enabled, contextWindow, maxTokens, temperature, note } },
  params: { temperature: 0.7, maxContext: 10000, privacy: false,
            kb: { auto: false }, embeddings: { enabled: false, model: '' } }   // 每预设一份
}
```

**迁移**（`loadSettings` 内，幂等）：`ai.providers` 为空且旧 `ai.baseURL`/`ai.model`/`ai.models` 有值时，合成一个预设——名称按 baseURL 匹配内置模板（DeepSeek/智谱/OpenAI/Ollama）否则"默认供应商"，apiFormat='openai'，模型列表与平铺 `ai.modelcfg` 搬入，params 取旧 temperature/maxContext/privacy/options，旧 `ai.credential` 密文复制到 `ai.cred.<新id>`，写新键后删除旧键。导入旧备份后重载会再次触发同一迁移。

**启停语义**：停用供应商——列表状态点变灰；若为当前预设则自动切到第一个启用预设（没有则保留但 ready=false 并红字提示）。停用模型——从可选中移除；若为使用中则自动切到同预设第一个启用模型。`ready` 扩展为 "active 预设存在且启用 && activeModel && 有密钥"。

## 二、请求层：双格式（src/services/ai/provider.js）

- `chatStream(opts)` 增加 `opts.apiFormat`（默认 'openai'）
- `buildUrl(baseURL, apiFormat)`：anthropic 容错拼 `/v1/messages`（已含则原样；以 `/v1` 结尾则 +`/messages`）
- 新增 Anthropic 适配分支：
  - 请求头 `x-api-key` + `anthropic-version: 2023-06-01`
  - body 转换：system 消息合并到顶层 `system`；`{role:'tool', tool_call_id}` → `tool_result` 内容块；assistant `tool_calls` → `tool_use` 块；`max_tokens` 必填（缺省 4096）；tools 转 `input_schema`；toolChoice `auto/none/指定` 映射
  - SSE 解析 `message_start`/`content_block_start(tool_use)`/`content_block_delta(text_delta|input_json_delta)`/`message_delta(stop_reason)`/`message_stop`/`error`，**归一输出与 OpenAI 分支完全一致**（`{text, toolCalls, usage, finishReason}`，end_turn→stop、max_tokens→length、tool_use→tool_calls）——dialogue.js 工具循环零改动；非流式 JSON 响应兜底
  - 错误分类复用 `throwFailure`（Anthropic 错误体 `error.message` 已兼容）
- `listModels`/`embed`：anthropic 格式下抛出明确错误（UI 同步禁用"拉取模型"与"语义检索/向量模型"）

## 三、Store 改造（src/stores/ai.js）

- state 新增 `providers[] / activeProviderId / credentials{}`；删除旧单值字段（baseURL/model/models/modelCfg/temperature/maxContext/privacy/options/credential/hasCredential）
- 同名 **getters 投影** active 预设（`baseURL`/`model`/`models`/`modelCfg`/`temperature`/`privacy`/`options`/`hasCredential` 等）→ 全站消费方（AiAssistantPanel、EditorToolbar、PresetEvaluation 等十余处 `ai.model`/`ai.ready`）零改动
- 新增 actions：`addProvider(template)`、`duplicateProvider`、`removeProvider`（级联删密钥键+必要时切换）、`updateProvider`、`setProviderEnabled`、`setActiveProvider`、`saveProviderKey/clearProviderKey`、`setModelEnabled`、`updateParams`（温度/隐私等，privacy 变 true 时保留现有 cancel 逻辑）
- 现有模型 actions（addModel/removeModel/selectModel/saveModelCfg/autoFillModelCfg/fetchModelList）改为作用于 active 预设，名称不变
- **保留 `saveSettings(patch)` 兼容层**（映射到 active 预设；无预设先自动创建"默认"）→ tools 下 7 个验收脚本的播种调用无需改动
- `buildOpts()` 返回增加 `apiFormat`；`generationOpts` 从 active 预设取 modelCfg

## 五、备份与密钥排除（src/db/repo.js）
